# 08. Отчёт этапа 6: прослеживаемость наполнения data/

Отчёт закрывает предметную часть этапа 6 (`05-work-plan.md`: задачи 6.1–6.3):
каталог `data/` — выверенная выборка записей наполнения, значения которой
прослеживаются до ТУ, даташитов и листов спецификации (критерий этапа:
«значения наполнения прослеживаются до ТУ/даташитов/листов спецификаций»).
Грамматики и таблицы систем обозначений выверены ранее — `07-r1-verification.md`;
здесь фиксируются контрольные сверки значений (диапазоны параметров, матрицы
исполнений, аналоги) по первичным и вторичным источникам — внешние выборки
перенесены конвертацией в формат наполнения (задача 6.3).

`sample-data/` сохраняет назначение примеров формы («правдоподобные
непроверенные значения» — план работ 4.5) и этапом 6 не заменяется: `data/` —
самостоятельный набор с атрибуцией источников. Пин-тест
(`internal/importer/verified_test.go`) требует у каждой записи `data/`
атрибут `tu` либо `datasheetUrl`, импортирует весь каталог идемпотентно
на SQLite и PostgreSQL и проверяет разбор обозначений всех классов.

## 0. Правила моделирования (следствия плана, зафиксированные при наполнении)

- **Матрица исполнений К50-35** — «ёмкость × напряжение → габариты/масса»
  (D6, задача 6.2): исполнение — одно на номинальное напряжение (уникальность
  `Unom`, правило `cap_variant_matrix`), `Cnom` — диапазон ряда на это
  напряжение, массогабаритные данные — наибольший корпус напряжения с полным
  набором D×H + шаг выводов по источнику [S23]; полная таблица корпусов
  (у производителей несколько корпусов на одно напряжение в зависимости от
  ёмкости) шире модели v0.1 — приведена в §4.
- **Радиальная цилиндрическая форма корпуса** (поправка плана этапа 6):
  правило `cap_dimensions_form` расширено с пары `diameter`+`leadLength`
  (осевые выводы) на пару `diameter`+`height` — высота/длина корпуса
  (радиальные конденсаторы К50-35: по ОЖ0.464.214 ТУ нормируются D×H и шаг
  выводов, длина радиальных выводов изготовителем не нормируется; осевые
  резисторы С2-33Н — D×длина корпуса). Правки: `docs/plan/03-data-model.md`
  §6.7/§7/§10, `internal/catalog/rules.go`, тесты.
- **Взаимные ссылки-аналоги в одном файле** (A → B и B → A, план 03 §8:
  round-trip «независимо от порядка записей»): многопроходное разрешение
  импорта дополнилось разрывом цикла холостым созданием записи без секции
  аналогов с компенсирующим удалением при неудаче — контракт «запись не
  применяется вовсе» сохранён (`internal/importer/importer.go`, тест
  `MutualAnalogReferences`). Случай реальных данных: Д226 ↔ 1N4007.
- **Величины, не выражаемые типами каталога v0.1**, в записи не попадают и
  перечислены ниже по типам (параметр `h21e` — диапазон, а нормировано «не
  менее»; `FGran` — обязательны условия, а источник условий не приводит;
  формульные нормы — ток утечки К50-35, DCL-правило KEMET). Пополнение
  каталога типами/условиями — данными без правки кода (D1).
- Единицы — канонические (03 §3): ёмкость — пФ, сопротивление — Ом, частота —
  МГц, мощность транзисторов/диодов — мВт, резисторов — Вт, ТКС — 10⁻⁶/°C;
  даташитные производные переведены до записи; для pnp/p-канала условия
  записаны модулями напряжений/токов.
