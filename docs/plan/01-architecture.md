# 01. Архитектура проекта components-catalog

## 1. Общая форма

Go-модуль (библиотека + встраиваемый REST API + CLI), без внешних сервисов и демонов. Потребители:

- **веб-бэкэнд сайта** — импортирует Go-пакет и/или монтирует `http.Handler` с REST API `/api/v1/...` в свой роутер; аутентификация, авторизация, rate limiting, CORS — на стороне сайта;
- **администратор/наполнитель** — CLI `catalogctl` (init, import, add, list, info, find, delete, count, parse, export, catalog export);
- **наполнение** — файлы jsonc/yaml и NDJSON (для больших объёмов) через сервисный слой; тот же путь использует и CLI, и REST-импорт.

```
components-catalog/
├── cmd/catalogctl/            точка входа CLI (только main)
├── internal/
│   ├── domain/                обозначения (парсеры систем: ГОСТ/ОСТ, PRO ELECTRON, JEDEC, JIS; серии), единицы, классы приборов, ошибки
│   ├── catalog/               доступ к каталожным таблицам; движок валидации по правилам из БД
│   ├── storage/               переносимое реляционное ядро (database/sql) + диалекты sqlite/postgres
│   ├── service/               бизнес-операции: upsert, поиск, карточка, импорт/экспорт, производители
│   ├── importer/              реестр форматов наполнения (jsonc/json, yaml/yml, ndjson), семантика секций
│   ├── i18n/                  бандлы отображаемых строк (en — канонический, ru), переговоры локали (D9)
│   ├── httpapi/               REST /api/v1 (net/http), OpenAPI-совместимые хендлеры
│   └── cli/                   разбор аргументов, команды, вывод
├── api/openapi.yaml           спецификация REST API (артефакт этапа 5)
├── seed/                      базовые сиды каталога (единицы, условия, стартовые каталоги 4 классов)
├── data/                      выверенное наполнение (выборка этапа 6; источники — 08-data-verification.md)
├── AGENTS.md                  правила разработки
└── README.md
```

Правило слоёв:

- `domain` не зависит от БД и форматов; ошибки — значения (`*domain.Error` с кодом), не паника;
- `storage` не знает бизнес-правил: только переносимый DML + диалекты;
- `catalog`, `service`, `importer` — надстройки; `httpapi` и `cli` — тонкие транспорты над `service`, без бизнес-логики;
- `i18n` зависит только от кодов-строк; его единственные потребители — транспорты (`httpapi`, `cli`) и тесты полноты бандлов; внутренние слои (`domain`/`catalog`/`storage`/`service`) локали не знают (D9).

## 2. Слои и ответственности

### 2.1. `internal/domain` — обозначения и базовые понятия

- Классы приборов: `Kind` (`transistor`, `diode`, `resistor`, `capacitor`) — реестр в коде синхронизирован с сидами `kinds`; системы обозначений — реестр кодов синхронизирован с сидами `designation_systems` (пин-тесты).
- **Парсеры обозначений — код для строго формальных систем** (грамматики стабильны; гибкость требуется к параметрам и реестрам, не к грамматикам):
  - полупроводники: ГОСТ 10862-64 и преемники вплоть до ГОСТ Р 71055-2023 (материал, подкласс `Т`,`П` | `Д`,`С`,`В`,`А`,`И`,`Г`,`Л`,`Ц`, сборка, признак, номер, буквы, модификация, бескорпусное); PRO ELECTRON (материал `A…R`, класс `A…Z`, номер, суффикс); JEDEC (число переходов, `N`, номер регистрации, суффикс); JIS (переходы, `S`, класс, номер, суффикс);
  - резисторы — ГОСТ 3453-68 (`С2-33Н`, `СП3-19А`) + ОСТ 11.074.009-78 (`Р1-4`, `РП1-46`; формы не пересекаются);
  - конденсаторы — К-система (`К10-17Б`, `К50-35`);
  - `series` — единая слабая грамматика хвоста над реестром семейств (данные `series_families`: семейства вне строгых ГОСТ и мировые дом-номера производителей);
  - `other` — без разбора, только канонизация.
- Результат разбора: система + каноническое обозначение-строка (точный ключ) + набор полей «код → текст/число» (уходит в `device_designation_fields`), класс прибора.
- Материалы: пары равнозначных символов `Г/1, К/2, А/3, И/4` — только `gost` (равнозначность физическая: `КТ312` и `2Т312` — раздельные записи, но `find` при отсутствии точного совпадения подсказывает равнозначную по материалу); `pro` кодирует материал первой буквой (`A`/`B`/`C`) — в поле `material` с единым словарём значений для сквозного фильтра между `gost` и `pro`.
- Единицы: канонический справочник — данные (`units`, коды — латиница: `V`, `mA`, `MHz`, `ohm`, `pF`…), в домене — только форматирование чисел: целое — без точки, дробное — кратчайшей записью, инженерные суффиксы для больших/малых величин (пФ, нФ, мкФ, кОм, МОм — производные единицы отображения, форматирует слой вывода; символы единиц по локалям — `internal/i18n`, D9).
- Ошибки: `domain.Error{Code, MsgID, Args}`; коды машиночитаемые (`invalid_designation`, `unknown_parameter`, `parameter_not_applicable`, `attribute_not_applicable`, `validation_failed`, `kind_not_supported`, `not_found`, `already_exists`, `designation_mismatch`, `schema_version_mismatch`, `database_not_initialized`, `invalid_import_file`, ...). Сообщения — каталог (этап 8.3, D9): стабильные MsgID (реестр констант `internal/domain/messages.go`), форматы en (канонический) и ru — бандлы `internal/i18n` с позиционными аргументами `%[n]s`; `Message`/`Problem.Message` — канонический en-рендер, локализованный рендер (REST — `Accept-Language`, CLI — `--lang`) и подстановка аргументов-сообщений — транспорты. Полнота каталога (en+ru для всех MsgID) закреплена тестом; изменение формата — несовместимое изменение контракта.

### 2.2. `internal/catalog` — каталог как данные + движок валидации

- Чтение определений: параметры (код, класс, группа, единица, тип значения, границы, потолок, enum-значения, наборы условий), атрибуты (код, класс, тип, enum, группа, правило), условия, единицы, группы, именованные правила.
- **Движок валидации**: применимость параметра/атрибута к классу записи (`parameter_kinds`/`attribute_kinds`, пустой набор = все классы — D7; неприменимый код — ошибка `parameter_not_applicable`/`attribute_not_applicable`); проверка значения параметра по `value_type` (точное/не менее/не более/диапазон/текст/enum), позитивность, потолок, комбинации условий (наборы «required/optional/остальные запрещены» из БД, условия-константы `fixed_value`), правила атрибутов; сложные межполевые правила — вызов именованных код-валидаторов из реестра (привязка — строкой в БД; неизвестное имя правила — громкая ошибка).
- Кэш каталога в памяти: снимок каталога иммутабелен в рамках обработки одного запроса; при каждом обращении к сервисам проверяется `catalog_revision` (единственный `SELECT schema_meta`) — при изменении снимок атомарно заменяется целиком (замена указателя). Это корректно и для нескольких процессов (CLI-импорт каталога в общую базу виден сайту без перезапуска).
- Валидация целостности самих определений (метасхема): единица существует, enum непуст для enum-типа, наборы условий ссылаются на известные условия и т.п. — при импорте каталога.

### 2.3. `internal/storage` — переносимое реляционное ядро

- `database/sql` + `sql.Named` (`@имя`), только переносимые конструкции: `LIMIT/OFFSET`, производные таблицы, `INSERT ... SELECT`, `EXISTS`; булевы — INTEGER 0/1; NULL — «не задано»; без JSON-функций, без диалектных типов (схема — `02-database.md`).
- `Dialect{Open, CreateTableSql, ...}` + две реализации:
  - **sqlite** (`modernc.org/sqlite`, pure Go, без cgo): два пула — несколько соединений чтения и одно выделенное соединение записи (`SetMaxOpenConns(1)`); на каждом соединении `PRAGMA foreign_keys = ON`, режим WAL и `busy_timeout` — одновременная работа сайта и CLI с одним файлом не падает на блокировке (запись сериализуется на уровне файла: один писатель). Правило: весь DML — только внутри явных транзакций через соединение записи; вне транзакций — только SELECT из пула чтения;
  - **postgres** (`pgx/v5/stdlib`): пул соединений, параметры пула из конфигурации.
- Версия схемы: при первом обращении чтение `schema_meta.schema_version`; несовпадение с версией модуля — `*domain.Error` с кодом `schema_version_mismatch` («база данных создана другой версией модуля (N ≠ M); пересоздайте её: удалите файл/базу и выполните import»). Продолжение работы запрещено. База, в которой нет таблицы `schema_meta` (не инициализирована, файл другой программы, повреждена), даёт отдельный код `database_not_initialized` («база данных не инициализирована или не является базой модуля; выполните init (CLI) или EnsureCreated») — тихая порча данных исключена (политика D5, миграций нет).
- `EnsureCreated` — только у команд записи (init/import/add), один запуск — один DDL (`CREATE … IF NOT EXISTS`); безопасен при гонке двух процессов: вставка версии выполняется как `INSERT … SELECT … WHERE NOT EXISTS`, конфликт PK трактуется как проигранная гонка с перечитыванием версии; чтение и delete без DDL.
- Запись — в транзакции (`Begin` + `defer Rollback` + `Commit`); после замены связей и удалений удаляются производители, оставшиеся без единой связи (`NOT IN` по `device_manufacturers`).

### 2.4. `internal/service` — сервисный слой (публичный API библиотеки)

Единственная точка входа для CLI, REST и внешнего кода сайта. Интерфейсы (эскизы сигнатур — в `04-module-functionality.md`):

- устройства: `Upsert` (семантика секций: отсутствует/`null` — не менять, задана — заменить целиком, `[]`/`{}` — очистить, ошибка в секции — запись не применяется вовсе; секция `variants` — исполнения типа: замена набора целиком; секция `manufacturers` — производители: замена списка целиком; секция `analogs` — исходящие направленные ссылки на аналоги (D8): замена только исходящих; исход `Skipped` — слитое состояние записи совпадает с текущим: записи в БД не выполняются, ревизии не инкрементируются), `Get`/`Card` (включая матрицу исполнений «номинал × напряжение → габариты/масса» и блок аналогов — исходящие и встречные), `Find` (точное обозначение + подсказка равнозначных по материалу для полупроводников `gost`), `Delete` (каскад), `Search` (фильтры + сортировка + пагинация; вариантные фильтры — в пределах одного исполнения), `Count`;
- каталог: `Catalog` (полный снимок для UI), `ImportCatalog`, `ExportCatalog`;
- импорт/экспорт: `Import(reader, format, dryRun)`, `Export(writer, format, kind)`;
- обозначения: `Parse(ctx, text)` (класс + система + каноническая строка + поля; автодетект, §2.4 `03-data-model.md`);
- производители: привязка записей.

Публичный фасад пакета для встраивания: `components.Open(ctx, cfg) (*App, error)` + `App.Close()`; `App.Services`, `App.Handler()`.

### 2.5. `internal/importer`

- Реестр форматов: jsonc/json (`tailscale/hujson`), yaml/yml (`goccy/go-yaml`) и ndjson (построчный JSON, stdlib) для больших объёмов; семантика секций и дословные тексты ошибок — внутри `importer`.
- Корень: необязательные ключи-классы (`transistors`, `diodes`, `resistors`, `capacitors`) + опциональный `catalog`; хотя бы один ключ обязателен.
- Записи: `"КТ315Б"` | `{"name": ...}` | `{"name": ..., "system": "pro"}` (ключи `name`/`system` задают обозначение записи; `system` необязателен — автодетект, обязателен для `other`) + секции `attributes` / секции групп параметров (`parameters`, `ratings`, `dimensions` — имя секции задаётся группой каталога; форма — единые списки объектов, `06-examples.md`) / `manufacturers` / `variants` / `analogs`. Поля разбора в файле не задаются — их даёт разбор обозначения.
- Секция `catalog` — только коды и структурные поля (D9): ключи `name`/`description`/`symbol`/`display_name` отсутствуют и отвергаются как неизвестные.
- Идемпотентность импорта; Issues-модель (корневые проблемы + проблемы записей, накопление за один прогон; жёсткая ошибка — только синтаксис формата); дубликаты ключей в jsonc/yaml — ошибка разбора файла (тихая потеря данных недопустима).

### 2.6. `internal/i18n` — бандлы отображаемых строк (D9)

- Бандлы — Go-данные (карты «ключ → строка»), поставляются с бинарником; канонический язык — **en** (полнота обязательна и закреплена тестами), полный словарь также для **ru**. Namespace отображаемых строк сущностей: `kind.<код>`, `system.<код>` (+ `.description`), `family.<семейство>`, `unit.<код>.name`/`.symbol`, `condition.<код>`, `group.<код>`, `param.<код>`, `attr.<код>`, `rule.<код>`, `field.<поле разбора>`; сообщения (этап 8.3) — стабильные MsgID из реестра `internal/domain/messages.go`.
- Разрешение строки: локаль → en (fallback) → сам код сущности (последняя инстанция для расширений каталога данными, у которых нет записи в бандлах). Аргументы-сообщения (`i18n.Arg`, обёртка `domain.MsgArg`) разворачиваются рекурсивно — позиционные префиксы «раздел units, «кВ»» локализуются вместе с родительским сообщением.
- Переговоры локали: `Accept-Language` (q-значения, базовый подтег) для REST; CLI — явный `--lang en|ru`. Форматирование значений (этап 8.4): `i18n.FormatValue` — инженерные приставки производных единиц отображения (мкФ, МОм, кГц) и разделитель дробной части локали. Потребители пакетов — транспорты, тесты полноты и `domain` (только канонический рендер сообщений, без локали).

### 2.7. `internal/httpapi` — REST API

Версияуемый префикс `/api/v1`, `net/http` (Handler, монтируется в роутер сайта), JSON, OpenAPI-спецификация — артефакт. Список ресурсов и семантика — `04-module-functionality.md`. Аутентификация/авторизация — вне модуля. Локализация (D9): отображаемые поля (`kind_name`, `system_name`, `name`, названия групп/параметров/атрибутов, символы единиц в `/catalog`) заполняются по локали из бандлов `internal/i18n`; локаль — `Accept-Language` (по умолчанию en); коды в ответах всегда канонические.

### 2.8. `internal/cli`

Команды над `service`: `init`, `parse` (автодетект класса и системы), `add`, `import`, `list`, `info`, `find`, `delete`, `count`, `export` (устройства, round-trip формат наполнения), `catalog` (export/import). Общие опции: `--db/--dsn`, `--dialect`, `--system`, `--kind` (разрешает неоднозначность автодетекта; обязателен для класса `other`), `--dry-run`, `--lang en|ru` (локаль вывода, по умолчанию en — D9). Вывод: ожидаемые ошибки — с префиксом «Ошибка: », прочие — «Непредвиденная ошибка: », код выхода 1.

## 3. Сквозные механизмы

- **Конфигурация**: структура (диалект+DSN/путь, уровни логирования, параметры пула, лимиты пагинации, отключение `suggest`); без глобальных переменных; загрузка — код сайта или CLI-флаги/env.
- **Логирование**: `log/slog`, структурные поля, без обязательного глобального логгера (передаётся в `Open`).
- **Метрики**: интерфейс-хук (счётчики запросов/ошибок, длительности) — реализация на стороне сайта; свой экспорт метрик в модуле не заводим.
- **Контекст**: все сервисные операции принимают `context.Context`; тайм-ауты/отмена — на вызывающем.
- **Конкурентность**: библиотека безопасна для одновременного использования (stateless поверх пулов соединений; SQLite — одно выделенное соединение записи и пул чтения: один пишущий `App` на базу, читатели не блокируются записью в WAL); каталог-кэш — атомарная замена указателя (§2.2).
- **Кэширование ответов REST**: `ETag` по версии каталога (`catalog_revision`) и ревизии данных (`data_revision`, счётчик изменений) — сайт сам решает, как использовать.

## 4. Зависимости

База — stdlib. Внешние: `modernc.org/sqlite` (pure Go), `jackc/pgx/v5` (stdlib-режим), `tailscale/hujson`, `goccy/go-yaml`. Критерии добавления новых: заменяют самописный разбор или существенно сокращают код; pure Go без cgo; минимум транзитивных зависимостей; живое сопровождение. Граница ответственности библиотеки — лексика/синтаксис формата; семантика секций, порядок ключей и дословные тексты русских сообщений об ошибках остаются в `internal/importer`.
