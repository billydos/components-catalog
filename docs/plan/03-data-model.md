# 03. Модель данных: классы, системы обозначений, каталоги параметров и атрибутов

Документ фиксирует **стартовое наполнение** каталога (сиды `seed/`) — состав стартового наполнения: **минимальные каталоги** этого документа. Каталог — данные (D1): стартовые наборы расширяются без правки кода; перечисленное ниже — минимально достаточный справочник, а не потолок. Предметные перечни (подклассы, группы, таблицы букв и цифр систем обозначений, реестры семейств, примеры) выверены по первоисточникам: тексты ГОСТ Р 71055-2023 и PRO ELECTRON — в `docs/sources/`, ГОСТ Р 57440-2017 получен из открытых фондов; по ГОСТ 3453-68 и ОСТ 11.074.009-78 тексты в открытом доступе отсутствуют — использованы сходящиеся справочные пересказы. Источники, обоснования исправлений и остаточные работы — `07-r1-verification.md`.

## 1. Классы приборов и системы обозначений

### 1.1. Классы (`kinds`)

| Код | Название (ru-бандл) | Системы обозначений (`system_code`) |
|-----|----------|-------------------------------------|
| `transistor` | транзисторы | `gost`, `pro`, `jedec`, `jis`, `other` |
| `diode` | диоды | `gost`, `pro`, `jedec`, `jis`, `other` |
| `resistor` | резисторы | `gost`, `ost`, `other` |
| `capacitor` | конденсаторы | `gost`, `other` |
| `relay` | реле | `other` |

Названия — отображаемые строки бандлов `internal/i18n` (D9): в БД только коды; en-бандл: transistor / diode / resistor / capacitor / relay. Расширение (тиристоры/оптопары) — добавлением класса и парсера; реле добавлены классом **без парсера**: единой строгой системы обозначений реле нет (обозначения семейств — `РЭС-9`, заказные коды производителей), все записи — система `other` (§2.1) с классификацией секцией `fields` (§2.5). Схема и каталог данных при добавлении класса не меняются.

### 1.2. Реестр систем обозначений (`designation_systems`)

- реестр систем и применимость к классам (`designation_system_kinds`) — **данные**; добавление системы классу — вставка строк (+ реализация парсера в коде, если система строго формальна);
- система обозначения — атрибут записи: колонка `devices.system_code` (фильтр, индекс); результат разбора — поля в `device_designation_fields`;
- слабоструктурированные семейства (`МП39`, `МЛТ-0.5`, `КСО`) и бессистемные имена — записи системы **`other`**: разбора нет, только канонизация; семейство/номер/буквы — явные поля секции `fields` (справочник кодов семейств — `docs/class-keys.md` §12, историческая выверка — `07-r1-verification.md` §7);
- парсеры по типам систем: строгие грамматики (`gost`, `ost`, `pro`, `jedec`, `jis`) — код; `other` — без разбора (только канонизация);
- поля разбора имеют **единые имена для одинаковой семантики** (`material`, `subclass`, `junctions`, `dev_number`, `letters`, `series`) — сквозные фильтры между системами (например, материал: `gost` и `pro`; поле `series` задаётся явно для записей `other`). Значение поля `material` — стабильный код словаря (`ge`, `si`, `ga`, `in`, `sic`, `other`, `gaas`; D9): хранится в `device_designation_fields.text_value`, отображаемые названия — бандлы `internal/i18n` (`material.<код>`); фильтры поиска принимают код либо отображаемое название локали (канонизация на краю);
- производное поле `base` (базовое обозначение — тип записи, §2.6) — общий продукт парсеров строгих систем: группировка записей одного типа внутри класса, фильтр/сортировка поиска и блок «группа типа» карточки.

## 2. Обозначения по системам

### 2.1. Полупроводники (транзисторы, диоды)

Шесть применимых систем — колонка `system_code`:

- **`gost` (ГОСТ 10862-64 и преемники — ГОСТ 10862-72, ОСТ 11.336.919-81, ГОСТ Р 71055-2023):** одна система для исторических и современных написаний; выверка и источники — `07-r1-verification.md` §1
  - материал: `Г/1`→`ge` германий, `К/2`→`si` кремний, `А/3`→`ga` соединения галлия, `И/4`→`in` соединения индия; ГОСТ Р 71055-2023 добавил `Д/5`→`sic` соединения карбида и `П/6`→`other` соединения прочих металлов (стрелка — код словаря со сквозным фильтром); буква — общегражданское применение, цифры — категории качества ВП/ОС/ОСМ; **равнозначность только физическая** — `КТ312` и `2Т312` раздельные записи (подсказка `find` по паре символов материала — только для `gost`: у прочих систем пар символов материала нет);
  - подкласс: `Т` биполярный, `П` полевой (транзисторы); `Д` выпрямительные/универсальные/импульсные, `С` стабилитроны (в обозначениях по ГОСТ 10862-64 напряжение стабилизации — в двух последних цифрах номера: `КС168А` ≈ 6,8 В), `В` варикапы, `А` СВЧ-диоды, `И` туннельные, `Г` генераторные/шумовые, `Л` излучатели (светодиоды), `Ф` фотоприборы, `Ц` столбы/блоки, `Н` динисторы, `У` тринисторы (диоды и тиристоры); современные дополнения ГОСТ Р 71055-2023 — `Е` IGBT, `О` оптоэлектронные (с буквой функции: `ОИ` излучатели, `ОФ` приёмники, `ОД`/`ОТ`/`ОР`/`ОУ` оптопары), `Р` ограничители напряжения, `Ж` стабилизаторы тока, `Э` эффект Холла, `Х` детекторы ионизирующих излучений, `УП` полевые тиристоры с изолированным затвором, `М` модули; тиристоры/оптоэлектронные/модули — вне стартовых классов, но поддерживаются грамматикой (расширение классом без правки парсера);
  - признак (цифра 1–9 функционального назначения) обязателен в современных обозначениях (`2Т3148А`); в обозначениях по ГОСТ 10862-64 отсутствует — семантика в диапазонах трёхзначного номера (`КТ315Б`), номер 1–99 либо 101–999 (по ГОСТ Р 71055-2023);
  - буква группы — заглавная русская, кроме `З О Ч Ы Ш Щ Э Ю Я Ь Ъ`;
  - хвостовые элементы (опциональны, порядок фиксирован): сборка `С` — после подкласса в старых обозначениях (`КДС111В`) и после буквы группы в ГОСТ Р 71055-2023 (`2Д627АС`); подобранные группы `Р`/`Т`/`Г`/`К`/`Н` — пары/тройки/четвёрки/шестёрки/восьмёрки; уточнения `Д` (Дарлингтон, после `Т` — `КТД735В`) и `Ш` (Шоттки, после `Д` — `КДШ289А`); модернизация 1–9; `9` — корпус для поверхностного монтажа; `-1..-6` — бескорпусное исполнение; `/ИФ` — код предприятия-изготовителя воспроизводимого прибора;
  - поля разбора: `material` (текст — код словаря), `subclass` (текст — код словаря §2.5: `Т`→`bjt`, `П`→`fet`, `Д`/`Ц`→`rectifier`, `С`→`zener`, `В`→`varicap`, `А`→`detector`, `И`→`tunnel`, `Г`→`generator`, `Л`→`led`, `Ф`→`photo`), `assembly` (num 0/1), `feature` (num, NULL), `dev_number` (num), `letters` (текст), `modification` (num, NULL), `chip` (num, NULL). Примеры: `КТ315Б`, `2Т914А-1`, `КДС111В`, `КС168А`, `АЛ307Б`, `2Д627АС`, `КДШ289А`, `2П798Г/ИФ`.
- **`pro` (PRO ELECTRON, Европа):** `<материал><класс><номер>[<спец. буква>][<версионные буквы>][-<суффикс подклассификации>]` — две заглавные латинские буквы, номер, опциональные элементы; первоисточник — публикация Pro Electron/Philips (`docs/sources/PRO-ELECTRON.pdf`), выверка — `07-r1-verification.md` §2
  - первая буква — материал (для дискретных приборов только эти): `A`→`ge` германий (зона 0,6–1 эВ), `B`→`si` кремний (1–1,3 эВ), `C`→`gaas` арсенид галлия и соединения с зоной ≥ 1,3 эВ (стрелка — код словаря), `R` соединения без p-n-перехода (CdS-фоторезисторы — вне классов модуля);
  - вторая буква — класс прибора (полная таблица): `A` маломощный сигнальный диод, `B` варикап, `C`/`D` маломощный/мощный НЧ транзистор, `E` туннельный диод, `F`/`L` маломощный/мощный ВЧ транзистор, `G` набор разнородных приборов, `H` магниточувствительный диод, `N` оптопара, `P`/`Q` детектор/излучатель, `R`/`T` маломощный/мощный управляющий прибор (тиристоры, диаки, триаки), `S`/`U` маломощный/мощный ключевой транзистор, `W` ПАВ-устройство, `X` диод-умножитель (варактор, step-recovery), `Y` мощный выпрямитель, `Z` стабилитрон/стабистор/TVS; граница «маломощный/мощный» — Rth j-mb > / ≤ 15 К/Вт;
  - номер: `100`–`999` — приборы для бытовой аппаратуры; `<буква Z,Y,X…><10–99>` — промышленная/специальная регистрация (при исчерпании номеров — расширение до 4/3 цифр);
  - специальная третья буква (`A` триаки, `F` волоконная оптика, `L` лазеры, `O` оптотриаки, `T` трёхвыводные двухцветные LED, `W` TVS — по классу прибора) и версиональные буквы (1–2, без фиксированного значения, кроме `R` обратная полярность и `W` SMD);
  - суффиксы-подклассификации через дефис: у стабилитронов — буква допуска (`A` 1 % … `E` 20 %, `F` 3 %) + напряжение с `V` вместо запятой (`BZX85C5V1` — ±5 %, 5,1 В); у выпрямителей/тиристоров — VRRM/VDRM (`BYT-100`, `R` — обратная полярность); у TVS, ВЧ мощных транзисторов и массивов — своя семантика; хвост распознаётся, но в полях не раскладывается;
  - поля: `material` (текст — код словаря, единый с `gost`), `subclass` (текст — код словаря §2.5: `C`/`D`/`F`/`L`/`S`/`U`→`bjt`, `Y`→`rectifier`, `Z`→`zener`, `B`→`varicap`, `E`→`tunnel`, `A`→`signal`, `X`→`multiplier`, `H`→`magnetic`, `P`→`photo`, `Q`→`led`), `dev_number` (num), `letters` (текст, NULL). Примеры: `BC547B`, `AD161`, `BF245`, `BY133`, `BZX85C5V1`.
- **`jedec` (JEDEC, США; система EIA-370, с 1982 — JESD370B):** `<переходы>N<номер регистрации>[<суффикс>]` — цифра числа p-n-переходов (`1` диоды, `2` транзисторы и тиристоры, `3` четырёхвыводные приборы — тетроды/двухзатворные полевые; `4N` оптопары — вне классов модуля), `N` (по JESD370B — корпусированное изделие, `C` — кристалл), номер регистрации EIA, опциональные суффиксные буквы улучшенных версий (`2N2222A`); военные префиксы `JAN`/`JANTX` выводят обозначение из системы — класс `other`.
  - материал и подкласс/категория в обозначении **не кодируются** — задаются атрибутом `structure` и секцией `fields` (`material`, `subclass`, `category`; §2.5); фильтры по грамматическим полям обозначения — только номер и суффикс;
  - регистрация гарантирует взаимозаменяемость, а не идентичность: один номер выпускают многие производители — запись с несколькими производителями для `jedec` — норма (модель `device_manufacturers`);
  - поля: `junctions` (num), `dev_number` (num), `letters` (текст, NULL). Примеры: `1N4148`, `1N4007`, `2N2222A`, `2N3055`.
- **`jis` (JIS C 7012 / EIAJ, Япония):** `<переходы>S<класс><номер>[<суффикс>]` — цифра (`1` диоды, `2` транзисторы, `3` четырёхвыводные/двухзатворные), `S` — признак регистрации, заглавная латинская буква класса, номер регистрации JEITA-EDEREC (начинается с 11), опциональный суффикс (группы hFE `A`/`B`/`C`; у светодиодов — цвет).
  - класс (полный перечень): без буквы — диод (старые регистрации `1S2076`); `A` p-n-p ВЧ, `B` p-n-p НЧ, `C` n-p-n ВЧ, `D` n-p-n НЧ, `E` диод, `F` тиристор, `G` диод Ганна, `H` однопереходный, `J` p-канал ПТ, `K` n-канал ПТ (JFET и MOSFET), `M` симистор, `Q` светодиод, `R` выпрямительный, `S` сигнальный диод, `T` лавинный, `V` варикап, `Z` стабилитрон; тиристоры/симисторы — вне стартовых классов, грамматикой поддерживаются;
  - на корпусах префикс `2S` часто опускается (`C1815`) — канонизация восстанавливает полный формат; сокращённые формы не являются ключами записей;
  - поля: `junctions` (num), `subclass` (текст — код словаря §2.5: `A`–`D`→`bjt`, `J`/`K`→`fet`, `H`→`ujt`, `T`→`avalanche`, `F`→`thyristor`, `M`→`triac`, `E`/`R`→`rectifier`, `S`→`signal`, `Z`→`zener`, `V`→`varicap`, `G`→`gunn`, `Q`→`led`), `dev_number` (num), `letters` (текст, NULL). Примеры: `2SA1015`, `2SC1815`, `2SK1058`, `1S2076`, `1SS352`, `1SR154-400`.
- **`other` (без строгой системы):** произвольное имя компонента; разбора нет — только канонизация (§2.4); класс задаётся явно (ключ класса файла наполнения / `--kind`); полей грамматики парсер не устанавливает — классификация и данные семейства задаются секцией `fields` (§2.5): словарные `material`/`subclass`/`category` и грамматические `series`/`dev_number`/`letters`. Примеры: единичные фирменные имена, варианты JEDEC/Pro ELECTRON с военными префиксами (`JANTX2N3055`), полные заказные коды и MIL-обозначения вида `M39003/…` (атрибуция листов — `07-r1-verification.md` §8), досистемные семейства и дом-номера (`МП39`, `П214`, `OC44`, `TIP120`, `МЛТ-0.5`, `КСО`, `РЭС-9`; справочник кодов семейств — `docs/class-keys.md` §12, историческая выверка — `07-r1-verification.md` §7); номер в семействе и буквы — поля `dev_number`/`letters`, мощность резисторов — вариантный параметр `Pnom` (§7, D6). Реле — записи только этой системы (§1.1).

### 2.2. Резисторы

- **`gost` (ГОСТ 3453-68, заменён ОСТ 11.074.009-78 для новых разработок; атрибуция выверена — `07-r1-verification.md` §4):** `[С|СП]<группа 1–6>-<номер разработки><буквы>` — `С2-33Н`, `СП3-19А`, `С5-16МВ`. Семейства `СТ`/`СН`/`СФ` — терморезисторы/варисторы/фоторезисторы, иные классы приборов, резисторному классу не принадлежат. Группы `С`/`СП` (материал/технология): 1 непроволочные тонкослойные углеродистые и бороуглеродистые, 2 металлодиэлектрические/металлооксидные, 3 композиционные плёночные, 4 композиционные объёмные, 5 проволочные, 6 непроволочные тонкослойные металлизированные. Поля: `family` (`С`,`СП`), `adjustment` (текст — код словаря подстройки §2.5: `С`→`fixed`, `СП`→`variable`), `group` (num 1–6), `dev_number`, `letters` (буквы модификации). Суффикс мощности вида `С2-33Н-0.125` — элемент полного обозначения ГОСТ (исполнение/параметры/климат/ТУ, например `С2-29В-0,25-10,1кОм±1,0%-1,0-Б ОЖ0.467.130 ТУ`); **хвост не поддерживается**: ключом записи является сокращённое обозначение без хвоста, мощности задаются исполнениями-вариантами с `Pnom` (§7, решение D6); ввод обозначения с числовым хвостом после букв — ошибка разбора с подсказкой «используйте обозначение С2-33Н и секцию variants» (политика зафиксирована планом, консистентна с конденсаторами; данные не отбрасываются молча).
- **`ost` (ОСТ 11.074.009-78, действующая система):** `[Р|РП|НР]<материал 1|2>-<регистрационный номер>` — `Р` постоянные, `РП` переменные, `НР` наборы резисторов; материал: 1 непроволочные, 2 проволочные или металлофольговые; канонические примеры стандарта: `Р1-4`, `РП1-46` (семейства `ВР`/`ВРП`/`ТР`/`ТРП` — варисторы/терморезисторы, вне класса). Полное обозначение добавляет исполнение, параметры, климатическое исполнение (`В`/`Т`) и документ на поставку — в сокращённое не входят. Формы с `gost` **не пересекаются** (`С`/`СП` против `Р`/`РП`/`НР`) — автодетект однозначен. Поля: `family` (`Р`,`РП`,`НР`), `adjustment` (текст: `Р`/`НР`→`fixed`, `РП`→`variable`), `group` (num 1–2), `dev_number`, `letters` (текст, NULL).
- **`other`** — общие правила (§2.1).

### 2.3. Конденсаторы

- **`gost` (единая система; действующая кодификация — ГОСТ Р 57440-2017, историческая семантика групп — советские справочники; выверка — `07-r1-verification.md` §5):** `<подкласс><группа, 2 цифры>-<номер разработки><буква>`. Префиксы-подклассы: `К` постоянной ёмкости, `КТ` подстроечные, `КП` переменной ёмкости, `КН` нелинейные (ГОСТ Р 57440-2017); исторически также `КС` — конденсаторные сборки. Обозначения подстроечных вида `КТ4-25` принадлежат этой системе, а не записям `other` досистемных семейств. Примеры: `К10-17Б` (керамические < 1600 В), `К50-35` (алюминиевые электролитические), `К73-17` (ПЭТФ/лавсановые), `К78-2` (полипропиленовые), `К42-19` (бумажные металлизированные), `КТ4-25` (подстроечный с твёрдым диэлектриком). Группы (перспективные по ГОСТ Р 57440-2017): 10 керамика < 1600 В, 15 керамика ≥ 1600 В, 26 тонкоплёночные, 50 алюминиевые оксидно-электролитические, 51/52 танталовые фольговые/объёмно-пористые, 53 оксидно-полупроводниковые, 58 ионисторы, 61 вакуумные, 70 полиэтиленнафталатные, 73 ПЭТФ, 75 комбинированные, 76 полифениленсульфидные, 78 полипропиленовые; подстроечные 1–4 (вакуумные/воздушные/газообразные/твёрдый диэлектрик), переменные 1, нелинейные 1. Исторические группы (неперспективные, в т.ч. по приложению А стандарта): 21 стеклянные, 22 стеклокерамические, 23 стеклоэмалевые, 31/32 слюдяные малой/большой мощности, 40/41 бумажные фольговые < 2 кВ / ≥ 2 кВ, 42 бумажные металлизированные, 60 воздушные, 61 газообразные, 70/71 полистирольные фольговые/металлизированные, 72 фторопластовые, 73/74 ПЭТФ металлизированные/фольговые, 76 лакоплёночные, 77 поликарбонатные, 79 полиимидные — обе версии семантики хранятся данными с атрибуцией периода. Поля: `prefix` (`К`,`КТ`,`КП`,`КН`,`КС`), `adjustment` (текст: `К`/`КН`/`КС`→`fixed`, `КТ`→`preset`, `КП`→`variable`), `group` (num, таблица групп), `dev_number`, `letters` (буква варианта конструкции/ТКЕ — часть обозначения, к исполнениям §7 отношения не имеет).
- **`other`** — общие правила (§2.1).

### 2.4. Общие правила обозначений

- нормализация на входе: trim, верхний регистр, типографские дефисы → `-`, удаление пробелов, запятая → `.`; кириллица (`gost`) и латиница (`pro`, `jedec`, `jis`, `other`) не смешиваются в одном обозначении — смешение алфавитов диагностируется ошибкой с указанием позиции;
- каноническая строка обозначения — точный ключ записи внутри класса; система — атрибут записи, не часть ключа;
- парсеры всех строгих систем помимо грамматических полей дают производное поле `base` — базовое обозначение (тип) записи: каноническая строка без буквы классификации и хвостовых элементов (§2.6);
- сообщения об ошибках разбора — по-позиционные, с «ожидалось/получено» (контракт, тесты дословные);
- автодетект класса и системы по обозначению; порядок попыток: полупроводник `gost` → `pro` → `jedec` → `jis` → резистор `gost`/`ost` → конденсатор `gost`; обозначения вне строгих грамматик (включая бывшие серийные семейства) автодетектом не опознаются — ошибка `autodetect_failed`, система `other` требует явного указания (ключ `system` в записи наполнения, `--kind`/`--system` в CLI); пересечения форм разводятся порядком попыток и алфавитом (кириллица/латиница), неоднозначность — явным ключом класса/системы, который **переопределяет** автодетект;
- класс при автодетекте определяется системой обозначений: `gost`-подкласс `Т`/`П` → транзистор, `Д`/`С`/`В`/`А`/`И`/`Г`/`Л`/`Ц` → диод, `Ф` — неоднозначно (фотодиоды и фототранзисторы) — только явное указание класса, остальные подклассы (`Н`,`У`,`Е`,`О`,`Р`,`Ж`,`Э`,`Х`,`УП`,`М`) — ошибка `kind_not_supported` («обозначение принадлежит классу, не поддерживаемому модулем»); `pro`: вторая буква `C`,`D`,`F`,`L`,`S`,`U` → транзистор, `A`,`B`,`E`,`H`,`P`,`Q`,`X`,`Y`,`Z` → диод, `G`,`N`,`R`,`T`,`W` — ошибка `kind_not_supported`; `jedec`/`jis`: 1 → диод, 2 и 3 → транзистор (тетроды/двухзатворные — транзисторы), 4 (`4N` оптопары) — ошибка `kind_not_supported`; резисторные (`gost`/`ost`) и конденсаторная (`gost`) системы дают свой класс однозначно; `other` класс из обозначения не выводит — только явное указание.

### 2.5. Классификационные поля (секция `fields`, словари)

`fields` — словарный классификационный слой поверх всех систем обозначений
(схема v4; расширение для записей `other` — схема v6). Реестр полей разбора
(`internal/domain/designation.go`) помимо продуктов парсеров содержит
классификационные поля; значения — стабильные коды словарей (D9),
отображение — бандлы `internal/i18n`.

| Поле | Словарь | Применимость | Разбором дают | Секцией `fields` |
|------|---------|--------------|---------------|------------------|
| `material` | домен: `ge`, `si`, `ga`, `in`, `sic`, `other`, `gaas` | транзисторы, диоды | `gost`, `pro` | `jedec`, `jis`, `other` |
| `subclass` | домен, 17 кодов (таблица ниже) | транзисторы, диоды | `gost`, `pro`, `jis` | `jedec`, `other` |
| `adjustment` | домен: `fixed`, `variable`, `preset` | резисторы, конденсаторы | `gost`/`ost` (резисторы), `gost` (конденсаторы) | `other` |
| `category` | каталог (таблица `categories`, данные) | все классы | никто | все системы |
| `assembly` | 0/1 | транзисторы, диоды | `gost` | `pro`, `jedec`, `jis`, `other` |

Для записей `other` (разбора нет — пер-полое правило выполняется тривиально)
секция дополнительно задаёт грамматические поля бывшей системы series
(компенсация её удаления, D10; все — необязательные):

| Поле | Значение | Применимость |
|------|----------|--------------|
| `series` | код семейства — непустой текст, канонизируется верхним регистром (справочник кодов — `docs/class-keys.md` §12) | все классы |
| `dev_number` | номер разработки — положительное целое | все классы |
| `letters` | буквы — непустой текст, канонизируется верхним регистром | все классы |

Мощность (хвост `МЛТ-0.5`) полем не компенсируется — номинальная мощность
резисторов нормируется вариантным параметром `Pnom` (§7, правило
`resistor_variant_power`, D6), дублирование исключено.

Правила (валидация сервисного слоя после разбора — известны класс и
система записи):

- `fields` задаёт только поле, которое парсер системы записи не
  устанавливает сам (пер-полое правило; переопределение продукта разбора —
  ошибка `svc_field_parser_owned`), и только применимое к классу записи
  (`svc_field_not_applicable`); грамматические поля строгих систем (номер
  разработки, буквы, группа и т.п.) секцией не задаются вовсе — исключение
  записи `other`: для них допустимы `series`/`dev_number`/`letters`
  (парсер `other` не устанавливает ничего); производное поле `base`
  (тип, §2.6) не задаётся ни в одной системе — ошибка
  `svc_field_base_derived`;
- значения — коды словарей; коды категорий — из снимка каталога
  (`unknown_category` с перечнем допустимых);
- семантика секции — общая (D-решение о секциях): отсутствует/`null` — не
  менять, задана — заменить набор явных полей целиком, `{}` — очистить,
  ошибка в любом поле — запись не применяется; повторное применение того
  же набора — исход `Skipped` (канонический порядок — по имени поля);
- экспорт пишет секцию `fields` только с явными полями (хранимые минус
  продукты разбора обозначения минус производное `base` — разность
  всегда определена) — round-trip идемпотентен; для записей `other` тип
  пересчитывается при изменении явных `series`/`dev_number`;
- словарь `subclass` — наименьший общий знаменатель систем: полярность
  (p-n-p/n-p-n), частота и мощность кодируются атрибутом `structure` и
  параметрами, словарь их не дублирует; отображения букв — многие-к-одному
  (`jis` `C` и `gost` `Т` → `bjt`), обратных расщеплений нет; словарь
  ортогонален `category` (применение/характеристика) — пересечение кодов
  запрещено.

### 2.6. Базовое обозначение (тип)

Записи одного **типа** — семейство обозначений, различающихся буквой
классификации и хвостовыми элементами при общем номере разработки
(КТ315А/Б/В/Г; BC547A/B/C; 2SC1815-ранги; С2-33А/Н). Тип — производное
поле разбора `base`: каноническая строка без буквы классификации
(`letters`) и хвостовых элементов (подобранные группы, модернизация/`9`,
`-1..-6`, `/ИФ`; суффиксы pro/jedec/jis):

| Система | base | Примеры (обозначение → base) |
|---------|------|------------------------------|
| `gost` полупроводники | материал + подкласс (+уточнение Д/Ш, сборка С старой позиции) + признак + номер разработки | `КТ315Б` → `КТ315`; `2Т914А-1` → `2Т914`; `КДС111В` → `КДС111`; `2Д627АС` → `2Д627`; `АЛС324Б1` → `АЛС324` |
| `gost`/`ost` резисторы, `gost` конденсаторы | семейство/префикс + группа + номер разработки | `С2-33Н` → `С2-33`; `РП1-46` → `РП1-46` |
| `pro` | материал + класс + номер (без версиональных букв и суффиксов) | `BC547B` → `BC547`; `BZX85C5V1` → `BZX85` |
| `jedec` | переходы + N/C + номер (без суффиксных букв) | `2N2222A` → `2N2222` |
| `jis` | переходы + S + класс + номер (без суффиксов) | `2SC1815Y` → `2SC1815`; `1SR154-400` → `1SR154` |
| `other` | явные поля `series` + `dev_number` (`МП41А` → `МП41`); без семейства — само обозначение | `МП39` → `МП39` |

Правила:

- `base` — продукт парсеров строгих систем; для записей `other`
  вычисляется сервисным слоем по слитому состоянию явных полей
  `series`/`dev_number`. Хранится строкой `device_designation_fields`
  (схема v8), в секции `fields` формата наполнения не задаётся
  (производное — ошибка `svc_field_base_derived`); round-trip экспорт
  его не пишет;
- тип — измерение поверх записей, не замена исполнений (§7): буква
  классификации остаётся элементом сокращённого обозначения и ключом
  записи (раздельность записей — в пределах типа), общие значения типа
  не наследуются — у каждой записи своя строка ТУ/справочника;
- `base` — текстовое поле реестра полей разбора: фильтр (`?base=` /
  `--base`, значение канонизируется как обозначение) и сортировка
  поиска; карточка несёт блок «группа типа» — соседние записи того же
  класса с тем же типом и мини-матрицу различий данных типа в целом
  (порядок записей — по обозначению, параметров — каталог); подсказка
  `find` при ненайденном обозначении предлагает соседа по типу
  (КТ315А → КТ315Б), если нет равнозначной по материалу записи.

## 4. Условия (`conditions`)

Стартовый набор (позитивные, кроме `temp` и `Vgs`; расширяемо данными):

|-----|----------|---------|

| `Iz` | ток стабилизации (стабилитроны) | `mA` |

| `pulse_duration` | длительность импульса | `us` |
| `temp` | температура среды (может быть отрицательной) | `degC` |

Пространства имён параметров и условий независимы: код `Vnom` — и параметр (§6.8), и условие (нормирование `Ileak`); в файле наполнения они не конфликтуют — параметр выбирается ключом `parameter`, условия задаются соседними ключами внутри значения (`06-examples.md`).

Импульсные предельные значения связываются с длительностью не отдельным правилом, а **обязательным условием** `pulse_duration` у соответствующих параметров.

## 5. Группы параметров (`parameter_groups`)

| Код | Секция наполнения/REST | Отображение (ru-бандл) | Применение |
|-----|------------------------|-------------|-----------|
| `electrical` | `parameters` | «Электрические параметры» / для конденсаторов «Характеристики» | транзисторы, диоды, резисторы, конденсаторы, реле |
| `limiting` | `ratings` | «Предельные эксплуатационные данные» | транзисторы, диоды, резисторы, реле; конденсаторы — только общие данные надёжности `operatingLife`/`shelfLife` (§6.12), прочие предельные данные конденсаторов по постановке отражены характеристиками (§6.8) |
| `dimensional` | `dimensions` | «Массогабаритные данные» | все классы (масса; габариты — преимущественно конденсаторы) |

Отображаемые названия групп — бандлы `internal/i18n` (en: Electrical parameters / Absolute maximum ratings / Mass and dimensions); `section_name` — ключ формата (ASCII), в БД отображаемого текста нет (D9). Группа задаёт: секцию файла наполнения, порядок на карточке, семантику замены (секция заменяется целиком по группе).

## 6. Каталог параметров (стартовые сиды)

Типы значений: `exact` (точное), `at_least` (min), `at_most` (max), `range` (min..max), `text`, `enum`. Дополнение: тип `at_least` может нести необязательную верхнюю границу (value_max) — «не менее X, не более Y». Колонка `allow_negative` (у температурных пределов) разрешает неположительные значения; по умолчанию значения и условия положительны. Единицы в разделе указаны русскими условными обозначениями — фактические значения колонки `unit_code` — канонические коды §3 (`МГц` = `MHz`, `мкА` = `uA`, `Вт` = `W` и т.д.). Отображаемые названия параметров — бандлы `internal/i18n`: `param.<код>` (D9). Enum-параметры многозначны: несколько разных значений при одних условиях — допустимые строки значений (повтор того же значения — дубликат); для ТКЕ, описывающего группу материала записи, — регламентом одно значение.

Коды параметров глобально уникальны (PK `parameters.code`). Коды — **международная даташитная номенклатура** (IEC/JEDEC, U→V): `Vf`/`Vr`/`Vz` — напряжения, `hfe`/`hfb` — коэффициенты передачи, `fT` — граничная частота, `Idss`/`Igss`/`Icbo`/`Iceo`/`Icer` — токи, `Ciss`/`Coss`/`Crss`/`Cobo`/`Cibo` — ёмкости, `RdsOn` — сопротивление в открытом состоянии. Словарь квалификаторов фиксирован и обязателен для расширений каталога (данные, D1): пары выводов (`ce`, `cb`, `eb`, `be`, `ds`, `gs`), суффиксы режимов (`Sat`, `Off`, `Th`, `On`), суффиксы предельных значений (`Max`, `Min`, `Pulse`), классические группы JEDEC (суффикс `o` — «третий вывод разомкнут»: `Icbo`, `VceoMax`), стандартные аббревиатуры (`NF`, `TCR`, `TCC`, `DF`, `Esr`), греческие символы — латинскими именами (`Eta`, `Tauc`, `AlphaVz`, `Lambda`). Советской НТД-номенклатуре (Uкэ.нас, Iкбо, h21э, Uзи.отс…) коды соответствуют взаимно-однозначно; отображаемые названия ru-бандла сохраняют терминологию НТД; отклонение нового кода от словаря — не ошибка валидации, а предмет ревью наполнения. Применимость параметра к классам — строки `parameter_kinds` (D7): пустой набор = «все классы», включая добавленные в будущем; ниже применимость указана в фигурных скобках, «все классы» — без пометки. Параметры в **разных группах** — всегда разные строки и потому разные коды: температурный диапазон как предельные данные (`TempMin`/`TempMax`, группа `limiting`, {транзистор, диод, резистор}) и как рабочая характеристика конденсаторов (`opTempMin`/`opTempMax`, группа `electrical`, {конденсатор}) — намеренно разные коды; правило `temp_pair` (§11) привязано к обеим парам.

Величины биполярных и полевых транзисторов (подкласс `fet`: с управляющим p-n-переходом и с изолированным затвором) разведены по кодам — по электроду: `PcMax` — мощность **коллектора** (биполярные), `PdMax` — мощность **стока** (полевые); `IcPulseMax`/`PcPulseMax` — импульсные величины коллектора, `IdPulseMax` — импульсный ток стока. Применимость и тех и других — {транзистор}: подкласс (`bjt`/`fet`) в механизм применимости не входит, поэтому пересечений **величин по кодам** не допускается — один код не может служить и коллекторной, и стоковой величине. Разделение схем измерения — наборами условий: полевые несут условия `Vds`/`Vgs`/`Id` (§4), наборы биполярных (`Vce`/`Vcb`/`Veb`, `Ic`/`Ie`/`Ib`) с ними не смешиваются — значение обязано соответствовать одному набору целиком.

### 6.1. Транзисторы — `electrical`

Применимость всех параметров раздела — {транзистор}. `hfe` (диапазон; Vce+Ic | Vcb+Ie), `hfb` (не менее, опционально диапазон; Vcb+Ie), `fT` МГц (не менее; Vce+Ic | Vcb+Ie), `VceCutoff` В (не менее; Ic|Ie), `VceSat` В (не более; Ic|Ie), `VbeSat` В (не более; Ic|Ie), `Icbo`/`Iebo`/`Iceo` мкА (не более; Vcb/Veb/Vce), `Icer` мкА (Vce+Rbe), `h11` Ом (Vce+Ic), `Cobo`/`Cibo` пФ (не более; Vcb/Veb), `Tauc` пс (не более; Vcb+Ie), `Ton`/`Toff` нс (не более; Ic+Ib), `NF` дБ (не более; Vce+Ic+freq, опц. Rg | Vcb+Ie+freq, опц. Rg), `Pout` Вт (не менее; freq, опц. Vce+Ic), `Gp` дБ (не менее; freq, опц. Vce+Ic), `Eta` % (не менее; freq, опц. Vce+Ic; потолок 100) — величины биполярных.

Полевые транзисторы — собственные коды (без пересечений с биполярными, см. вступление §6): `Idss` мА (диапазон; Vds + Vgs — константа 0, `fixed_value`), `gfs` мА/В (не менее; Vds + Vgs=0 | Vds+Id), `VgsOff` В (диапазон, отрицательные допустимы; Id, опц. Vds — напряжение отсечки: управляющий переход и МОП со встроенным каналом), `VgsTh` В (диапазон, отрицательные допустимы; Id, опц. Vds — пороговое напряжение: МОП с индуцированным каналом), `Igss` нА (не более; Vgs, опц. temp — ток утечки затвора: управляющий переход и изолированный затвор), `Ciss`/`Crss`/`Coss` пФ (не более; Vds, опц. Vgs — входная/проходная/выходная ёмкости), `RdsOn` Ом (не более; Id+Vgs — сопротивление сток-исток в открытом состоянии). Коэффициент шума и выходные величины СВЧ-режима (`NF`/`Pout`/`Gp`/`Eta`) стартовым набором нормированы только схемами биполярных; для полевых они расширяются данными через секцию `catalog` — собственными кодами либо дополнительными наборами условий с `Vds`/`Vgs`/`Id`.

### 6.2. Транзисторы — `limiting`

Применимость всех параметров раздела — {транзистор}, кроме отмеченного; все — `exact`. `VcbMax`, `VebMax`, `VceoMax` В; `IcMax`, `IbMax` мА; `PcMax` мВт — наибольшая рассеиваемая мощность **коллектора** (биполярные); `VdsMax` В / `IdMax` мА — предельные напряжение сток-исток и ток стока (полевые; у биполярных им соответствуют `VceoMax`/`IcMax`); `VgsMax` В — наибольшее напряжение затвор-исток (полевые; `allow_negative` — p-канальные приборы); `PdMax` мВт — наибольшая рассеиваемая мощность **стока** (полевые; у биполярных ей соответствует `PcMax`); `IcPulseMax` мА (обязательное условие `pulse_duration`) и `PcPulseMax` мВт (то же) — импульсные величины коллектора (биполярные); `IdPulseMax` мА (+`pulse_duration`) — импульсный ток стока (полевые); `TempMin`/`TempMax` °C (`allow_negative`), `TempJunctionMax` °C, `Rth` °C/Вт — три последние с применимостью {транзистор, диод, резистор} (используются также §6.4/§6.6).

### 6.3. Диоды — `electrical`

Применимость всех параметров раздела — {диод}. `Vf` В (не более; If), `Ir` мкА (не более; Vr, опц. temp), `Ctot` пФ (не более; Vr, опц. freq), `Cratio` раз (не менее; Vr; unit NULL, «раз» — в названии), `trr` нс (не более; If), `Vz` В (диапазон; Iz), `Rdiff` Ом (не более; Iz), `AlphaVz` %/°C (не более; Iz), `Gconv` дБ (не более; freq), `Iv` мкд (диапазон; If), `Lambda` нм (диапазон). Номенклатура величин — по терминологии НТД (`07-r1-verification.md` §9).

### 6.4. Диоды — `limiting`

Применимость всех параметров раздела — {диод}, кроме отмеченного. `VrMax` В, `VrPulseMax` В (+`pulse_duration`), `IfMax` мА, `IfPulseMax` мА (+`pulse_duration`), `Pmax` мВт, `IzMin`/`IzMax` мА (стабилитроны); `TempMin`/`TempMax`/`TempJunctionMax`, `Rth` — применимость {транзистор, диод, резистор} (см. §6.2). Номенклатура величин — по терминологии НТД (`07-r1-verification.md` §9).

### 6.5. Резисторы — `electrical`

Применимость всех параметров раздела — {резистор}, кроме отмеченного. `Rnom` Ом (диапазон — границы ряда номиналов типа), `Tolerance` % (не более; {резистор, конденсатор}), `nominalRow` — **enum** ({резистор, конденсатор}; ряды предпочтительных величин по ГОСТ 28884-90 / МЭК 60063: `E3`, `E6`, `E12`, `E24`, `E48`, `E96`, `E192`, выверка — `07-r1-verification.md` §11; многозначный — серия может выпускаться в нескольких рядах по градациям допуска, например МЛТ: `E24`+`E96` при ±2/±5/±10 %; связь ряда с `Tolerance` — регламент наполнения, межполевого правила нет; допускается вариантное значение — у электролитических конденсаторов вместе с `Cnom` варианта), `TCR` 10⁻⁶/°C (не более), `Vnoise` мкВ/В (не более; unit NULL + пояснение в названии), `Rins` Ом (не менее; {резистор, конденсатор}; значения до 10¹⁰ — вывод инженерными суффиксами). Номенклатура величин — по терминологии НТД (`07-r1-verification.md` §9).

### 6.6. Резисторы — `limiting`

Применимость всех параметров раздела — {резистор}, кроме отмеченного. `Pnom` Вт, `Vmax` В, `VPulseMax` В (+`pulse_duration`); `TempMin`/`TempMax` — применимость {транзистор, диод, резистор} (см. §6.2), покрывают температуру окружающей среды. Снижение мощности при нагреве — примечанием (`notes`), не данными.

Переменные/подстроечные и многосекционные (раздел «предельные эксплуатационные данные» справочника): `imbalance` дБ (не более — разбаланс сопротивления секций многосекционных резисторов; справочник допускает до 3 дБ для общего назначения), `endurance` — не менее, unit NULL («циклов» — в названии; износоустойчивость подвижной системы переменных/подстроечных), `rotationAngle` ° (не менее — полный угол поворота оси), `switchAngle` ° (не более — углы срабатывания выключателя у резисторов с выключателем), `staticFrictionTorque` мН·м (не более — момент статического трения подвижной системы переменных/подстроечных; даташитные гс·см переводятся), `humidity` % (не более, опц. temp — относительная влажность воздуха). Применимость этих параметров к переменным/многосекционным экземплярам — регламент наполнения, межполевого правила нет (подстройка — словарь `adjustment`, секции — атрибут `sections`, §2.5/§10). Минимальная наработка и срок сохраняемости — общие данные надёжности §6.12.

### 6.7. Общие — `dimensional` (применимость — все классы)

`massMax` г (`exact`), `length`/`width`/`height` мм, `diameter`/`leadLength` мм, `leadPitch` мм (`exact`; габариты — преимущественно конденсаторы; правило `cap_dimensions_form`). Высота `height` входит и в цилиндрический набор как второй габарит корпуса (радиальные конденсаторы К50-35 по ОЖ0.464.214 ТУ — диаметр × высота + шаг выводов, длина радиальных выводов изготовителем не нормируется; осевые резисторы С2-33Н — диаметр × длина корпуса) — поправка этапа 6, `08-data-verification.md`.

### 6.8. Конденсаторы — `electrical` («характеристики»)

Применимость всех параметров раздела — {конденсатор}, кроме отмеченного. `Cnom` пФ (диапазон), `Tolerance` % (не более; {резистор, конденсатор}), `nominalRow` — enum ({резистор, конденсатор}; ряды номинальных значений — см. §6.5; у электролитических может быть вариантным — вместе с `Cnom` варианта), `TCC` — **enum** (выверен по таблицам ТКЕ, `07-r1-verification.md` §6): нормируемый ТКЕ `П100` (вариант `П120`), `П60`, `П33`, `МП0`, `М33`, `М47`, `М75`, `М150`, `М220`, `М330`, `М470`, `М750` (вариант `М700`), `М1500` (вариант `М1300`), `М2200`; ненормируемый (сегнетокерамика) `Н10`, `Н20`, `Н30`, `Н50`, `Н70`, `Н90`; международные коды EIA RS-198 (§6 там же): класс 1 — `C0G`, `NP0`, `U2J`; класс 2 — `X5R`, `X6S`, `X7R`, `X7S`, `X8R`, `Y5V`, `Z5U` — варианты написания (`П100`/`П120`, `М750`/`М700`, `М1500`/`М1300`, `C0G`/`NP0`) являются отдельными допустимыми значениями enum, синонимия советских групп и кодов EIA (`МП0` ≈ `C0G`/`NP0`, `М750` ≈ `U2J`) и объединение синонимов в фильтрах — вне первого релиза; `Vnom` В (exact), `DF` % (не более; опц. temp), `Rins` Ом (не менее; {резистор, конденсатор}), `Ileak` мкА (не более; Vnom, опц. temp), `Esr` Ом (не более; условие freq — константа 0.1 МГц, задаётся `fixed_value` набора условий), `Iripple` мА (не более; freq, опц. temp — допустимый ток пульсаций электролитических, вариантный), `opTempMin`/`opTempMax` °C (exact, `allow_negative` — рабочий диапазон температур как характеристика, по постановке без секции ratings; отдельные коды — см. вступление §6).

У электролитических конденсаторов `Vnom` и `Cnom` — преимущественно **вариантные** параметры (зависят от исполнения типа, см. §7); у типа в целом остаются допуск, tg δ, ток утечки (нормируется на номинальное напряжение варианта).

### 6.9. Правила именования кодов (величина/квалификатор)

Правила едины для параметров и условий (пространства имён независимы, §4) и обязательны для расширений каталога данными (секция `catalog`, D1): отклонение — не ошибка валидации, а основание отказа ревью наполнения. Код — ключ каталога и формата наполнения: переименование — несовместимое изменение, эволюция каталога — только новыми кодами.

**а) Источник — международная номенклатура.** Код — плоская запись международного символа величины (IEC/JEDEC; советское U передаётся V). Символ не изобретается: у величины есть международный символ — код символьный (б–г); символа нет (среда, конструктив, паспортные данные: температура, масса, допуск) — словесный код (д). Советские обозначения (Uкэ.нас, Iкбо, h21э…) в код не пишутся: величинам НТД соответствуют международные символы взаимно-однозначно, терминология НТД — в ru-названии бандла.

**б) Структура** — слева направо, слитно (без точек, дефисов, подчёркиваний), латиница; цифровые индексы символа сохраняются (`h11`):

```
<символ величины><выводы | свойство><режим><Pulse><Max | Min>
```

Подстрочные индексы и скобочные суффиксы международной записи сливаются в порядке записи: `V_CE(sat)` → `VceSat`, `R_DS(on)` → `RdsOn`, `I_CBO` → `Icbo`, `f_T` → `fT`, `t_rr` → `trr`, `α_VZ` → `AlphaVz`, `τ_c` → `Tauc`.

**в) Регистр токена кодирует его роль** (норма для новых кодов):

| Токен | Регистр | Примеры |
|-------|---------|---------|
| символ величины | прописная — `V`, `I`, `C`, `R`, `P`, `G`; строчные `f`, `h`, `g`, `t` — величины, строчные в самой номенклатуре | `Vce`, `Ic`, `Ciss`, `RdsOn`, `fT`, `hfe`, `gfs`, `trr` |
| акроним величины без буквенного символа | все прописные | `NF`, `TCR`, `TCC`, `DF` |
| греческая буква | латинское имя с прописной (символом или квалификатором) | `Eta`, `Lambda`, `Tauc`, `AlphaVz` |
| вывод / пара выводов | строчные | `ce`, `cb`, `eb`, `be`, `ds`, `gs`, `ss`; одиночные — `b`, `c`, `d`, `e`, `g`, `p`, `f`, `r`, `v`, `z` |
| JEDEC-буква конфигурации третьего вывода | строчная | `o` (разомкнут): `Icbo`, `Cobo`, `VceoMax`; `r` (через сопротивление): `Icer` |
| свойство-слово | однословное — строчные; составное (несколько слов) — camelCase: первый компонент строчными, последующие с прописной | `nom`, `diff`, `tot`, `out`, `th`, `fs`, `ins`, `conv`, `leak`, `ripple`, `noise`, `ratio`, `load`; составное: `coilNom` (`VcoilNom`) |
| режим / состояние | первая прописная | `Sat`, `Off`, `Th`, `On`, `Cutoff` |
| предельное значение | первая прописная | `Max`, `Min`, `Pulse` |

Составной код читается по токенам: `hfe` = `h`+`f`+`e` (h-параметр, прямая передача, общий эмиттер), `Tauc` = `Tau`+`c` (постоянная времени коллекторной цепи), `AlphaVz` = `Alpha`+`Vz` (ТКН при напряжении стабилизации), `Idss` = `I`+`d`+`ss` (ток стока при замкнутых затвор-исток), `VcoilNom` = `V`+`coilNom` (номинальное напряжение обмотки реле — составное свойство camelCase).

**г) Порядок суффиксов.** Выводы или свойство — сразу за символом величины (`VgsTh`, `Rth`, `Ctot`); режим — после них (`VceSat`, `VgsOff`, `RdsOn`); `Pulse` — перед `Max`/`Min` (`IcPulseMax`, `VrPulseMax`, `PcPulseMax`). Импульсное предельное значение несёт обязательное условие `pulse_duration` (§4).

**д) Словесные коды** — для величин без международного символа: английское имя, camelCase, первая буква строчная; суффиксы пределов — как у символьных: `massMax`, `leadLength`, `nominalRow`, `opTempMin`; условия среды — коротким словом (`freq`, `temp`).

**е) Единица не входит в код.** Величина и её каноническая единица — независимые атрибуты определения (`parameters.code`, `parameters.unit_code`); правила кодов единиц — §3.

**ж) Исторические отклонения стартового сида** — действующие коди, не образец для новых: `Pmax` (строчной суффикс предела — ср. `Vmax`, `PcMax`), `Ton`/`Toff` (прописной символ времени — ср. `trr`), `Tolerance`, `TempMin`, `TempMax`, `TempJunctionMax` (прописная первая у словесного кода — ср. `massMax`, `opTempMin`), `Esr` (смешанный регистр акронима), `pulse_duration` (подчёркивание в словесном коде — ср. `leadPitch`). Переименование — отдельное несовместимое изменение формата; новые коды по ним не образуются.

### 6.10. Реле — `electrical`

Применимость всех параметров раздела — {реле}; все — безусловные (контекст измерения — режим обмотки и цепи контактов — добавляется данными новыми условиями по мере выверки наполнения). Обмотка: `VcoilNom` В (exact — номинальное напряжение обмотки), `Rcoil` Ом (диапазон — допуск сопротивления обмотки), `Pcoil` Вт (не более — мощность, потребляемая обмоткой), `Vpickup` В (не более — напряжение срабатывания), `Vdropout` В (не менее — напряжение отпускания), `Ipickup` мА (не более — ток срабатывания; токовые обмотки). Контакты и изоляция: `Rcontact` Ом (не более — сопротивление контактов), `Vtest` В (не менее — испытательное напряжение изоляции обмотка—контакты), `Rins` Ом (не менее; применимость {резистор, конденсатор, реле} — см. §6.5). Времена: `tOperate`/`tRelease` мс (не более — время срабатывания/отпускания; строчной символ времени `t` — норма §6.9в, ср. `trr`), `tBounce` мс (не более — время дребезга контактов). Износостойкость: `enduranceElec`/`enduranceMech` — не менее, unit NULL («циклов» — в названии): коммутационная (под нагрузкой) и механическая.

### 6.11. Реле — `limiting`

Применимость всех параметров раздела — {реле}, кроме отмеченного; все — exact. `VswitchMax` В — наибольшее коммутируемое напряжение, `IswitchMax` А — наибольший коммутируемый ток (ток — в `A`, в отличие от `mA` полупроводниковых величин: коммутируемые токи реле единицы–десятки ампер); `TempMin`/`TempMax` °C — применимость {транзистор, диод, резистор, реле} (см. §6.2). Исполнения-паспорта реле — §7: вариант обязан иметь `Rcoil` и обмоточный номинал `VcoilNom`/`Ipickup` (правило `relay_variant_coil`); без паспортов запись допустима (обмотка не выверена — `Rcoil` диапазоном на уровне типа).

### 6.12. Общие — предельные данные надёжности (`limiting`, применимость — все классы)

`operatingLife` ч (не менее — минимальная наработка), `shelfLife` г. (не менее — срок сохраняемости). Обе величины — паспортные данные надёжности любого прибора, потому применимость пустая (все классы, включая будущие, D7); у конденсаторов это единственные представители секции `ratings` (§5) — остальные предельные данные конденсаторов остаются рабочими характеристиками `opTempMin`/`opTempMax` (§6.8). Даташитные месяцы сохраняемости переводятся в годы до записи.

## 7. Исполнения (варианты) номиналов

Зависимость массогабаритных данных от ёмкости и напряжения — норма для электролитических конденсаторов: у `К50-35` ёмкость 1 мкФ выпускается только на 160 В, а габариты и масса растут с произведением C×U; у резисторов габариты зависят от мощности (`С2-33`: 0.125–2 Вт). Плоский набор значений на запись этого не выражает, а заводить отдельную запись на каждое сочетание нельзя — напряжение в обозначение единой системы (`gost`) не входит, обозначение — точный ключ. Поэтому:

- **вариант (исполнение)** — строка `device_variants` (метка для карточки: «160 В», «0.125 Вт», «РС4.529.029-00») + значения параметров с `variant_id` + **атрибуты исполнения** (строки `device_variant_attribute_values`, §10): конструктивные признаки, различающиеся по исполнениям одного типа, — у переменных резисторов семейства вида СП3-33 это закон изменения сопротивления (`functionalChar`), вид конца вала, число секций; у реле — контактная группа паспорта (`contactForm`). Атрибуты двухуровневые: значение записи — признак типа в целом, значение исполнения — признак конкретного исполнения; один код допустим на обоих уровнях (правило выбора — контекст: тип в целом против исполнения), валидируются одинаково (существование, применимость к классу, тип значения — движком);
- мощности резисторных типов задаются вариантами с обязательным `Pnom` (правило `resistor_variant_power`); хвост мощности в обозначении ГОСТ не поддерживается и в ключ не входит (§2.2);
- обмотки реле задаются вариантами-паспортами с обязательным `Rcoil` и обмоточным номиналом — `VcoilNom` либо `Ipickup` для токовых обмоток (правило `relay_variant_coil`, §6.11): под одним номером разработки существует до десятка исполнений (паспортов), отличающихся обмоткой, а также коммутируемой способностью и родом тока (07 §13); децимальный номер паспорта — элемент заказа, в ключ записи не входящий, метка варианта — код паспорта (у мировых серий — номинал катушки); общий для паспортов номинал напряжения не уникален (исполнения различаются сопротивлением и контактами), исполнение идентифицирует метка;
- `variant_id = NULL` — данные типа в целом: `TCC`, `Tolerance`, `DF`, `Rins`, полярность, ТУ, годы; у реле — сопротивление контактов, изоляция, времена (если не зависят от паспорта), предельные данные типа;
- у варианта — свои значения характеристик (`Vnom` точное, `Cnom` как диапазон ряда на это напряжение) и **свои массогабаритные данные** (`diameter`+`leadLength` осевые, `diameter`+`height` радиальные, либо `length`+`width`+`height`; `massMax`);
- карточка отображает варианты матрицей «номинал × напряжение → габариты/масса»;
- правила: `cap_variant_matrix` — вариант электролитического конденсатора обязан иметь `Vnom` и `Cnom`, а при наличии габаритов — согласованный набор формы корпуса; `resistor_variant_power` — вариант резистора обязан иметь `Pnom`; `relay_variant_coil` — вариант реле обязан иметь `Rcoil` и обмоточный номинал `VcoilNom`/`Ipickup` (привязка уровнем класса `capacitor`/`resistor`/`relay`); семантика конденсаторов подтверждена структурой полного обозначения ГОСТ Р 57440-2017 — напряжение и ёмкость суть элементы заказа, в сокращённое обозначение не входящие; реле — децимальными номерами паспортов (07 §13);
- уникальность исполнений в пределах записи: метка варианта и его ключевые значения (`Vnom` у конденсаторов, `Pnom` у резисторов) не повторяются — проверяет движок валидации; у реле уникальна метка-паспорт, `VcoilNom` может повторяться;
- поиск: фильтры атрибутов включают вариантные значения с той же семантикой одного исполнения, что и параметрические фильтры (04 §1) — все фильтры должны выполняться в пределах данных типа либо одного исполнения вместе с данными типа;
- транзисторы/диоды — без вариантов (раздельность записей задаётся буквой классификации обозначения); группировка внутри номера разработки — производным полем `base` (тип, §2.6): соседние записи одного типа — блок «группа типа» карточки и мини-матрица различий, без наследования общих значений;
- отличие от условий измерения: условие — контекст, в котором нормировано значение (напряжение, ток, частота, температура), вариант — конструктивное исполнение типа со своим набором значений; одно другому не заменяет, смешение в данных каталога запрещено (условия задаются у параметра, вариантность — фактом значений).

## 8. Аналоги (прямые ссылки между записями)

Аналоги — на основе **прямого указания**; автоматический подбор по характеристикам/атрибутам — вне модуля, задача бэкэнда-потребителя (модуль обеспечивает его параметрическим поиском и нормализованными полями/единицами).

- ссылка **направленная** (D8): `device_analogs(device_id, analog_device_id, note NULL)` читается как «для записи-владельца `device_id` аналогом является `analog_device_id`» (замена владельца аналогом); `note` относится именно к этому направлению («полный аналог», «с ограничениями: запас по напряжению и току»); обратная ссылка (B → A) — отдельная самостоятельная строка, может существовать одновременно с прямой и иметь другую note; enum-градаций в v1 нет — аналог есть редакторское утверждение, а не вывод из параметров;
- ссылка — между записями **одного класса** (межклассовые аналоги смысла не имеют); ссылки между разными системами обозначений — норма и главный случай (`КТ315` → `BC547`); несколько исходящих ссылок у записи — норма, количество не ограничено;
- наполнение: секция `analogs` записи — список обозначений того же класса (опционально объекты с `note`) — задаёт **исходящие** ссылки записи; семантика замены целиком (как у `manufacturers`) касается только исходящих ссылок: встречные ссылки других записей не затрагиваются; неизвестное обозначение — ошибка записи;
- round-trip идемпотентен по построению: экспорт выдаёт исходящие ссылки каждой записи, повторный импорт воспроизводит то же состояние независимо от порядка записей;
- валидация — только структурная: записи существуют, один класс, нет самоссылки и дубликата `(device_id, analog_device_id)`; сверка параметров аналогов не выполняется (иначе это автоподбор — вынесен за рамки модуля);
- карточка/REST: блок «аналоги» (исходящие, с системой и обозначением каждой ссылки) и блок «встречные ссылки» (кто указал запись аналогом); фильтр «имеет аналоги» — второй очередью.

## 9. Синонимы (исторические названия записей)

Компонент в разные годы выпуска мог нести разные имена: резистор `С5-35` (ГОСТ 3453-68) выпускался под досистемными названиями `ПЭВ`. Синоним — утверждение **тождества имени**, а не замены (аналоги — §8) и не равнозначности кода материала (§2): обозначение-синоним не является записью, собственной карточки не имеет и разрешается в запись-владельца. Тождество «запись ↔ запись» (когда старое имя — полноценная запись со своими данными) синонимами не покрывается и расширением не планируется: механизм решает задачу «ищем ПЭВ — попадаем на С5-35».

- хранение: `device_synonyms(device_id, designation, note NULL, year_from NULL, year_to NULL, sort_order)` — строка принадлежит владельцу `device_id`, PK `(device_id, designation)`, индекс по `designation` — разрешение find/поиска; каскад при удалении записи — FK. Направление одно: у синонима нет второй стороны-писателя, проблем затирания D8-рода не возникает по построению;
- владелец один, синонимов у записи — сколько угодно; `note` — происхождение имени («обозначение до введения ГОСТ 3453-68»), `yearFrom`/`yearTo` — годы употребления имени (границы 1949–2100 и порядок — по образцу правила `year_range` атрибутов);
- канонизация — как у обозначений записей (прописные, типографские дефисы); парсингом синоним **не** разбирается: досистемные имена лежат вне грамматик шести систем, `system` у синонима не задаётся;
- **уникальность в пределах класса**: синоним не совпадает с обозначением самой записи, с обозначением другой записи (в том числе создаваемой тем же прогоном импорта) и не принадлежит двум записям; инвариант проверяется при применении секции. Обратная сторона: создание записи с обозначением, занятым синонимом другой записи, отвергается (`already_exists`) — синоним не может молча оказаться в тени точного ключа;
- наполнение: секция `synonyms` записи — список строк-обозначений либо объектов `{name, note, yearFrom, yearTo}`; семантика секций общая (отсутствует/`null` — не менять, задана — заменить целиком, `[]` — очистить, ошибка в любом значении — запись не применяется вовсе); повторный импорт того же файла — `Skipped`;
- find: порядок разрешения — точный ключ записи → **синоним** → подсказки (равнозначная по материалу запись, сосед по типу); попадание по синониму помечается в ответе (`MatchedBySynonym`), точное обозначение записи не помечается; поиск `q=` и автодополнение `suggest` сопоставляют подстроку/префикс и с обозначением записи, и с её синонимами (совпадение возвращает запись-владельца);
- карточка/REST: блок «исторические обозначения» (`synonyms`: designation, note, year_from, year_to); CLI печатает строку «Синонимы» с годами и заметкой и помечает находку find по синониму; экспорт пишет секцию, round-trip идемпотентен.

## 10. Атрибуты (`attributes`, стартовые сиды)

Применимость атрибутов — строки `attribute_kinds` (D7): пустой набор = «все классы», явный список — в фигурных скобках; ключ атрибута в секции `attributes` — код. Применимость «все классы»: `description` (текст — описание прибора по справочнику, каноническая характеристика; было `category` — переименовано в схеме v4, словарная классификация перешла в секцию `fields` §2.5), `technology` (текст), `package` (текст), `packageMaterial` (текст), `colorMarking` (текст), `pinout` (текст), `esdSensitive` (bool), `militaryGrade` (bool), `radiationHardened` (bool), `spec` (текст), `notes` (text_list — заметки и наблюдения наполняющего, в отличие от `description`: список отдельных заметок, порядок значим), `yearFrom`/`yearTo` (int; правило `year_range`), `datasheetUrl` (текст). Применимость {транзистор, диод}: `structure` (текст). Применимость {конденсатор}: `polarized` (bool). Применимость {резистор}: `functionalChar` (enum `А|Б|В` — закон изменения сопротивления переменных резисторов; осмыслен только при `adjustment = variable` — регламент наполнения, межполевого правила нет), `sections` (int — число секций многосекционного переменного резистора; осмыслен при `adjustment = variable` — регламент), `shaftEnd` (enum `шлиц|лыска|гладкий|резьбовой` — вид конца вала переменного резистора, термины НТД; уровни записи/исполнения — §7: конструктивные признаки, различающиеся по исполнениям). Применимость {реле}: `relayType` (enum `electromagnetic|polarized|reed|solid_state|latching` — тип реле по принципу действия), `contactForm` (enum `1З|1Р|1П|2З|2Р|2П|3П|4П` — контактная группа по НТД: число контактов + функция `З`/`Р`/`П` — замыкающий/размыкающий/переключающий; международные формы A/B/C — синонимия, объединение в фильтрах вне первого релиза, по образцу ТКЕ §6.8).

Правила валидации значений: текст — непустой после trim (пустая строка — ошибка, null — «не задано»); text_list — массив непустых после trim строк без повторов (пустой массив — ошибка: убрать атрибут из секции — omission, не пустой список); bool — 0/1; enum — из списка; число — positivity по типу. Список полей секции `attributes` файла наполнения — из каталога (данными).

Атрибуты **двухуровневые** (§7): секция `attributes` записи задаёт признаки типа в целом, ключ `attributes` объекта исполнения — признаки конкретного исполнения (конструктивные различия вида «закон изменения сопротивления × вид конца вала × число секций» у переменных резисторов, контактная группа паспорта у реле). Один и тот же код допустим на обоих уровнях: значение записи — общее для типа, значение исполнения — своё; типовые исторические атрибуты (`yearFrom`/`yearTo`, `spec`) на исполнениях не задаются — регламент наполнения. Форма значений и валидация — единые для обоих уровней; именованные правила атрибутов (§11) применяются к атрибутам записи и каждого исполнения. Замена набора исполнений (секция `variants`) заменяет и их атрибуты; атрибуты записи при этом не затрагиваются — это отдельная секция со своей семантикой замены.

## 11. Именованные правила (код, привязка данными)

| Код | Семантика | Привязка |
|-----|-----------|----------|
| `year_range` | `yearFrom < yearTo`; диапазон 1949–2100 | атрибуты `yearFrom`/`yearTo` |
| `cap_dimensions_form` | согласованность формы корпуса: прямоугольный (`length`+`width`+`height`), осевой цилиндрический (`diameter`+`leadLength`) либо радиальный цилиндрический (`diameter`+`height`), смешение — ошибка | параметры группы `dimensional` |
| `temp_pair` | `TempMin < TempMax` / `opTempMin < opTempMax`, если заданы оба | обе пары: `TempMin`/`TempMax` (limiting, §6.2) и `opTempMin`/`opTempMax` (electrical, §6.8) |
| `cap_variant_matrix` | вариант электролитического конденсатора обязан иметь `Vnom` и `Cnom`; габариты — согласованным набором формы корпуса; уникальность `Vnom`/метки в пределах записи | класс `capacitor` (`kind_validation_rules`) |
| `resistor_variant_power` | вариант резистора обязан иметь `Pnom`; уникальность `Pnom`/метки в пределах записи | класс `resistor` (`kind_validation_rules`) |

Новый тип межполевого правила — реализация в реестре `internal/catalog` + строка в данных; правило с неизвестным кодом в данных каталога — ошибка импорта каталога. Привязка правил — к параметру/атрибуту (точечная) или к классу прибора (для правил записи в целом, включая вариантные матрицы).

## 12. Метасхема каталога (валидация определений при импорте)

- единица/условие/группа/правило существуют; классы применимости (`parameter_kinds`/`attribute_kinds`) существуют; пустой набор применимости = «все классы»;
- система обозначения существует и применима к классу (`designation_system_kinds`);
- `enum`-параметр имеет непустой список значений; `text`/`enum` не имеют единиц;
- числовые типы имеют границы по своему виду (`at_least` → min и т.п. — на уровне значений);
- каждый набор условий непуст — хотя бы один элемент (required или optional); наборы из одних optional допустимы (`DF` с опц. `temp`); у безусловного параметра наборов нет; `fixed_value` задан только у элементов с `mode = required`;
- коды параметров глобально уникальны; `value_ceiling` положителен; `sort_order` ≥ 0;
- коды условий не совпадают с зарезервированными ключами объекта значения формата наполнения (`parameter`, `value`, `min`, `max`, `text`), а имена секций групп — со служебными ключами записи (`name`, `system`, `fields`, `attributes`, `manufacturers`, `variants`, `analogs`), ключом `label` исполнения, ключом корня `catalog` и секциями классов корня (`<код класса>s`): такие определения невыразимы в файле наполнения, round-trip их искажает (единый реестр зарезервированных ключей — `internal/catalog/fillformat.go`).

Примеры записи наполнения — `06-examples.md`.
