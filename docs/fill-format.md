# Регламент наполнения

Полный справочник формата файлов наполнения справочника: поля, семантика
секций, единицы, типичные ошибки и их лечение. Примеры записей по классам —
`docs/plan/06-examples.md`; живые образцы — `data/` (выверенное наполнение).
Реестр действующих кодов параметров/атрибутов/условий —
`catalogctl catalog list --db <база>`; эталон формы секции `catalog` —
`catalogctl catalog export --db <база>`. Сводный справочник кодов по
классам (параметры, атрибуты, условия, семейства series) —
`docs/class-keys.md`.

## 1. Форматы и общие правила

| Формат | Расширения | Назначение |
|--------|-----------|-----------|
| jsonc | `.jsonc`, `.json` | ручное редактирование и ревью (комментарии `//`) |
| yaml | `.yaml`, `.yml` | ручное редактирование (якоря допустимы) |
| ndjson | `.ndjson` | машинный поток больших объёмов (10⁴–10⁵): одна JSON-строка — одна сущность |

Формат определяется по расширению (`catalogctl import <файл>`; «-» — stdin,
читается как jsonc). Общие правила всех форматов:

- дубликаты ключей объекта — ошибка разбора файла (тихая потеря данных
  недопустима); порядок ключей значим и сохраняется экспортом;
- числа записываются десятичной точкой; запятая в обозначении («1,5»)
  канонизируется в точку;
- комментарии и якоря — только в jsonc/yaml; NDJSON — без комментариев;
- жёсткая ошибка (прогон не выполняется) — только синтаксис формата;
  проблемы формы и значений накапливаются за один прогон (`Issues`), каждая
  плохая запись отвергается целиком, корректные применяются.

## 2. Корневая структура

```jsonc
{
  "catalog": { … },        // опционально: расширение каталога (§8)
  "transistors":  [ … ],   // секции классов: ключ = код класса + "s"
  "diodes":       [ … ],
  "resistors":    [ … ],
  "capacitors":   [ … ]
}
```

- допустимые ключи корня — `catalog` и секции известных классов; все секции
  опциональны, `null` — пропускается;
- порядок записей — порядок применения; обозначение-цель аналога может
  встретиться позже по файлу (взаимные ссылки допустимы);
- NDJSON: вместо корня — построчные обёртки `{"<класс>": <запись>}` и
  `{"catalog": {"<подраздел>": […]}}` (§9).

## 3. Запись

```jsonc
{
  "name": "КТ315Б",            // обязательный ключ: обозначение
  "system": "gost",            // код системы; по умолчанию — автодетект;
                               // обязателен для "other"
  "fields": { … },             // классификация: объект «код поля → код
                               //   словаря» (§5.1)
  "attributes": { … },         // объект «код атрибута → значение» (§5)
  "parameters":  [ … ],        // секции групп каталога (§4): parameters,
  "ratings":     [ … ],        //   ratings, dimensions — имена секций
  "dimensions":  [ … ],        //   из каталога (см. catalog list)
  "manufacturers": ["НИИПП"],  // список имён
  "variants": [ … ],           // исполнения (§6)
  "analogs": [ … ]             // исходящие ссылки-аналоги (§7)
}
```

Короткая форма — строка вместо объекта: `"КТ315Б"` (только обозначение).

- `name` — обозначение без хвостов заказа: `С2-33Н` верно, `С2-33Н-0.125` —
  ошибка разбора с подсказкой задать вариант (мощность — исполнением);
  напряжение/ёмкость электролитических конденсаторов — тоже исполнениями;
- поля грамматик систем (номер разработки, буквы, группа, семейство,
  признак, модификатор, вариант кристалла, переходы) в файле не задаются —
  их даёт разбор обозначения; классификационные словарные поля (материал,
  подкласс, подстройка, категория, сборка) задаются секцией `fields` и
  только для систем, которые не кодируют их обозначением (§5.1);
- обозначение — ключ записи в пределах класса: `КТ312` и `2Т312` — раздельные
  записи; канонизация — trim, верхний регистр, пробелы удаляются,
  типографские дефисы приводятся к `-`; смешение кириллицы и латиницы —
  ошибка;
- допустимые системы: `gost`, `ost`, `pro`, `jedec`, `jis`, `series`, `other`;
  для `other` обязателен `system` (и класс записи — секцией корня);
  записи `series` требуют известного семейства в реестре (`series_families`).

## 4. Значения параметров (секции групп)

Форма едина для всех групп (`parameters`, `ratings`, `dimensions`) — список
объектов; порядок списка — порядок значений на карточке:

```jsonc
{ "parameter": "h21e", "min": 50, "max": 350, "Uke": 10, "Ik": 1 }
```

| Ключ | Смысл |
|------|-------|
| `parameter` | обязательный код параметра каталога |
| `value` | точное значение (тип параметра `exact`) |
| `min`, `max` | границы (`range` — обе; `at_least` — `min`, `max` необязателен; `at_most` — `max`) |
| `text` | текстовое/enum-значение (типы `text`, `enum`) |
| прочие ключи | коды условий измерения (число): `Uke`, `Ik`, `temp`, `freq`, … |

- тип значения и допустимые условия — свойства параметра в каталоге
  (`catalog list`); форма значения обязана соответствовать типу: `exact`
  не допускает `min`/`max`/`text`, `text` — чисел, и наоборот;
- числа положительны, если у параметра не разрешены отрицательные
  (`allow_negative`); у параметра может быть потолок (`ceiling`);
- условия положительны, кроме условий с `allow_negative` (температуры);
  комбинация условий должна соответствовать одному из наборов условий
  параметра (`required` обязательны, `optional` допустимы, посторонние
  запрещены, `fixed_value` — константа, которую можно опустить);
- повтор значения того же параметра с теми же условиями — дубликат (ошибка);
- единицы — канонические (§10): кОм → Ом, мкФ/нФ → пФ, кГц/ГГц → МГц и т.д.

## 5. Атрибуты

Объект «код → значение»; тип значения — свойство атрибута каталога:

- `text` — непустая строка; `enum` — значение из списка каталога;
- `bool` — `true`/`false`; `int` — положительное целое (годы выпуска);
- `number` — положительное число;
- `null` — атрибут не задаётся.

## 5.1. Классификационные поля (`fields`)

```jsonc
{ "name": "MJE340", "system": "other",
  "fields": { "material": "si", "subclass": "bjt", "category": "high_voltage" } }
```

Объект «код поля → значение словаря» (`assembly` — число 0/1). Состав и
словари — `docs/class-keys.md` §1.1:

- `material` — ге/си-приборы (`gost`, `pro` дают разбором; для `jedec`,
  `jis`, `series`, `other` — этой секцией), коды: `ge`, `si`, …;
- `subclass` — функция перехода (`bjt`, `fet`, `zener`, `rectifier`, …);
  системы `gost`/`pro`/`jis` дают разбором, `jedec`/`series`/`other` — секцией;
- `adjustment` — подстройка номинала (`fixed`/`variable`/`preset`), только
  резисторы и конденсаторы; `gost`/`ost` дают разбором, прочие — секцией;
- `category` — применение/характеристика из словаря каталога
  (`general_purpose`, `power`, …), всем системам: обозначение её не кодирует;
- `assembly` — признак сборки 0/1 (транзисторы и диоды), кроме `gost`.

Правила:

- переопределение поля, которое парсер системы записи устанавливает сам, —
  ошибка (`поле определяется разбором обозначения системы …`);
- неприменимое к классу поле — ошибка (`adjustment` у транзистора);
- значения — только коды словарей (не локализованные названия); коды
  категорий — из каталога (`catalog list`), новые — секцией `catalog`;
- семантика секции — как у прочих: отсутствует/`null` — не менять, задана —
  заменить набор целиком, `{}` — очистить, ошибка в любом поле — запись
  не применяется вовсе.

## 6. Исполнения (варианты)

```jsonc
"variants": [
  { "label": "0.125 Вт",
    "ratings":     [ { "parameter": "Pnom", "value": 0.125 } ],
    "dimensions":  [ { "parameter": "massMax", "value": 0.15 } ] }
]
```

- исполнения допустимы только для классов с вариантной семантикой
  (конденсаторы — матрица «ёмкость × напряжение», резисторы — ряд
  мощностей); у транзисторов и диодов секция `variants` — ошибка;
- вариант электролитического конденсатора обязан иметь `Unom` и `Cnom`,
  вариант резистора — `Pnom`; `Unom`/`Pnom` и метки уникальны в записи;
- габариты — согласованным набором формы корпуса: прямоугольная
  (`length`+`width`+`height`), осевая цилиндрическая (`diameter`+
  `leadLength`) либо радиальная цилиндрическая (`diameter`+`height`);
  смешение форм и неполный набор — ошибка;
- метка (`label`) — для карточки и фильтров («160 В», «0.125 Вт»);
  значения — та же форма, что в секциях записи.

## 7. Аналоги

```jsonc
"analogs": ["BC547B", { "name": "1N4007", "note": "с ограничениями" }]
```

- ссылки направленные: секция задаёт исходящие ссылки записи (встречные
  отображаются на карточке получателя, но не переносятся экспортом);
- цель — обозначание того же класса; разрешение ссылок — по файлу и базе
  (прямые ссылки на позднейшие записи файла допустимы, взаимные тоже);
- `note` — характер замены именно в этом направлении; самоссылки
  и дубликаты — ошибка.

## 8. Секция `catalog` (расширение каталога)

Подразделы (все опциональны, применяются upsert'ом по коду до записей):

| Подраздел | Строки | Ключевые поля |
|-----------|--------|---------------|
| `kinds` | классы | `code`, `name` |
| `designation_systems` | системы | `code`, `name`, `description` |
| `designation_system_kinds` | применимость систем | `system`, `kind` |
| `series_families` | реестр семейств | `series`, `kind`, `name`, `tail_semantic` ("" \| `power`) |
| `units` | единицы | `code`, `name`, `symbol` |
| `categories` | словарь категорий (поле `category`) | `code` |
| `conditions` | условия | `code`, `name`, `unit`, `allow_negative` |
| `parameter_groups` | группы | `code`, `section`, `name`, `sort_order` |
| `parameters` | параметры | `code`, `group`, `name`, `unit`, `value_type`, `kinds`, `enum_values`, `condition_sets`, `ceiling`, `allow_negative`, `rule`, `sort_order`, `is_active` |
| `attributes` | атрибуты | `code`, `name`, `group`, `type`, `unit`, `kinds`, `enum_values`, `rule`, `sort_order`, `is_active` |
| `validation_rules` | именованные правила | `code`, `description` — только коды реализаций реестра |
| `kind_validation_rules` | привязка правил к классам | `kind`, `rule` |

- ключи повторяют колонки каталожных таблиц (snake_case), ссылки — коды;
  `kinds` пуст/отсутствует — применимость ко всем классам;
- enum-значения, наборы условий и применимость замещаются целиком;
- удалений нет — только деактивация `"is_active": false`;
- целостность (ссылки, типы, наборы условий, инвариант реестра series)
  проверяется метасхемой: непустой список проблем — отказ целиком,
  записи файла читаются по прежнему каталогу;
- расширение каталога — данными, без правки кода; новое именованное правило
  требует реализации в коде (реестр мал по построению).

## 9. NDJSON

- одна строка — одна сущность: `{"<класс>": <запись>}` либо
  `{"catalog": {"<подраздел>": […]}}`; ровно один ключ на строку;
- строки `catalog` сливаются до валидации метасхемы и обязаны предшествовать
  записям, использующим вводимые определения;
- пустые строки пропускаются; конкатенация файлов и частичный догрузочный
  импорт допустимы (идемпотентность — §11).

## 10. Единицы

Хранилище и формат оперируют каноническими единицами:

| Величина | Каноническая | Даташитные — переводятся на входе |
|----------|--------------|-----------------------------------|
| сопротивление | Ом | кОм, МОм |
| ёмкость | пФ | мкФ, нФ |
| частота | МГц | кГц, ГГц |
| мощность (резисторы, конденсаторы) | Вт | — |
| мощность (транзисторы/диоды) | мВт | Вт |
| ТКС | 10⁻⁶/°C | — |
| ТКН | %/°C | — |
| безразмерные | без единицы | — |

Производные единицы отображения (мкФ, МОм, кГц) — только слой вывода.

## 11. Семантика применения и идемпотентность

Для секций `fields`, `attributes`, секций групп, `manufacturers`,
`variants`, `analogs`:

- отсутствует или `null` — не менять;
- задана — заменить целиком (включая очистку `[]`/`{}`);
- ошибка в любом значении секции — запись не применяется вовсе.

`fields` заменяет набор явных классификационных полей целиком (поля
грамматики парсера не затрагиваются — они производны обозначения);
`variants` заменяет набор исполнений целиком с их значениями;
`manufacturers` — список связей с чисткой производителей-сирот;
`analogs` — только исходящие ссылки. Повторный импорт того же файла —
исход «без изменений» по всем записям: записей в БД нет, ревизии данных
не инкрементируются. Экспорт пишет актуальные коды каталога и словарей,
секцию `fields` — только с явными полями записи, порядок массивов
сохраняется — round-trip идемпотентен.

## 12. Типичные ошибки

| Ситуация | Сообщение (дословно) | Лечение |
|----------|----------------------|---------|
| опечатка в ключе корня | `неизвестный ключ корня «transistor» (допустимы: …)` | ключ секции — код класса во множественном числе |
| нет обозначения | `обязательный ключ "name" — строка с обозначением` | добавить `name` |
| опечатка в поле записи | `неизвестное поле «rating» (допустимы: name, system, fields, attributes, manufacturers, variants, analogs и секции групп: …)` | имена секций — из `catalog list` |
| fields не объект | `секция fields — объект «код поля → значение»` | заменить массив/строку на объект |
| неклассификационное поле | `неизвестное поле классификации «power» (допустимы: material, subclass, adjustment, category, assembly)` | коды полей — §5.1; грамматика систем задаётся разбором |
| поле парсера системы | `поле «material» определяется разбором обозначения системы gost и явно не задаётся` | убрать поле из `fields` |
| поле чужого класса | `поле «adjustment» неприменимо к классу transistor` | применять к резисторам/конденсаторам |
| неизвестный код словаря | `неизвестный подкласс «…» (допустимы: bjt, fet, …)`; `неизвестная категория «…» (допустимы: …)` | код из словаря (`class-keys.md` §1.1) или расширить секцией `catalog` |
| значение не по типу | `значение поля классификации «material» — строка с кодом словаря`; `значение поля классификации assembly — число 0 либо 1` | строка-код либо число |
| хвост мощности в обозначении | `обозначение «…»: числовой хвост после букв — суффикс мощности, элемент полного обозначения; используйте обозначение «…» и секцию variants` | мощность — исполнением `variants` |
| неизвестная система | `неизвестная система обозначений «…» (допустимы: …)` | код из семи систем |
| дубликат ключа JSON | ошибка разбора файла (`файл не является корректным JSONC: …`) | переименовать ключ |
| параметр не из каталога | `неизвестный параметр «…»` | код из `catalog list` или расширить секцию `catalog` |
| параметр чужого класса | `параметр «…» неприменим к классу …` | параметр не для этого класса (допуск у транзистора) |
| параметр не в своей секции | `параметр «…» задан в секции «…», относится к секции «…»` | перенести в секцию группы параметра |
| форма не по типу | `тип значения exact — обязателен ключ value` (и аналогичные) | `value`/`min`+`max`/`text` по типу параметра |
| отрицательное значение | `значение ключа … должно быть положительным` | проверить знак и каноническую единицу |
| лишние условия | `комбинация условий не соответствует ни одному набору условий параметра` | условия — из наборов параметра (`catalog export`) |
| условия у безусловного | `безусловный параметр — условия недопустимы` | убрать условия |
| повтор значения | `дубликат значения с теми же условиями` | убрать дубликат или изменить условия |
| варианты не того класса | `класс … не поддерживает исполнения (варианты)` | убрать `variants` |
| вариант без Unom/Cnom/Pnom | `вариант …: отсутствует обязательный параметр …` | добавить обязательный параметр исполнения |
| смешение форм корпуса | `габариты: смешение форм корпуса — …` | один набор: прямоугольный/осевой/радиальный |
| аналог не существует | `аналог «…» не найден в классе …` | проверить обозначение/класс, добавить цель раньше или в этот же файл |
| самоссылка аналога | `запись «…» не может быть аналогом самой себя` | убрать |
| годы | `год вне диапазона 1949–2100`; `год начала должен быть меньше года окончания` | проверить yearFrom/yearTo |
| catalog после записей (NDJSON) | `блок catalog должен предшествовать записям` | переставить строки catalog в начало |
| строка-обёртка с двумя ключами | `строка-обёртка должна содержать ровно один ключ — класс либо catalog` | разделить на две строки |
| catalog import с записями | `файл содержит записи классов; catalog import применяется к файлам только с секцией catalog` | использовать `import` вместо `catalog import` |

## 13. Процедура наполнения

1. Инициализировать базу: `catalogctl init --db catalog.db`.
2. Сверить реестры: `catalogctl catalog list --db catalog.db`; недостающие
   определения добавить секцией `catalog` файла наполнения (или отдельным
   файлом + `catalogctl catalog import`).
3. Подготовить файл (jsonc/yaml для ручного, ndjson для конвейера);
   значения — в канонических единицах, прослеживаемые до ТУ/даташитов
   (регламент выверки — `docs/plan/08-data-verification.md`).
4. Контрольный прогон: `catalogctl import <файл> --dry-run --db catalog.db`
   — полный список проблем за один прогон, записи не меняются.
5. Импорт: `catalogctl import <файл> --db catalog.db`; повторный импорт
   того же файла — «без изменений» (идемпотентность).
6. Выборочная сверка: `catalogctl info <обозначение>`, `list`, `find`;
   выгрузка — `catalogctl export [--kind] [--format]`.
