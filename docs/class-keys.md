# Справочник ключей по классам приборов

Сводный перечень возможных ключей и подключей записи наполнения для каждого
класса приборов: системы обозначений, атрибуты, параметры по секциям
(`parameters` / `ratings` / `dimensions`), условия измерения, исполнения,
справочник кодов семейств для поля `series`. Отражает **стартовое наполнение
каталога** (сид
`seed/seed.go`, план `docs/plan/03-data-model.md`); каталог — данные (D1) и
может быть расширен секцией `catalog` — действующий реестр всегда смотрите
командой `catalogctl catalog list --db <база>`.

Форма файлов, семантика секций (замена целиком, идемпотентность), единицы
и типичные ошибки — `docs/fill-format.md`; живые примеры записей —
`docs/plan/06-examples.md` и `data/`.

## 1. Общие ключи записи (все классы)

Корень файла: `catalog` (опционально) + секции классов — `transistors`,
`diodes`, `resistors`, `capacitors`, `relays` (все опциональны). Запись — объект
(либо короткая форма — строка с обозначением):

| Ключ | Обязателен | Смысл |
|------|-----------|-------|
| `name` | да | обозначение без хвостов заказа (мощность/напряжение/ёмкость — исполнениями) |
| `system` | только для `other` | код системы; по умолчанию — автодетект |
| `fields` | нет | объект «код классификационного поля → код словаря» (§1.1) |
| `attributes` | нет | объект «код атрибута → значение» (§2) |
| `parameters` | нет | секция группы `electrical` — список значений (§3) |
| `ratings` | нет | секция группы `limiting`; у конденсаторов — только общие данные надёжности `operatingLife`/`shelfLife` (§7.2) |
| `dimensions` | нет | секция группы `dimensional` — список значений (§9) |
| `manufacturers` | нет | список имён производителей |
| `variants` | нет | исполнения (только резисторы и конденсаторы, §10) |
| `analogs` | нет | исходящие ссылки-аналоги: `"ИМЯ"` или `{ "name", "note" }` |
| `synonyms` | нет | исторические названия записи: `"ИМЯ"` или `{ "name", "note", "yearFrom", "yearTo" }` |

Системы обозначений по классам:

| Класс | Системы (`system`) |
|-------|--------------------|
| `transistor` | `gost`, `pro`, `jedec`, `jis`, `other` |
| `diode` | `gost`, `pro`, `jedec`, `jis`, `other` |
| `resistor` | `gost`, `ost`, `other` |
| `capacitor` | `gost`, `other` |
| `relay` | `other` |

Системы и их применимость к классам — данные каталога (подразделы
`designation_systems` и `designation_system_kinds` секции `catalog`, §14):
таблица — стартовое наполнение, действующий реестр — `catalogctl catalog list`.

Поля грамматик систем (номер разработки, буквы, группа, признак,
модификатор, вариант кристалла, переходы) в файле не задаются — их даёт
разбор обозначения. Классификационные словарные поля (материал, подкласс,
подстройка, категория) задаются секцией `fields` только для систем, которые
не кодируют их обозначением; записи `other` дополнительно задают поля
семейства — `series`, `dev_number`, `letters` (§1.1).

## 1.1. Классификационные поля (`fields`)

Секция `fields` — объект «код поля → значение словаря»: явная
классификация записи, сквозная между системами обозначений. Значения —
коды словарей (латиница, D9); отображаемые названия — локаль вывода
(REST/CLI принимают и код, и локализованное название фильтром).

| Поле | Тип | Классы | Кто задаёт разбором | Кому доступно в `fields` |
|------|-----|--------|---------------------|--------------------------|
| `material` | код словаря материалов | транзисторы, диоды | `gost`, `pro` | `jedec`, `jis`, `other` |
| `subclass` | код словаря подклассов | транзисторы, диоды | `gost`, `pro`, `jis` | `jedec`, `other` |
| `adjustment` | код словаря подстройки | резисторы, конденсаторы | `gost`, `ost` (резисторы), `gost` (конденсаторы) | `other` |
| `category` | код словаря `categories` (§14) | все классы | никто | все системы |
| `assembly` | число 0/1 | транзисторы, диоды | `gost` | `pro`, `jedec`, `jis`, `other` |
| `series` | код семейства — текст, верхний регистр (§12) | все классы | никто (система series удалена) | только `other` |
| `dev_number` | положительное целое | все классы | строгие системы — разбором | только `other` |
| `letters` | текст, верхний регистр | все классы | строгие системы — разбором | только `other` |
| `base` | базовое обозначение (тип) — текст | все классы | все системы (для `other` — вычисляется по `series`/`dev_number`) | никто — поле производное |

Поле `base` — тип записи: обозначение без буквы классификации и
хвостовых элементов (`КТ315Б` → `КТ315`, `BC547B` → `BC547`,
`С2-33Н` → `С2-33`; план `03-data-model.md` §2.6). Задаётся системой
автоматически, в секции `fields` запрещено; фильтр поиска `?base=` /
`--base` (значение канонизируется как обозначение), на карточке —
блок «группа типа»: соседние записи того же типа и различия их
параметров.

Правило: `fields` задаёт только те поля, которые парсер системы записи
не устанавливает сам (переопределение продуктов разбора — ошибка), и
только применимые к классу записи. Семантика секции — как у прочих:
отсутствует/`null` — не менять, задана — заменить набор целиком (пустой
объект `{}` — очистить), ошибка в любом поле — запись не применяется.

## 2. Атрибуты (`attributes`)

Объект «код → значение». Типы: `text` — непустая строка; `bool` —
`true`/`false`; `int` — положительное целое (годы, число секций);
`enum` — значение из списка. `null` — атрибут не задаётся. Состав
атрибутов и enum-списки (`functionalChar`: `А`, `Б`, `В`) — данные
каталога: стартовое наполнение ниже, расширяется подразделом
`attributes` секции `catalog` (§14); enum-значения при переопределении
замещаются целиком. Атрибуты двухуровневые: секция `attributes` записи
задаёт признаки типа в целом, ключ `attributes` объекта исполнения
(§10) — конструктивные признаки конкретного исполнения; форма значений
и реестр кодов — единые (план 03 §7/§10, D12).

## 3. Форма значения параметра (секции `parameters`, `ratings`, `dimensions`)

Список объектов; порядок списка — порядок значений на карточке:

```jsonc
{ "parameter": "hfe", "min": 50, "max": 350, "Vce": 10, "Ic": 1 }
```

| Подключ | Смысл |
|---------|-------|
| `parameter` | обязательный код параметра каталога |
| `value` | точное значение — для типа `exact` |
| `min`, `max` | границы: `range` — обе; `at_least` — `min` (`max` необязателен); `at_most` — `max` |
| `text` | значение для типов `text`/`enum` |
| прочие ключи | коды условий измерения (число): `Vce`, `Ic`, `temp`, `freq`, … (§11) |

Комбинация условий обязана совпадать с одним из наборов условий параметра
(колонка «Условия» в таблицах ниже): без пометки — обязательное условие,
«опц.» — необязательное, «фикс.» — константа, которую можно опустить.
Повтор параметра с теми же условиями — дубликат (ошибка); enum-параметры
многозначны — разные значения при одних условиях допустимы (`nominalRow`),
повтор того же значения — дубликат. Числа
положительны, кроме параметров с пометкой «отрицательные допустимы».
Единицы в колонках «Ед.» ниже — русские условные обозначения канонических
единиц (МГц = `MHz`, °C = `degC`); реестр кодов — `docs/fill-format.md` §10.
Составы параметров (§4–§7) — стартовое наполнение, расширяется подразделом
`parameters` секции `catalog` (§14).

мощность стока — `PdMax` (§4.2), не `PcMax`.

### 7.2. Общие предельные данные (справочно)

`TempMin`, `TempMax` (`temp_pair`, `TempMin` — отрицательные допустимы) —
применимость {транзистор, диод, резистор, реле}; `TempJunctionMax`, `Rth` —

соответствующего класса. Общие данные надёжности `operatingLife` ч,
`shelfLife` г. (at_least) — применимость «все классы», включая
конденсаторы (для них — единственная причина существования секции
`ratings`, §7.1); даташитные месяцы переводятся в годы до записи.

### 7.3. Значения enum `TCC`

- нормируемый (линейный), 10⁻⁶/°C: `П100`, `П120`, `П60`, `П33`, `МП0`,
  `М33`, `М47`, `М75`, `М150`, `М220`, `М330`, `М470`, `М750`, `М700`,
  `М1500`, `М1300`, `М2200`;
- ненормируемый (сегнетокерамика), %: `Н10`, `Н20`, `Н30`, `Н50`, `Н70`,
  `Н90`;
- международные коды EIA RS-198: класс 1 (линейный ТКЕ, 10⁻⁶/°C) — `C0G`,
  `NP0` (синонимичные написания — отдельные значения), `U2J`; класс 2
  (буква нижней границы диапазона + цифра верхней + буква предела
  изменения ёмкости) — `X5R`, `X6S`, `X7R`, `X7S`, `X8R`, `Y5V`, `Z5U`.

Варианты написания (`П100`/`П120`, `М750`/`М700`, `М1500`/`М1300`,
`C0G`/`NP0`) — отдельные допустимые значения; синонимия советских групп и
кодов EIA (`МП0` ≈ `C0G`/`NP0`, `М750` ≈ `U2J`) в фильтрах не объединяется
(вне первого релиза). Список целиком — `enum_values` параметра
(данные каталога): при переопределении `TCC` подразделом `parameters`
секции `catalog` замещается целиком.

### 8.3. Исполнения — паспорта (§10)

Исполнение советского реле — **паспорт** (децимальный номер, элемент заказа;
07 §13): под одним номером разработки до десятка исполнений, отличающихся
обмоткой, коммунируемой способностью и родом тока. Метка варианта — код
паспорта (`РС4.529.029-00`); у мировых серий — номинал катушки (`24 В`).
Правило `relay_variant_coil`: вариант обязан иметь `Rcoil` (диапазон допуска
сопротивления обмотки) и обмоточный номинал — `VcoilNom` (точный) либо
`Ipickup` (не более; токовые паспорта без номинального напряжения);
метка-паспорт уникальна, повтор `VcoilNom` допустим (исполнения на одно
напряжение различаются сопротивлением/контактами). Прочие параметры
(сопротивление контактов, времена, изоляция) — на уровне варианта, если
зависят от паспорта. Запись без вариантов допустима: обмотка не выверена —
`Rcoil` диапазоном на уровне типа.

|-----|----------|-----|-----|-----------|
| `Rcoil` | сопротивление обмотки | Ом | range | обязателен; допуск обмотки паспорта |
| `VcoilNom` | номинальное напряжение обмотки | В | exact | либо `Ipickup` |
| `Ipickup` | ток срабатывания | мА | at_most | токовые паспорта; либо `VcoilNom` |

## 13. Именованные правила валидации

| Код | Семантика | Привязка |
|-----|-----------|----------|
| `year_range` | `yearFrom < yearTo`; диапазон 1949–2100 | атрибуты `yearFrom`/`yearTo` |
| `cap_dimensions_form` | согласованность формы корпуса (§9) | параметры группы `dimensional` |
| `temp_pair` | `TempMin < TempMax` / `opTempMin < opTempMax`, если заданы оба | обе температурные пары |
| `cap_variant_matrix` | вариант конденсатора обязан иметь `Vnom`+`Cnom`; габариты — согласованным набором; уникальность `Vnom`/метки | класс `capacitor` |
| `resistor_variant_power` | вариант резистора обязан иметь `Pnom`; уникальность `Pnom`/метки | класс `resistor` |

Привязки правил — данные: к параметрам/атрибутам — поле `rule` их
определений, к классам — подраздел `kind_validation_rules` секции `catalog`
(§14); сами коды — только реализации реестра в коде, подраздел
`validation_rules` хранит описания.

## 14. Расширение каталога

Секция `catalog` файла наполнения расширяет словари каталога данными —
поверх стартового наполнения этого справочника (форма, семантика и
пример — `docs/fill-format.md` §8):

| Подраздел | Расширяет | Стартовое наполнение |
|-----------|-----------|----------------------|
| `kinds` | классы приборов | §1 |
| `designation_systems` | системы обозначений | §1 |
| `designation_system_kinds` | применимость систем к классам | §1 |
| `units` | единицы | `docs/fill-format.md` §10 |
| `categories` | словарь категорий — значения поля `category` (со схемы v4) | §1.1 |
| `conditions` | условия измерения | §11 |
| `parameter_groups` | группы параметров (секции значений) | §1, §3 |

| `attributes` | атрибуты | §2 |

## 15. Именование новых кодов (величина/квалификатор)

Правила образования кодов параметров и условий, вводимых подразделами
`conditions` и `parameters` секции `catalog` (§14); нормативная версия —
`docs/plan/03-data-model.md` §6.9. Отклонение — предмет ревью наполнения
(не ошибка валидации); код — ключ каталога, переименование несовместимо
с форматом.

Источник — международный символ величины (IEC/JEDEC,
советское U → V); символ не изобретается. Советские обозначения
(Uкэ.нас, h21э) в код не пишутся — терминология НТД живёт в ru-названии
параметра. Величина без международного символа (масса, температуры,
допуск, среда) — словесный код (таблица «Суффиксы и словесные коды»).
Структура — слева направо, слитно, латиница, без разделителей; цифровые
индексы допустимы:

```
<символ величины><выводы | свойство><режим><Pulse><Max | Min>
```

Примеры образования кодов:

| Международная запись | Код | Разбор по токенам |
|----------------------|-----|-------------------|
| `V_CE(sat)` | `VceSat` | `V`+`ce`+`Sat` |
| `R_DS(on)` | `RdsOn` | `R`+`ds`+`On` |
| `I_CBO` | `Icbo` | `I`+`cb`+`o` |
| `I_CER` | `Icer` | `I`+`ce`+`r` |
| `f_T` | `fT` | `f`+`T` |
| `t_rr` | `trr` | `t`+`rr` |
| `α_VZ` | `AlphaVz` | `Alpha`+`Vz` |
| `τ_c` | `Tauc` | `Tau`+`c` |
| `h_11` | `h11` | `h`+`11` |

Регистр токена кодирует его роль (норма для новых кодов):

| Токен | Регистр | Примеры |
|-------|---------|---------|
| символ величины | прописная — `V`, `I`, `C`, `R`, `P`, `G`; строчные `f`, `h`, `g`, `t` — величины, строчные в самой номенклатуре | `Vce`, `Ciss`, `fT`, `hfe`, `gfs`, `trr` |
| акроним величины без буквенного символа | все прописные | `NF`, `TCR`, `TCC`, `DF` |
| греческая буква | латинское имя с прописной (символом или квалификатором) | `Eta`, `Lambda`, `Tauc` |
| вывод / пара выводов | строчные | `ce`, `cb`, `eb`, `be`, `ds`, `gs`, `ss`; одиночные `b`, `c`, `d`, `e`, `g`, `p`, `f`, `r`, `v`, `z` |
| JEDEC-буква конфигурации третьего вывода | строчная | `o` (разомкнут): `Icbo`, `VceoMax`; `r` (через сопротивление): `Icer` |
| свойство-слово | однословное — строчные; составное (несколько слов) — camelCase: первый компонент строчными, последующие с прописной | `nom`, `diff`, `tot`, `out`, `th`, `fs`, `ins`, `conv`, `leak`, `ripple`, `noise`, `ratio`, `load`; составное: `coilNom` (`VcoilNom`) |
| режим / состояние | первая прописная | `Sat`, `Off`, `Th`, `On`, `Cutoff` |
| предельное значение | первая прописная | `Max`, `Min`, `Pulse` |

Суффиксы и словесные коды:

| Правило | Примеры |
|---------|---------|
| режим — после выводов/свойства | `VgsTh`, `VgsOff`, `RdsOn` |
| `Pulse` — перед `Max`/`Min`; импульсные пределы несут обязательное условие `pulse_duration` (§11) | `IcPulseMax`, `VrPulseMax` |
| словесный код — английское имя, camelCase, строчная первая; суффиксы пределов — как у символьных | `massMax`, `leadLength`, `nominalRow`, `opTempMin`, `freq` |
| единица не входит в код — задаётся полем `unit` (реестр — `docs/fill-format.md` §10) | `Vce` — `V`, `RdsOn` — `ohm` |

Исторические отклонения стартового сида — действующие коды, не образец
для новых:

| Отклонение сида | Норма для новых кодов |
|-----------------|-----------------------|
| `Pmax` — строчной суффикс предела | `Vmax`, `PcMax` |
| `Ton`/`Toff` — прописной символ времени | `trr` |
| `Tolerance`, `TempMin`, `TempMax`, `TempJunctionMax` — прописная первая словесного кода | `massMax`, `opTempMin` |
| `Esr` — смешанный регистр акронима | `NF`, `TCR`, `DF` |
| `pulse_duration` — подчёркивание в словесном коде | `leadPitch` |
