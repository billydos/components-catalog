# 05. План работ

Оценки относительные (S ≤ недели фокусной работы, M — 2–4, L — больше); главный множитель этапов 1 и 6 — предметная каталогизация и выверка по первоисточникам, не код. Правило гигиены: после каждого пакета — `go build ./... && go vet ./... && gofmt -l .` и `go test ./...`; тексты русских сообщений — контракт, закреплены тестами дословно.

Критерии готовности: скелет собирается, CI зелёный, коды ошибок зафиксированы.

## Этап 2 — Каталог-данные и движок валидации (M)

| Задача | Содержание |
|--------|-----------|
| 2.1 | Транспорт каталога (чтение определений), снимок `CatalogSnapshot`, кэш с проверкой `catalog_revision` на каждом запросе |

## Риски

| ID | Риск | Мера |
|----|------|------|
| R1 | Предметная неточность каталогов/реестров/грамматик (ГОСТ, PRO ELECTRON, JEDEC, JIS, серии) | выверка на этапе 6 до релиза; каталог — данные: правка без кода; примеры — golden-тестами |
| R2 | EAV-производительность фильтров при росте данных | индексы из `02-database.md`; ориентиры и прикидка в этапе 7; план Б — денормализация/материализованные представления без смены публичного API |
| R3 | Расхождение диалектов SQLite/PostgreSQL (типы, пулы, RETURNING) | один набор интеграционных тестов на обе СУБД; диалектная изоляция (все диалектозависимые вещи — в `Dialect`) |
| R4 | Без миграций при «длинной» жизни бэкэнда станет больно | защита `schema_version` (громкий отказ, без тихой порчи); пересоздание импортом; решение о миграциях отложено за пределы v0.1 |
| R5 | Гибкость каталога vs целостность данных (валидация по данным сложнее CHECK) | метасхема + движок валидации как единственная точка записи (сервисы); прямые записи в БД — вне контракта |
| R6 | Неоднозначность автодетекта класса/системы (слабые серии, пересечения форм систем) | ключ класса/системы в файлах наполнения, `--kind`/`--system` в CLI, отказ с перечнем поддерживаемых систем; кириллица/латиница разводит большинство форм |
| R7 | Объём именованных правил растёт (каждое — код) | правило добавляется только когда не выражается данными (условия/типы/enum); реестр правил мал по построению |
| R8 | Вариантная семантика (исполнения) усложняет запросы и импорт: фильтры — EXISTS в пределах варианта, матрицы — многострочные данные | единая точка семантики в сервисах; тесты на вариантные фильтры и атомарность секции `variants`; контроль производительности EXISTS в этапе 7 (индексы `parameter_values(variant_id)`, `device_variants(device_id)`) |
