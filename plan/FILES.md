# FILES.md — состав плана и назначение файлов

План будущего проекта `components-catalog` (справочник электронных компонентов — советская и мировая элементная база: транзисторы, диоды, резисторы, конденсаторы). План самодостаточен и не опирается на внешние репозитории. Порядок чтения соответствует нумерации.

| Файл | Смысл и назначение |
|------|--------------------|
| `README.md` | Входная точка плана: назначение проекта, зафиксированные архитектурные решения D1–D6 (каталог-данные, EAV, равноправие SQLite/PostgreSQL, библиотека+REST, без миграций, исполнения-варианты) с мотивацией; навигация по документам |
| `01-architecture.md` | Архитектура проекта: форма (Go-модуль: библиотека + REST + CLI), слои и пакеты с ответственностями, сквозные механизмы (конфигурация, логирование, метрики, конкурентность), зависимости |
| `02-database.md` | Архитектура БД: принципы (каталог-данные, EAV, переносимость, без миграций с защитой версией схемы), полный состав таблиц с колонками и ограничениями, индексы, диалекты SQLite/PostgreSQL, сидирование каталога, жизненный цикл записи (upsert/каскады/чистка сирот) |
| `03-data-model.md` | Модель данных: классы приборов и системы обозначений (ГОСТ/ОСТ, PRO ELECTRON, JEDEC, JIS, серии: грамматики, реестры семейств), канонические единицы, условия, группы параметров; стартовые каталоги параметров/атрибутов по каждому классу, включая массогабаритные данные и исполнения-варианты «номинал × напряжение → габариты/масса»; именованные правила валидации, метасхема каталога |
| `04-module-functionality.md` | Функционал модуля для встраивания в веб-бэкэнд: публичный Go API (фасад и сервисы), REST `/api/v1` с моделью ошибок и ETag, CLI, формат файлов наполнения, интеграция (кэширование, наблюдаемость, производительность, границы первого релиза) |
| `05-work-plan.md` | План работ: этапы 0–7 с задачами, артефактами и критериями готовности, зависимости этапов, риск-реестр R1–R8 |
| `06-examples.md` | Примеры записи наполнения: по каждому классу и каждой применимой системе обозначений (по три записи на систему) — форма секций групп параметров, ключ `system`, исполнения-варианты, аналоги; семантика секций при импорте |
| `FILES.md` | Этот файл: карта документов плана |

Документы связаны: решения `README.md` раскрываются архитектурой (`01`), та материализуется в схему (`02`) и наполняется предметными данными (`03`), поверх определяется функционал (`04`) и порядок исполнения (`05`); `06` — приложение с примерами записи наполнения к `03`/`04`.
