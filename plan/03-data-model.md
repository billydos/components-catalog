# 03. Модель данных: классы, системы обозначений, каталоги параметров и атрибутов

Документ фиксирует **стартовое наполнение** каталога (сиды `seed/`). Каталог — данные (D1): стартовые наборы расширяются без правки кода; перечисленное ниже — минимально достаточный справочник, а не потолок. Предметные перечни (подклассы, группы, таблицы букв и цифр систем обозначений, реестры семейств, примеры) помечены [R1] — сверяются по первоисточникам (ГОСТ 10862-64 с изм., ГОСТ 13453-68, ОСТ 11.074.009, справочники конденсаторов, публикации PRO ELECTRON, JEDEC, JIS/EIAJ, каталоги производителей) на этапе каталогизации; до этого считаются рабочими.

## 1. Классы приборов и системы обозначений

### 1.1. Классы (`kinds`)

| Код | Название | Системы обозначений (`system_code`) |
|-----|----------|-------------------------------------|
| `transistor` | транзисторы | `gost`, `pro`, `jedec`, `jis`, `series`, `other` |
| `diode` | диоды | `gost`, `pro`, `jedec`, `jis`, `series`, `other` |
| `resistor` | резисторы | `gost`, `ost`, `series`, `other` |
| `capacitor` | конденсаторы | `gost`, `series`, `other` |

Расширение (тиристоры/оптопары) — добавлением класса и парсера; схема и каталог данных не меняются.

### 1.2. Реестр систем обозначений (`designation_systems`)

- реестр систем и применимость к классам (`designation_system_kinds`) — **данные**; добавление системы классу — вставка строк (+ реализация парсера в коде, если система строго формальна);
- система обозначения — атрибут записи: колонка `devices.system_code` (фильтр, индекс); результат разбора — поля в `device_designation_fields`;
- бывшая система `legacy` расформирована: слабоструктурированные семейства (`МП39`, `МЛТ-0.5`, `КСО`) вошли в **`series`** (семейство — и есть «слабая система»), бессистемные имена — в **`other`**;
- парсеры по типам систем: строгие грамматики (`gost`, `ost`, `pro`, `jedec`, `jis`) — код; `series` — реестр семейств (данные `series_families`) + единая слабая грамматика хвоста (код); `other` — без разбора (только канонизация);
- поля разбора имеют **единые имена для одинаковой семантики** (`material`, `subclass`, `junctions`, `dev_number`, `letters`, `series`) — сквозные фильтры между системами (например, материал: `gost` и `pro`).

## 2. Обозначения по системам

### 2.1. Полупроводники (транзисторы, диоды)

Шесть применимых систем — колонка `system_code`:

- **`gost` (ГОСТ 10862-64):** `<материал><подкласс>[С]<признак><номер><буквы>[<модификация>][-<бескорп.>]`
  - материал: `Г/1` германий, `К/2` кремний, `А/3` арсенид галлия, `И/4` индий; **равнозначность только физическая** — `КТ312` и `2Т312` раздельные записи (подсказка `find` по паре символов материала — только для `gost`: у прочих систем пар символов материала нет);
  - подкласс: `Т` биполярный, `П` полевой (транзисторы); `Д` диоды выпрямительные/универсальные/импульсные, `С` стабилитроны, `В` варикапы, `А` СВЧ-диоды, `И` туннельные, `Г` генераторные, `Л` светодиоды, `Ц` столбы/блоки [R1] (диоды);
  - сборка `С`, признак 1–9, номер 01–999, буквы 1–2 заглавные русские, модификация 1–9, бескорпусное `-1..-6`;
  - поля разбора: `material` (текст), `subclass` (текст), `assembly` (num 0/1), `feature` (num), `dev_number` (num), `letters` (текст), `modification` (num, NULL), `chip` (num, NULL). Примеры: `КТ315Б`, `2Т914А-1`, `КДС111В`, `КС168А`, `АЛ307Б`.
- **`pro` (PRO ELECTRON, Европа):** `<материал><класс><номер><суффикс>` — две заглавные латинские буквы, серийный номер, опциональный суффикс.
  - первая буква — материал/базовая функция: `A` германий, `B` кремний, `C` арсенид галлия, `D`/`E`/`Q`/`R` — специальные классы (датчики, излучатели, туннельные и др.) [R1 — полный перечень];
  - вторая буква — класс прибора: `A` маломощный диод, `B` варикап, `C`/`D` маломощный/мощный НЧ транзистор, `F`/`L` маломощный/мощный ВЧ, `S`/`U` маломощный/мощный ключевой, `Y` мощный выпрямитель, `Z` стабилитрон [R1 — полный перечень];
  - номер: 3 цифры — общая регистрация, от 4 цифр — специализированные приборы [R1]; суффикс — группа (усиление/напряжение), версия корпуса;
  - поля: `material` (текст — германий/кремний/арсенид галлия, единый словарь с `gost` для сквозного фильтра), `subclass` (текст), `dev_number` (num), `letters` (текст, NULL). Примеры: `BC547B`, `AD161`, `BF245`, `BY133`, `BZX85C` [R1].
- **`jedec` (JEDEC, США):** `<переходы>N<номер регистрации>[<суффикс>]` — цифра числа p-n-переходов (`1` диоды, `2` биполярные и полевые транзисторы, `3` четырёхвыводные приборы [R1]), `N`, номер, опциональные буквы улучшенной версии.
  - материал и подкласс/категория в обозначении **не кодируются** — задаются атрибутами записи (`structure`, `category`); фильтры по полям обозначения — только номер и суффикс;
  - регистрация гарантирует взаимозаменяемость, а не идентичность: один номер выпускают многие производители — запись с несколькими производителями для `jedec` — норма (модель `device_manufacturers`);
  - поля: `junctions` (num), `dev_number` (num), `letters` (текст, NULL). Примеры: `1N4148`, `1N4007`, `2N2222A`, `2N3055`.
- **`jis` (JIS/EIAJ, Япония):** `<переходы>S<класс><номер>[<суффикс>]` — цифра (`1` диоды, `2` транзисторы), `S` — признак регистрации, заглавная латинская буква класса, номер, опциональный суффикс (группа hFE и т.п.).
  - класс: `A` p-n-p ВЧ, `B` p-n-p НЧ, `C` n-p-n ВЧ, `D` n-p-n НЧ, `J` p-канал ПТ, `K` n-канал ПТ, прочие — тиристоры, составные и др. [R1 — полный перечень]; старые диодные регистрации без буквы класса (`1S2076`) [R1 — форма];
  - поля: `junctions` (num), `subclass` (текст), `dev_number` (num), `letters` (текст, NULL). Примеры: `2SA1015`, `2SC1815`, `2SK1058`, `1S2076`.
- **`series` (слабые системы — сочетания букв/цифр):** семейство из реестра `series_families` (данные: код семейства, класс, семантика хвоста) + слабый хвост (число, буквы; для семейств с `tail_semantic = power` — мощность, Вт). Объединяет бывшие советские `legacy`-реестры и мировые дом-номера производителей:
  - транзисторы: `П13`, `П214`, `МП39`, `МП41А` + `OC44`, `OC71`, `ASZ15`, `TIP120`, `MPSA42` [R1 — полный реестр];
  - диоды: `Д2Б`, `Д7А`…`Д7Ж`, `Д104`, `Д226`, `Д242`, стабилитроны `Д808`…`Д814А`, точечные `ДГ-Ц8` [R1];
  - поля: `series` (текст), `dev_number` (num, NULL), `letters` (текст, NULL), `power` (num, NULL);
  - семейство определяет класс (автодетект по реестру); материал и категория прибора не кодируются — задаются атрибутами (`category`, `structure`); фильтры по материалу/подклассу к `series`-записям неприменимы (полей нет).
- **`other` (без строгой системы):** произвольное имя компонента; разбора нет — только канонизация (§2.4); класс задаётся явно (ключ класса файла наполнения / `--kind`); полей разбора нет, группировка — атрибутами. Примеры: единичные фирменные имена, MIL-обозначения вида `M39003/…` [R1 — политика отнесения].

### 2.2. Резисторы

- **`gost` (ГОСТ 13453):** `[С|СП|СН]<группа 1–6>-<номер разработки><буквы>` — `С2-33Н`, `СП3-19А`, `С5-16МВ`. Поля: `family` (`С`,`СП`,`СН`), `group` (num 1–6, материал/технология [R1]), `dev_number`, `letters` (буквы модификации).
- **`ost` (ОСТ 11.074.009):** обозначения отраслевой системы; грамматика, состав полей и примеры — [R1] (выверка по тексту ОСТ до реализации парсера; возможны пересечения с `gost` по форме — порядок попыток разбора фиксируется после выверки).
- **`series` (реестр семейств):** `МЛТ`, `ОМЛТ`, `МТ`, `МГТ`, `ВС`, `УЛИ`, `ПЭ`, `ПЭВ`, `СПО`, `ВК` + мировые семейства (`RC`, `RL`, `RD`, мил-ряды `RCR`/`RWR`/`RN` [R1]). Мощность через дефис у семейств с `tail_semantic = power`: `МЛТ-0.5`, `ПЭВ-10`. Поля: `series` (текст), `dev_number` (num, NULL), `letters` (текст, NULL), `power` (num, Вт, NULL). Реестр — данные, неизвестное семейство — ошибка разбора с перечнем поддерживаемых [R1].
- **`other`** — общие правила (§2.1).

### 2.3. Конденсаторы

- **`gost` (единая система, ГОСТ 13453 [R1 — атрибуцию номера стандарта подтвердить по первоисточнику]):** `<префикс><группа, 2 цифры>-<номер разработки><буква>`. Префикс — не только `К`: допустимы также `КС`, `КТ`, `КП` (полный перечень префиксов и их семантика — [R1]; вероятны пересечения с семействами вида `КТ-4` — разрешение по форме обозначения и реестру семейств). Примеры: `К10-17Б` (керамика), `К50-35` (алюминиевый электролитический), `К73-17` (лавсан), `К78-2` (полипропилен), `К42-19` (металлобумажный). Поля: `prefix` (`К`,`КС`,`КТ`,`КП`…), `group` (num, таблица групп диэлектрика [R1]), `dev_number`, `letters` (буква варианта конструкции/ТКЕ — часть обозначения, к исполнениям §7 отношения не имеет).
- **`series` (реестр семейств):** `КСО`, `МБМ`, `МБГЧ`, `МБГО`, `БМ-2`, `КМ-4/5/6`, `КТ-1…4`, `КЛС`, `СГМ`, `ЭМ`, `ЭТО-1/2` и др. + мировые семейства производителей [R1]. Поля: `series` (текст), `dev_number` (num, NULL), `letters` (текст, NULL). Реестр — данные [R1].
- **`other`** — общие правила (§2.1).

### 2.4. Общие правила обозначений

- нормализация на входе: trim, верхний регистр, типографские дефисы → `-`, удаление пробелов (переносится из действующего проекта, расширено); кириллица (`gost`) и латиница (`pro`, `jedec`, `jis`, `series`, `other`) не смешиваются в одном обозначении — смешение алфавитов диагностируется ошибкой с указанием позиции [решение закрепляется этапом 1];
- каноническая строка обозначения — точный ключ записи внутри класса; система — атрибут записи, не часть ключа;
- сообщения об ошибках разбора — по-позиционные, с «ожидалось/получено» (контракт, тесты дословные);
- автодетект класса и системы по обозначению; порядок попыток: полупроводник `gost` → `pro` → `jedec` → `jis` → резистор `gost`/`ost` → конденсатор `gost` → `series` (класс — из реестра семейств); `other` автодетекта не имеет — требует явного указания (ключ `system` в записи наполнения, `--kind`/`--system` в CLI); пересечения форм разводятся порядком попыток и алфавитом (кириллица/латиница), неоднозначность — явным ключом класса/системы.

## 3. Единицы (`units`, канонические; даташитные значения — в т.ч. мировые записи µF/nF, kΩ/MΩ — переводятся до записи)

`В`, `мВ`, `мА`, `мкА`, `А`, `Гц`?, `кГц`?, `МГц`, `ГГц`, `дБ`, `%`, `Вт`, `мВт`, `Ом`, `МОм`?, `пФ`, `мкФ`?, `пс`, `нс`, `мкс`, `°C`, `°C/Вт`, `10⁻⁶/°C`, `%/°C`, `г`, `мм`, `нм`, `мкд`, `раз` (безразмерное — unit NULL).

Решение (фиксируется на этапе 6): сопротивление — Ом (10⁶ Ом = 1 МОм, вывод инженерными суффиксами), ёмкость — пФ (вывод адаптивно пФ/нФ/мкФ), мощность — Вт у резисторов/предельных конденсаторов, мВт остаётся у транзисторов/диодов (преемственность справочника), ТКС — 10⁻⁶/°C, ТКН — %/°C.

## 4. Условия (`conditions`)

Стартовый набор (позитивные, кроме `temp`; расширяемо данными):

| Код | Название | Единица |
|-----|----------|---------|
| `Uke`, `Ukb`, `Ueb` | напряжения к-э / к-б / э-б | В |
| `Ik`, `Ie`, `Ib` | токи коллектора / эмиттера / базы | мА |
| `Uobr` | обратное напряжение (диоды) | В |
| `Upr` | прямое напряжение (диоды) | В |
| `Ipr` | прямой ток (диоды) | мА |
| `Ist` | ток стабилизации (стабилитроны) | мА |
| `Unom` | номинальное напряжение (условие тока утечки) | В |
| `Rg`, `Rbe` | сопротивление генератора / в цепи б-э | Ом |
| `Rn` | сопротивление нагрузки | Ом |
| `freq` | частота | МГц |
| `pulse_duration` | длительность импульса | мкс |
| `temp` | температура среды (может быть отрицательной) | °C |

Импульсные предельные значения связываются с длительностью не отдельным правилом, а **обязательным условием** `pulse_duration` у соответствующих параметров.

## 5. Группы параметров (`parameter_groups`)

| Код | Секция наполнения/REST | Отображение | Применение |
|-----|------------------------|-------------|-----------|
| `electrical` | `parameters` | «Электрические параметры» / для конденсаторов «Характеристики» | транзисторы, диоды, резисторы, конденсаторы |
| `limiting` | `ratings` | «Предельные эксплуатационные данные» | транзисторы, диоды, резисторы (не конденсаторы — по постановке) |
| `dimensional` | `dimensions` | «Массогабаритные данные» | все классы (масса; габариты — преимущественно конденсаторы) |

Группа задаёт: секцию файла наполнения, порядок на карточке, семантику замены (секция заменяется целиком по группе).

## 6. Каталог параметров (стартовые сиды)

Типы значений: `exact` (точное), `at_least` (min), `at_most` (max), `range` (min..max), `text`, `enum`. Колонка `allow_negative` (у температурных пределов) разрешает неположительные значения; по умолчанию значения и условия положительны.

### 6.1. Транзисторы — `electrical` (перенос из действующего каталога)

`h21e` (диапазон; Uke+Ik | Ukb+Ie), `h21b` (Ukb+Ie), `FGran` МГц (не менее; Uke+Ik | Ukb+Ie), `UGran` В (Iк|Iэ), `UkeNas` В (не более; Ik|Ie), `UbeNas` В (не более; Ik|Ie), `Ikbo`/`Iebo`/`Ikeo` мкА (не более; Ukb/Ueb/Uke), `Ikep` мкА (Uke+Rbe), `h11` Ом (Uke+Ik), `Ck`/`Ce` пФ (не более; Ukb/Ueb), `Tauk` пс (не более; Ukb+Ie), `Ton`/`Toff` нс (не более; Ik+Ib), `KShum` дБ (не более; Uke+Ik+freq, опц. Rg | Ukb+Ie+freq, опц. Rg), `PVyh` Вт (не менее; freq, опц. Uke+Ik), `KUr` дБ (не менее; freq, опц. Uke+Ik), `Kpd` % (не менее; freq, опц. Uke+Ik; потолок 100).

### 6.2. Транзисторы — `limiting`

`UkeMax`, `UkbMax`, `UbeMax`, `UkeoMax` В; `IkMax`, `IbMax` мА; `PkMax` мВт; `IkPulseMax` мА (обязательное условие `pulse_duration`), `PkPulseMax` мВт (то же); `TempMin`/`TempMax` °C (`allow_negative`); `TempJunctionMax` °C; `Rth` °C/Вт. Все — `exact`.

### 6.3. Диоды — `electrical`

`Upr` В (не более; Ipr), `Iobr` мкА (не более; Uobr, опц. temp), `Cn` пФ (не более; Uobr, опц. freq), `Cp` раз (не менее; Uobr), `trr` нс (не более; Ipr), `Ust` В (диапазон; Ist), `Rdiff` Ом (не более; Ist), `TkUst` %/°C (не более; Ist), `Kpr` дБ (не более; freq), `Iv` мкд (диапазон; Ipr), `Lambda` нм (диапазон). [R1]

### 6.4. Диоды — `limiting`

`UobrMax` В, `UobrImpMax` В (+`pulse_duration`), `IprMax` мА, `IprImpMax` мА (+`pulse_duration`), `Pmax` мВт, `TempMin`/`TempMax`/`TempJunctionMax` °C, `Rth` °C/Вт, `IstMin`/`IstMax` мА (стабилитроны). [R1]

### 6.5. Резисторы — `electrical`

`Rnom` Ом (диапазон — границы ряда номиналов типа), `Dop` % (не более), `TKS` 10⁻⁶/°C (не более), `Ush` мкВ/В (не более; unit NULL + пояснение в названии), `Riz` МОм→Ом (не менее). [R1]

### 6.6. Резисторы — `limiting`

`Pnom` Вт, `Umax` В, `UimpMax` В (+`pulse_duration`), `TempMin`/`TempMax` °C. Снижение мощности при нагреве — примечанием (`notes`), не данными.

### 6.7. Резисторы/прочее — `dimensional`

`massMax` г (все классы, `exact`), `length`/`width`/`height` мм, `diameter`/`leadLength` мм, `leadPitch` мм (`exact`; преимущественно конденсаторы; правило `cap_dimensions_form`).

### 6.8. Конденсаторы — `electrical` («характеристики»)

`Cnom` пФ (диапазон), `Dop` % (не более), `TKE` — **enum**: `Н90`, `Н30`, `Н10`, `М1500`, `М750`, `М470`, `М330`, `М150`, `М75`, `М47`, `М33`, `МП0`, `П100`, `П33` … [R1], `Unom` В (exact), `Tgd` % (не более; опц. temp), `Riz` Ом (не менее), `Iut` мкА (не более; Unom, опц. temp), `Esr` Ом (не более; freq = 0.1 МГц), `tempMin`/`tempMax` °C (exact, `allow_negative` — допустимый диапазон температур как характеристики, по постановке без секции ratings). [R1]

У электролитических конденсаторов `Unom` и `Cnom` — преимущественно **вариантные** параметры (зависят от исполнения типа, см. §7); у типа в целом остаются допуск, tg δ, ток утечки (нормируется на номинальное напряжение варианта).

## 7. Исполнения (варианты) номиналов

Зависимость массогабаритных данных от ёмкости и напряжения — норма для электролитических конденсаторов: у `К50-35` ёмкость 1 мкФ выпускается только на 160 В, а габариты и масса растут с произведением C×U; у резисторов габариты зависят от мощности (`С2-33`: 0.125–2 Вт). Плоский набор значений на запись этого не выражает, а заводить отдельную запись на каждое сочетание нельзя — напряжение в обозначение единой системы (`gost`) не входит, обозначение — точный ключ. Поэтому:

- **вариант (исполнение)** — строка `device_variants` (метка для карточки: «160 В», «0.125 Вт») + значения параметров с `variant_id`;
- `variant_id = NULL` — данные типа в целом: `TKE`, `Dop`, `Tgd`, `Riz`, полярность, ТУ, годы;
- у варианта — свои значения характеристик (`Unom` точное, `Cnom` как диапазон ряда на это напряжение) и **свои массогабаритные данные** (`diameter`+`leadLength` или `length`+`width`+`height`, `massMax`);
- карточка отображает варианты матрицей «номинал × напряжение → габариты/масса»;
- правила: `cap_variant_matrix` — вариант электролитического конденсатора обязан иметь `Unom` и `Cnom`, а при наличии габаритов — согласованный набор формы корпуса (привязка уровнем класса `capacitor`); `resistor_variant_power` — вариант резистора обязан иметь `Pnom` (привязка уровнем класса `resistor`) [R1];
- транзисторы/диоды — без вариантов (раздельность записей задаётся буквой классификации обозначения);
- отличие от условий измерения: условие — контекст, в котором нормировано значение (напряжение, ток, частота, температура), вариант — конструктивное исполнение типа со своим набором значений; одно другому не заменяет, смешение в данных каталога запрещено (условия задаются у параметра, вариантность — фактом значений).

## 8. Аналоги (прямые ссылки между записями)

Решение (`plan/README.md`, вопрос 5): аналоги — на основе **прямого указания**; автоматический подбор по характеристикам/атрибутам — вне модуля, задача бэкэнда-потребителя (модуль обеспечивает его параметрическим поиском и нормализованными полями/единицами).

- ссылка — между записями **одного класса** (межклассовые аналоги смысла не имеют); пары из разных систем обозначений — норма и главный случай (`КТ315` ↔ `BC547`);
- `device_analogs(device_id, analog_device_id, note NULL)`: одна строка на пару (нормализация направления — сервис), отображение на карточке в обе стороны; `note` — характер замены текстом («полный аналог», «с ограничениями»); enum-градаций в v1 нет — аналог есть редакторское утверждение, а не вывод из параметров;
- наполнение: секция `analogs` записи — список обозначений того же класса (опционально объекты с `note`), семантика замены целиком как у `manufacturers`; неизвестное обозначение — ошибка записи;
- валидация — только структурная: записи существуют, один класс, нет самоссылки и дубликата пары; сверка параметров аналогов не выполняется (иначе это автоподбор — вынесен за рамки модуля);
- карточка/REST: блок «аналоги» с системой и обозначением каждой ссылки; фильтр «имеет аналоги» — второй очередью.

## 9. Атрибуты (`attributes`, стартовые сиды)

Общие (kind NULL): `structure` (текст, транзисторы/диоды), `category` (текст — категория прибора для записей, у которых подкласс не кодируется обозначением (`series`, `other`, `jedec`): выпрямительный, стабилитрон, импульсный и т.п.), `technology` (текст), `package` (текст), `packageMaterial` (текст), `colorMarking` (текст), `pinout` (текст), `esdSensitive` (bool), `militaryGrade` (bool), `radiationHardened` (bool), `polarized` (bool, конденсаторы), `functionalChar` (enum `А|Б|В` — закон изменения сопротивления переменных резисторов), `tu` (текст), `notes` (текст), `yearFrom`/`yearTo` (int; правило `year_range`), `datasheetUrl` (текст).

Правила валидации значений: текст — непустой после trim (пустая строка — ошибка, null — «не задано»); bool — 0/1; enum — из списка; число — positivity по типу. Список полей секции `attributes` файла наполнения — из каталога (как `extraFields` сейчас, но данными).

## 10. Именованные правила (код, привязка данными)

| Код | Семантика | Привязка |
|-----|-----------|----------|
| `year_range` | `yearFrom < yearTo`; диапазон 1949–2100 | атрибуты `yearFrom`/`yearTo` |
| `cap_dimensions_form` | согласованность формы корпуса: прямоугольный (`length`+`width`+`height`) либо цилиндрический (`diameter`+`leadLength`), смешение — ошибка | параметры группы `dimensional` |
| `temp_pair` | `tempMin < tempMax`, если заданы оба | параметры `tempMin`/`tempMax` (`TempMin`/`TempMax`/`tempMin`/`tempMax`) |
| `cap_variant_matrix` | вариант электролитического конденсатора обязан иметь `Unom` и `Cnom`; габариты — согласованным набором формы корпуса | класс `capacitor` (`kind_validation_rules`) |
| `resistor_variant_power` | вариант резистора обязан иметь `Pnom` | класс `resistor` (`kind_validation_rules`) |

Новый тип межполевого правила — реализация в реестре `internal/catalog` + строка в данных; правило с неизвестным кодом в данных каталога — ошибка импорта каталога. Привязка правил — к параметру/атрибуту (точечная) или к классу прибора (для правил записи в целом, включая вариантные матрицы).

## 11. Метасхема каталога (валидация определений при импорте)

- единица/условие/группа/правило существуют; `kind` существует; `jsonc_key` уникален;
- система обозначения существует и применима к классу (`designation_system_kinds`); семейство записи `system = series` существует в реестре `series_families` для соответствующего класса;
- `enum`-параметр имеет непустой список значений; `text`/`enum` не имеют единиц;
- числовые типы имеют границы по своему виду (`at_least` → min и т.п. — на уровне значений);
- каждый набор условий непуст (`required` ≥ 1) либо у параметра нет наборов (безусловный);
- коды параметров глобально уникальны; `value_ceiling` положителен; `sort_order` ≥ 0.

## 12. Примеры записи наполнения (конденсаторы)

```jsonc
{
  "capacitors": [
    // Электролитический: данные типа в целом + матрица исполнений «ёмкость × напряжение»
    {
      "name": "К50-35",
      "attributes": { "polarized": true, "tu": "…", "yearFrom": 1980 },
      "parameters": [                       // тип в целом (variant_id NULL)
        { "parameter": "Dop", "max": 20 },
        { "parameter": "Tgd", "max": 0.15, "temp": 20 }
      ],
      "variants": [
        {
          "label": "160 В",
          "parameters": [                   // характеристики исполнения
            { "parameter": "Unom", "value": 160 },
            { "parameter": "Cnom", "min": 1, "max": 10 }   // 1 мкФ — только на 160 В
          ],
          "dimensions": { "diameter": 8, "leadLength": 12, "massMax": 1.5 }
        },
        {
          "label": "25 В",
          "parameters": [
            { "parameter": "Unom", "value": 25 },
            { "parameter": "Cnom", "min": 47, "max": 4700 }
          ],
          "dimensions": { "diameter": 10, "leadLength": 16, "massMax": 3 }
        }
      ]
    },

    // Керамический: варианты не нужны, габариты постоянны для типа
    {
      "name": "К10-17Б",
      "attributes": { "package": "монолитный", "tu": "ОЖ0.464.036ТУ", "yearFrom": 1980 },
      "parameters": [
        { "parameter": "Cnom", "min": 22, "max": 1000000 },
        { "parameter": "TKE", "text": "Н30" },
        { "parameter": "Unom", "value": 25 }
      ],
      "dimensions": { "massMax": 1, "length": 6, "width": 4, "height": 5 }
    }
  ]
}
```

Семантика секций — как в действующем проекте: отсутствует/`null` — не менять; задана — заменить целиком; `[]`/`{}` — очистить; ошибка в любом значении секции (включая любой вариант) — запись не применяется вовсе; `manufacturers` внутри `attributes` — `null` «не менять список». Секция `variants` заменяет набор исполнений целиком вместе с их значениями; секция `analogs` заменяет список аналогов целиком (как `manufacturers`). Ключ `system` необязателен (по умолчанию — автодетект) и обязателен для `other`.
