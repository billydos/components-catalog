# components-catalog

Локальный и встраиваемый справочник электронных компонентов — советская и мировая элементная база. Проект - модуль веб-бэкенда: **Go-библиотека с сервисным слоем**, встраиваемый версионируемый **REST API `/api/v1`** и консольная утилита **`catalogctl`**. Хранилища — SQLite и PostgreSQL, равноправные; всё на pure Go, без cgo. Лицензия — MIT.

## Возможности

- **Пять классов приборов**: транзисторы, диоды, резисторы, конденсаторы, реле.
- **Шесть систем обозначений**: ГОСТ, ОСТ, PRO ELECTRON, JEDEC, JIS и `other`. Строгие грамматики разбирает код (с автодетектом класса и системы); бессистемные имена (включая досистемные семейства МЛТ, ВС, КСО…) — `other` с классификацией секцией `fields`.
- **Каталожные данные**: электрические параметры с условиями измерения, предельные эксплуатационные данные, массогабаритные и описательные атрибуты. Состав каталога (параметры, атрибуты, условия, enum-значения) — данные в БД: расширяется файлами наполнения без правки кода и пересборки; движок валидации читает правила из БД.
- **Исполнения-варианты**: зависимости «номинал × напряжение → габариты» (К50-35) и ряды мощностей (С2-33Н) — внутри одной записи.
- **Направленные аналоги**: ссылки «чем заменить» с заметками; «B заменяет A» не означает обратного.
- **Поиск**: подстрока обозначения, сквозные между системами словарные фильтры (материал, подкласс, подстройка, категория), фильтры по полям обозначения, атрибутам и границам параметров, сортировка, пагинация.
- **Импорт/экспорт**: jsonc, yaml, ndjson; идемпотентный импорт и round-trip экспорт.
- **Локализация на краю**: база и формат наполнения хранят только коды; отображаемые строки — бандлы (en — канонический, ru — полный). REST — `Accept-Language`, CLI — `--lang`.
- **Простое хранилище**: схема создаётся целиком при открытии, миграций нет; рассинхрон кода и базы исключён версией схемы.

## Поддерживаемые приборы

| Класс | Код | Примеры из `data/` |
|-------|-----|--------------------|
| Транзисторы | `transistor` | КТ315Б, ГТ109Г, BC547B, 2N3055, 2SC1815, IRF540 |
| Диоды | `diode` | Д226, КС168А, 1N4148, BZX85C5V1, BAT54S, KBP206G |
| Резисторы | `resistor` | С2-33Н, МЛТ-0.5, СП3-19А, ПЭВ-10, CFR-25 |
| Конденсаторы | `capacitor` | К50-35, К10-17Б, КСО-2, GRM188R71H104KA93D, T491C476K016AT |
| Реле | `relay` | РЭС-9, РЭС-15, РЭС-34, РПС-32, МКУ-48-С, КДР-1, G5V-1, G2R-2 |

Системы обозначений: `gost`, `ost`, `pro`, `jedec`, `jis`, `other` (бессистемные имена — включая досистемные семейства МЛТ, ВС, КСО…; семейство/номер/буквы — явные поля `fields`, справочник семейств — `docs/class-keys.md` §12). Обозначение — точный ключ записи в пределах класса: `КТ315Б` и `2Т315Б` — разные записи.

## Быстрый старт (CLI)

```bash
go build ./cmd/catalogctl

catalogctl init --db catalog.db
for f in data/*.jsonc; do catalogctl import "$f" --db catalog.db; done

catalogctl list --kind transistor --q КТ3 --db catalog.db   # поиск по подстроке
catalogctl list --material si --subclass bjt --db catalog.db # словарные фильтры
catalogctl info КТ315Б --db catalog.db                       # карточка
catalogctl find 2Т315Б --db catalog.db                       # подсказка: КТ315Б
catalogctl export --format ndjson --db catalog.db            # round-trip экспорт
```

### Команды `catalogctl`

| Команда | Назначение |
|---------|------------|
| `init` | создать и инициализировать базу (сиды каталога) |
| `parse <обозначение>…` | разбор обозначений, автодетект класса и системы |
| `add <обозначение>…` | добавить записи-обозначения |
| `import <файл> [--dry-run]` | импорт файла наполнения (`-` — stdin) |
| `list [фильтры]` | список записей: `--kind --system --material --subclass --adjustment --category --q --limit --offset` и др. |
| `info <обозначение>` | карточка записи |
| `find <обозначение>` | точный поиск; подсказка равнозначного обозначения (ГОСТ) |
| `delete <обозначение>…` | каскадное удаление |
| `count [--kind]` | число записей |
| `export [--kind] [--format]` | экспорт записей (jsonc \| yaml \| ndjson) |
| `catalog export \| import \| list` | экспорт каталога, расширение, справочник параметров |
| `version` | версия сборки |
| `help [команда]` | справка; `help <команда>` — строка использования и опции команды |

Общие опции: `--dialect sqlite|postgres`, `--db <путь>` (по умолчанию `catalog.db`), `--dsn <строка>`, `--lang en|ru`, `--dry-run`. Полная справка — `catalogctl help`.

## Встраивание (Go API)

Публичный фасад — пакет `components` (план 01 §2.4): модуль не запускает серверов и не читает глобальных флагов и env — сайт создаёт `App` при старте и закрывает при завершении. Импортируется только `components`; пакеты `internal/` внешнему модулю недоступны, типы сервисного слоя открыты алиасами.

```go
import "github.com/billydos/components-catalog/components"

app, err := components.Open(ctx, components.Config{
	Dialect:       "sqlite", // "sqlite" | "postgres"
	DSN:           "catalog.db",
	EnsureCreated: true, // DDL + сиды каталога на пустую базу
})
if err != nil { … }
defer app.Close()

// сервисный слой: Devices / Designations / Catalog
page, err := app.Services.Devices.Search(ctx, components.SearchQuery{
	Kind:  components.KindTransistor,
	Query: "КТ3",
})

// импорт файла наполнения (jsonc/yaml/ndjson; формат — по расширению);
// опция WithProgress — колбэк прогресса больших файлов (NDJSON читается
// построчно, без загрузки целиком)
file, err := os.Open("fill.jsonc")
if err != nil { … }
defer file.Close()
rep, err := app.Importer.Import(ctx, file, "fill.jsonc", false,
	components.WithProgress(func(p components.Progress) { … }))

// ошибки — значения: машиночитаемый код + сообщение
if de, ok := components.AsError(err); ok { … de.Code … }
```

Готовый runnable-пример — [`examples/embed`](examples/embed/main.go): внешний модуль с `replace` на локальный путь; его сборка и запуск — фаза consumer QA-прогонщика (компилируемость у внешнего потребителя — часть контракта).

## REST API

`app.Handler()` возвращает обычный `http.Handler` REST `/api/v1` — монтируется в любой роутер сайта. Аутентификация, авторизация, rate limiting и CORS — на стороне сайта (запись монтируется только в защищённые маршруты).

```go
mux := http.NewServeMux()
mux.Handle("/api/v1/", app.Handler())
// опции REST — в components.Config:
// DisableSuggest: true — не монтировать GET /suggest
// Metrics:        myMetrics — хук счётчиков сайта
```

| Маршрут | Назначение |
|---------|------------|
| `GET /kinds` | классы приборов |
| `GET /catalog` | снимок каталога для построения форм (ETag по `catalog_revision`) |
| `GET /components` | поиск: подстрока `q`, фильтры `material` / `subclass` / `adjustment` / `category` (код или локализованное название), `attr.<код>`, `par.<код>.min/.max/.exact`, `sort`, `limit ≤ 200`, `offset` (ETag по `data_revision`) |
| `GET /components/{kind}/{designation}` | карточка записи |
| `GET /components/id/{id}` | карточка по стабильному id — для обозначений с `/` (MIL `M39003/…`) |
| `POST /components` | создание записи |
| `PUT /components/{kind}/{designation}` | upsert записи |
| `DELETE /components/{kind}/{designation}` | удаление |
| `GET /suggest` | автодополнение по префиксу |
| `GET /parse?designation=&system=&kind=` | разбор обозначения: автодетект либо явная система/класс + кандидаты строгих систем |
| `GET /changes?after=&limit=` | поток событий изменений (created/updated/deleted) для инкрементальной синхронизации индексов сайта |
| `GET /stats` | количества по классам, версия схемы, ревизии; `?kind=<код>` — фасетные агрегаты класса: min/max численных параметров (границы — как у фильтров поиска) и частоты текстовых/enum значений |
| `POST /import` | импорт файла наполнения; формат тела — обязательный заголовок `Content-Type` (`application/x-ndjson`, `application/json` — jsonc, `application/yaml`): NDJSON — потоково без потолка тела, jsonc/yaml — документ целиком с потолком 16 МиБ (превышение — 400 `invalid_import_file`); синхронный отчёт после EOF, проблемы — в отчёте; `?dry_run=true` — контрольный прогон без записи; жёсткая ошибка — только синтаксис формата и чтение потока (400) |

Ошибки — JSON `{"code", "message"}` со статусами 400/404/409/422/500. Отображаемые поля (`name`, `kind_name`, символы единиц, тексты ошибок) заполняются по `Accept-Language` (по умолчанию `en`); кодовые поля (`kind`, `system`, `unit`…) и коды ошибок от локали не зависят. Полный контракт — `api/openapi.yaml` (OpenAPI 3.1; совпадение с реализацией закреплено тестом).

## Наполнение

| Формат | Расширения | Назначение |
|--------|------------|------------|
| jsonc | `.jsonc`, `.json` | ручное редактирование и ревью (комментарии `//`) |
| yaml | `.yaml`, `.yml` | ручное редактирование |
| ndjson | `.ndjson` | машинный поток больших объёмов (10⁴–10⁵ записей) |

Семантика секций записи (`fields`, `attributes`, группы параметров, `manufacturers`, `variants`, `analogs`, `synonyms`): отсутствует — не менять, задана — заменить целиком, ошибка в любом значении — запись не применяется вовсе. Импорт идемпотентен: повторный прогон того же файла — «без изменений» по всем записям, без инкремента ревизий. Каталог расширяется секцией `catalog` того же файла — без правки кода.

Выверенное наполнение лежит в `data/` (все классы и системы обозначений, матрица исполнений К50-35, ряды мощностей резисторов, паспорта обмоток реле, направленные аналоги); источники по каждой записи — `docs/plan/08-data-verification.md`. Регламент наполнения — `docs/fill-format.md`, сводные ключи по классам — `docs/class-keys.md`.

## Сборка и проверка

```bash
go build ./... && go vet ./... && gofmt -l . && go test ./...
go run ./qa/runner     # кроссплатформенный QA: статика + сценарии CLI/REST, отчёт qa/reports/*.log
```

Прогонщик QA работает на Linux, macOS и Windows (SQLite всегда;
PostgreSQL — через `CATALOG_TEST_POSTGRES_DSN`; нагрузочная прикидка —
`-scale`/`CATALOG_QA_SCALE`). CI (`.github/workflows/ci.yml`) выполняет
его на Linux со службой PostgreSQL и прикидкой 10⁴ и на Windows.

## Производительность

Ориентиры: поиск с фильтрами ≤ 100 мс, карточка ≤ 20 мс на 10⁴–10⁵ записей. Подтверждено прикидкой на 10⁴ (SQLite, локально); известное превышение — фильтрованный поиск (EXISTS по EAV) на SQLite при 10⁵. Детали и план Б — `qa/reports/2026-10-02-stage7.md`.
