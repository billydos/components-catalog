# components-catalog

Локальный и встраиваемый справочник электронных компонентов — советская и мировая элементная база. Проект - модуль веб-бэкенда: **Go-библиотека с сервисным слоем**, встраиваемый версионируемый **REST API `/api/v1`** и консольная утилита **`catalogctl`**. Хранилища — SQLite и PostgreSQL, равноправные; всё на pure Go, без cgo. Лицензия — MIT.

## Возможности

- **Четыре класса приборов**: транзисторы, диоды, резисторы, конденсаторы.
- **Семь систем обозначений**: ГОСТ, ОСТ, PRO ELECTRON, JEDEC, JIS, серии и `other`. Строгие грамматики разбирает код (с автодетектом класса и системы), семейства серий — данные.
- **Каталожные данные**: электрические параметры с условиями измерения, предельные эксплуатационные данные, массогабаритные и описательные атрибуты. Состав каталога (параметры, атрибуты, условия, enum-значения) — данные в БД: расширяется файлами наполнения без правки кода и пересборки; движок валидации читает правила из БД.
- **Исполнения-варианты**: зависимости «номинал × напряжение → габариты» (К50-35) и ряды мощностей (С2-33Н) — внутри одной записи.
- **Направленные аналоги**: ссылки «чем заменить» с заметками; «B заменяет A» не означает обратного.
- **Поиск**: подстрока обозначения, сквозные между системами словарные фильтры (материал, подкласс, подстройка, категория), фильтры по полям обозначения, атрибутам и границам параметров, сортировка, пагинация.
- **Импорт/экспорт**: jsonc, yaml, ndjson; идемпотентный импорт и round-trip экспорт.
- **Локализация на краю**: база и формат наполнения хранят только коды; отображаемые строки — бандлы (en — канонический, ru — полный). REST — `Accept-Language`, CLI — `--lang`.
- **Простое хранилище**: схема создаётся целиком при открытии, миграций нет; рассинхрон кода и базы исключён версией схемы.

## Поддерживаемые приборы

| Класс | Код | Примеры из `data/` |
|-------|-----|--------------------|
| Транзисторы | `transistor` | КТ315Б, ГТ109Г, BC547B, 2N3055, 2SC1815, IRF540 |
| Диоды | `diode` | Д226, КС168А, 1N4148, BZX85C5V1, BAT54S, KBP206G |
| Резисторы | `resistor` | С2-33Н, МЛТ-0.5, СП3-19А, ПЭВ-10, CFR-25 |
| Конденсаторы | `capacitor` | К50-35, К10-17Б, КСО-2, GRM188R71H104KA93D, T491C476K016AT |

Системы обозначений: `gost`, `ost`, `pro`, `jedec`, `jis`, `series` (семейства из реестра данных: МЛТ, ВС, КСО…), `other` (ручная классификация). Обозначение — точный ключ записи в пределах класса: `КТ315Б` и `2Т315Б` — разные записи.

## Быстрый старт (CLI)

```bash
go build ./cmd/catalogctl

catalogctl init --db catalog.db
for f in data/*.jsonc; do catalogctl import "$f" --db catalog.db; done

catalogctl list --kind transistor --q КТ3 --db catalog.db   # поиск по подстроке
catalogctl list --material si --subclass bjt --db catalog.db # словарные фильтры
catalogctl info КТ315Б --db catalog.db                       # карточка
catalogctl find 2Т315Б --db catalog.db                       # подсказка: КТ315Б
catalogctl export --format ndjson --db catalog.db            # round-trip экспорт
```

### Команды `catalogctl`

| Команда | Назначение |
|---------|------------|
| `init` | создать и инициализировать базу (сиды каталога) |
| `parse <обозначение>…` | разбор обозначений, автодетект класса и системы |
| `add <обозначение>…` | добавить записи-обозначения |
| `import <файл> [--dry-run]` | импорт файла наполнения (`-` — stdin) |
| `list [фильтры]` | список записей: `--kind --system --material --subclass --adjustment --category --q --limit --offset` и др. |
| `info <обозначение>` | карточка записи |
| `find <обозначение>` | точный поиск; подсказка равнозначного обозначения (ГОСТ) |
| `delete <обозначение>…` | каскадное удаление |
| `count [--kind]` | число записей |
| `export [--kind] [--format]` | экспорт записей (jsonc \| yaml \| ndjson) |
| `catalog export \| import \| list` | экспорт каталога, расширение, справочник параметров |
| `help [команда]` | справка |

Общие опции: `--dialect sqlite|postgres`, `--db <путь>` (по умолчанию `catalog.db`), `--dsn <строка>`, `--lang en|ru`, `--dry-run`. Полная справка — `catalogctl help`.

## Встраивание (Go API)

Модуль не запускает серверов и не читает глобальных флагов и env: сайт создаёт `App` при старте и закрывает при завершении.

```go
app, err := service.Open(ctx, service.Config{
	Dialect:       "sqlite", // "sqlite" | "postgres"
	DSN:           "catalog.db",
	EnsureCreated: true, // DDL + сиды каталога на пустую базу
})
if err != nil { … }
defer app.Close()

app.Services() // Devices / Designations / Catalog
```

## REST API

`httpapi.New(app, cfg).Handler()` возвращает обычный `http.Handler` — монтируется в любой роутер сайта. Аутентификация, авторизация, rate limiting и CORS — на стороне сайта (запись монтируется только в защищённые маршруты).

```go
mux := http.NewServeMux()
mux.Handle("/api/v1/", httpapi.New(app, httpapi.Config{
	// Log:            slog.Default(), // nil — slog.Default()
	// DisableSuggest: true,           // не монтировать GET /suggest
	// Metrics:        myMetrics,      // хук счётчиков сайта
}).Handler())
```

| Маршрут | Назначение |
|---------|------------|
| `GET /kinds` | классы приборов |
| `GET /catalog` | снимок каталога для построения форм (ETag по `catalog_revision`) |
| `GET /components` | поиск: подстрока `q`, фильтры `material` / `subclass` / `adjustment` / `category` (код или локализованное название), `attr.<код>`, `par.<код>.min/.max/.exact`, `sort`, `limit ≤ 200`, `offset` (ETag по `data_revision`) |
| `GET /components/{kind}/{designation}` | карточка записи |
| `GET /components/id/{id}` | карточка по стабильному id — для обозначений с `/` (MIL `M39003/…`) |
| `POST /components` | создание записи |
| `PUT /components/{kind}/{designation}` | upsert записи |
| `DELETE /components/{kind}/{designation}` | удаление |
| `GET /suggest` | автодополнение по префиксу |
| `GET /stats` | количества по классам, версия схемы, ревизии |

Ошибки — JSON `{"code", "message", "details"}` со статусами 400/404/409/422/500. Отображаемые поля (`name`, `kind_name`, символы единиц, тексты ошибок) заполняются по `Accept-Language` (по умолчанию `en`); кодовые поля (`kind`, `system`, `unit`…) и коды ошибок от локали не зависят. Полный контракт — `api/openapi.yaml` (OpenAPI 3.1; совпадение с реализацией закреплено тестом).

## Наполнение

| Формат | Расширения | Назначение |
|--------|------------|------------|
| jsonc | `.jsonc`, `.json` | ручное редактирование и ревью (комментарии `//`) |
| yaml | `.yaml`, `.yml` | ручное редактирование |
| ndjson | `.ndjson` | машинный поток больших объёмов (10⁴–10⁵ записей) |

Семантика секций записи (`fields`, `attributes`, группы параметров, `manufacturers`, `variants`, `analogs`): отсутствует — не менять, задана — заменить целиком, ошибка в любом значении — запись не применяется вовсе. Импорт идемпотентен: повторный прогон того же файла — «без изменений» по всем записям, без инкремента ревизий. Каталог расширяется секцией `catalog` того же файла — без правки кода.

Выверенное наполнение лежит в `data/` (все классы и системы обозначений, матрица исполнений К50-35, ряды мощностей резисторов, направленные аналоги); источники по каждой записи — `docs/plan/08-data-verification.md`. Регламент наполнения — `docs/fill-format.md`, сводные ключи по классам — `docs/class-keys.md`.

## Производительность

Ориентиры: поиск с фильтрами ≤ 100 мс, карточка ≤ 20 мс на 10⁴–10⁵ записей. Подтверждено прикидкой на 10⁴ (SQLite, локально); известное превышение — фильтрованный поиск (EXISTS по EAV) на SQLite при 10⁵. Детали и план Б — `qa/reports/2026-10-02-stage7.md`.
