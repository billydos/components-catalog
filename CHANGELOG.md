# Changelog

## v0.0.5

Изменения с коммита `e619274` (2026-10-16) по коммит `d4f0dca` (2026-10-16).

### Добавлено

- REST: `GET /api/v1/parse` — разбор обозначений над REST для ввода на стороне сайта: автодетект либо явные `system`/`kind` (обязателен только `designation`); в ответе — класс, система, каноническое обозначение, поля разбора и кандидаты — все строгие системы, принявшие обозначение, в фиксированном порядке автодетекта (честная замена оценке уверенности). Коды семантики обозначений (`kind_ambiguous`, `kind_not_supported`, `power_suffix_not_supported`, `designation_mismatch`) в контексте запроса дают 400 — это вход пользователя, а не семантика хранимой записи.
- Лента изменений записей для инкрементальной синхронизации производных индексов сайта: каждое применённое изменение записи порождает событие created/updated/deleted с видом операции, классом, обозначением и стабильным `device_id`; событие пишет та же транзакция записи, что меняет данные и поднимает `data_revision` — событие не появляется без изменения и наоборот; исход `Skipped` событий не пишет, компенсационные удаления импортёра — обычные deleted; покрыты и записи мимо обёртки сайта (`catalogctl` в ту же базу).
  - `GET /api/v1/changes?after=&limit=` — страницы по монотонному id события (курсор — id последнего полученного события; ревизия курсором не является), в ответе также текущая `data_revision`. Изменения каталога вне ленты (`catalog_revision`, ETag `GET /catalog`); лента — не аудит: без акторов и состояний до/после; автоочистки нет — ретеншн ручным SQL, REST-пути чистки нет.
  - Схема БД выросла 8 → 9 (таблица `change_events`): базы v8 не открываются (`schema_version_mismatch`), каталог пересоздаётся реимпортом (D5).
- REST: повторяемый параметр `id` в `GET /api/v1/components` — до 200 положительных int64, множество пересекается с прочими фильтрами для составной выборки на стороне сайта без дублирования каталога. Первый намеренно повторяемый параметр запроса: дубликаты в наборе, неположительные и неразбираемые значения, наборы свыше 200 — 400. Без сортировки порядок выдачи следует порядку передачи id (переносимый `ORDER BY CASE` по общим именованным аргументам), с сортировкой — запрошенный порядок; отсутствующие или отфильтрованные id строку не дают; ETag поиска хеширует каждое значение id — порядок передачи часть представления.

### Документация и прочее

- feature-request: зафиксирована оценка заявок проекта-сайта (`feature-request/assessment.md`, features.log CC-1..CC-8) и обновлена после пересмотра сайтом: отозваны CC-3 (метаданные ключевых параметров), CC-4 (собственный полнотекстовый поиск) и CC-7 (события, дружественные вебхукам), CC-8 переопределён с расширяемости классов на фильтр поиска по набору id; CC-1 и CC-2 отмечены реализованными.
- План (`docs/plan/02-database.md` — таблица `change_events`, `docs/plan/04-module-functionality.md` — новые маршруты и параметры) и контракт `api/openapi.yaml` обновлены вслед за новыми возможностями; бандлы en/ru дополнены сообщениями новых ошибок.
- Добавлен `STYLEGUIDE.md` — правила стиля кода Go (форматирование, именование, комментарии, функции, ошибки, типы, тесты); архитектурные правила остаются в `AGENTS.md`.

## v0.0.4

Изменения с коммита `d228045` (2026-10-11) по коммит `90428eb` (2026-10-14).

### Несовместимые изменения

- Коды условий, параметров и атрибутов переведены с советских сокращений на международную даташитную номенклатуру IEC/JEDEC, `U`→`V`: условия `Uke`→`Vce`, `Usi`→`Vds`, `Uzi`→`Vgs`, `Unom`→`Vnom`, `Uobr`→`Vr`, `Ust`→`Vz`; электрические `h21e`→`hfe`, `FGran`→`fT`, `IcNach`→`Idss`, `S`→`gfs`, `Ck`→`Cobo`, `Kpd`→`Eta`; предельные `UkeoMax`→`VceoMax`, `PkMax`→`PcMax`, `PsiMax`→`PdMax`; словарные `TKS`→`TCR`, `TKE`→`TCC`, `Dop`→`Tolerance`, `Tgd`→`DF`, `KShum`→`NF`; атрибут `tu`→`spec`. Полная карта соответствия — сообщение коммита `d228045`.
  - Файлы наполнения и payload REST/CLI со старыми кодами отклоняются как неизвестные параметры/условия/атрибуты: файлы данных переводятся по карте соответствия (`data/` переведены атомарно вместе с кодом), база пересобирается реимпортом (D5).
  - Коды — данные (D1): схемы и логики это не касается; ru-отображение сохраняет терминологию НТД (`h21э`, ТКС), en-названия цитируют символы JEDEC (hFE).
- Версия схемы БД выросла 7 → 8 (производное поле `base`): базы v7 не открываются (`schema_version_mismatch`), каталог пересоздаётся реимпортом (D5).

### Добавлено

- Каталог: класс устройств `relay` (реле) — пятый класс, только в системе `other`: единой строгой грамматики обозначений нет (ГОСТ 16121 задаёт общие требования, а не типономиналы), ключ записи — базовое обозначение типа, классификация — секцией `fields`.
  - Seed: 15 параметров реле (обмотка, контакты, времена, изоляция, стойкость; коммутируемые токи — `A`), enum-атрибуты `relayType`/`contactForm`, единица `ms`; `Rins`, `TempMin`/`TempMax` распространены на реле.
- Валидация: правило `relay_variant_coil` — исполнения реле (паспорта) несут данные обмотки: обязательны `Rcoil` (диапазон допуска сопротивления обмотки) и обмоточный номинал — точный `VcoilNom` либо `Ipickup` для токовых паспортов без номинального напряжения; метки исполнений уникальны в записи, повтор `VcoilNom` допустим (паспорта различаются сопротивлением и материалом контактов). Тексты нарушений и описание правила — в обоих локалях.
- Тип записи: производное поле `base` — каноническое обозначение без классификационной буквы и хвостовых элементов (КТ315Б → КТ315, BC547B → BC547, С2-33Н → С2-33, 1SR154-400 → 1SR154); буква остаётся в ключе записи, тип — группировка поверх записей (транзисторы и диоды исполнений не имеют, записи одного типа — отдельные строки справочника).
  - Парсеры строгих систем строят `base` сами; записи системы `other` получают его из `series`/`dev_number` и перезаписывают на каждом upsert. В секции `fields` поле не задаётся (ошибка `svc_field_base_derived`), из экспорта исключено — round-trip не меняется.
  - Карточка `info` дополнена блоком «группа типа»: соседние записи того же вида и типа и мини-матрица различающихся значений уровня типа (КТ315Б/КТ315Г × `VceoMax` 20/35 `V`); поиск — фильтр `?base=`/`--base` (значение канонизируется как обозначение); `find` после подсказки по материалу предлагает соседа по типу (КТ315А → КТ315Б).

### Изменено

- Внутренняя перестройка: самописные хелперы заменены эквивалентами stdlib по всем слоям — экспорт с отступами через `json.Indent`, мультимножественное равенство на `slices.Sorted`, три канонизатора словарных кодов сведены в `codeByDisplay`, повсеместно идиомы `slices`/`maps`/`cmp`/`strings`. Поведение не изменилось: байты экспорта идентичны (дифференциальная проверка), отсортированные выводы и тексты ошибок сохранены; детали ошибки таймаута QA-прогонщика теперь называют ошибку контекста.

### Исправлено

- CI: в джобе `skip-check` пин `actions/checkout` восстановлен полным SHA — короткий 33-символьный хэш не разрешался GitHub'ом (ссылки действий разрешаются только полным SHA), воркфлоу не загружалось.

### Документация и прочее

- План: закреплены правила образования кодов параметров и условий из международных символов IEC/JEDEC (структура «величина/квалификатор», регистр токенов, порядок суффиксов, словесные коды величин без символа) — нормативно `docs/plan/03-data-model.md` §6.9, зеркало в `docs/class-keys.md`, указатель из `docs/fill-format.md`, сводка в AGENTS.md; составные свойства-слова — camelCase (`coilNom` в `VcoilNom`).
- План: из перечня предельных удалён фантомный `UkeMax` — код в каталоге никогда не существовал (след аудита переименования).
- Хвосты переименования кодов: MsgID `rule_variant_unom_*` → `rule_variant_vnom_*` (рендеримые тексты и коды ошибок не изменились — контракта REST/CLI это не касается), идентификаторы тестов и генератора нагрузки приведены к новым кодам, en-названия `hfe`/`hfb` цитируют hFE/hFB.
- data/: выверенный набор реле — 15 записей: РЭС-9/15/22/34/47/49/60, РПС-32/43/52, РКМ-1, МКУ-48-С, КДР-1 (транскрипции ТУ) и Omron G5V-1/G2R-2 (даташиты производителя); системы обозначений реле описаны в отчёте выверки R1, источники S19/S20 зарегистрированы в отчёте выверки данных, иллюстративные примеры реле заменены выверенными записями.
- data/: обмотки реле переведены в паспортные исполнения — РЭС-9 (20 паспортов), РЭС-15 (7), РЭС-22 (9; РЭС-22-04 не включена — неоднозначные колонки источника), РЭС-34 (5), РЭС-47 (4), новая запись РЭС-55 (18); у Omron G5V-1/G2R-2 номиналы катушки стали исполнениями; записи с невыверенными обмотками держат `Rcoil` диапазоном на уровне типа без исполнений. Процентные нормы срабатывания/отпускания, токи отпускания и таблицы стойкости по режимам не выражаются в типах значений каталога и опущены.
- Обновлены отчёты прогонов QA (`qa/reports`).

## v0.0.3

Изменения с v0.0.2 (коммит `8b0a3fa`, 2026-10-11) по коммит `d69da3d` (2026-10-11).

### Добавлено

- CLI: позиционный аргумент `all` субкоманды `catalog list` — печатает все найденные записи, перебирая страницы поиска в пределах сервисного потолка `limit`; контракт пагинации service/REST (`limit <= 200`) не изменился. `all` — единственный допустимый позиционный аргумент, взаимоисключим с `--limit`/`--offset` (явное `--offset 0` тоже отклоняется).
- Seed: покрытие полевых транзисторов — условия `Usi`/`Uzi` (с `allow_negative`)/`Isi`, единицы `nA` и `mA_per_V`, электрические параметры `IcNach`, `S`, `UziOts`, `UziPor`, `Izut`, `Czi`/`Czs`/`Csi`, `RsiOtk` и предельные `UziMax`, `PsiMax`, `IsiPulseMax`; названия и символы новых сущностей — в бандлах en/ru.

### Изменено

- Каталог параметров: стоковые величины полевых транзисторов получили собственные коды — `PkMax`/`PkPulseMax` стали коллекторными (только биполярные), новые `PsiMax`/`IsiPulseMax` несут стоковые величины, ранее пересекавшиеся по коду `PkMax`. В формате наполнения записям полевых транзисторов вместо `PkMax` требуется `PsiMax`; записи `data/transistors.jsonc` переведены.
- CLI: разбор аргументов переведён с `urfave/cli` на собственный код — реестр команд сам ведёт диспетчеризацию, проверку числа аргументов и поддерево `catalog`. Лексический контракт не изменился: `--` завершает флаги, одиночный `-` — позиционный аргумент (закреплено тестом); из зависимостей ушли `urfave/cli` и транзитивный `text/template`.

### Документация и прочее

- План: примеры записей по классам (`docs/plan/06-examples.md`) сокращены до 2–3 записей на систему и не более десяти на класс — примеры демонстрируют форму записи и различия систем обозначений, а не полноту типов.
- Skill `changelog`: закреплены формат секции версии (`TEMPLATE.md`) и правило диапазона — границы записи только два явных коммита, не `HEAD`.
- Документация (`docs/plan/*`, `docs/class-keys.md`, `docs/fill-format.md`, AGENTS.md) и бандлы en/ru обновлены вслед за расширением seed и изменениями CLI.
- Обновлены отчёты прогонов QA (`qa/reports`).

## v0.0.2

Изменения с v0.0.1 (коммит `fe9712c`, 2026-10-10) по коммиту `df4c746` (2026-10-11).

### Breaking changes

- Удалена система обозначений series и реестр `series_families` из всех слоёв: domain, storage, catalog, importer, REST/CLI, seed, i18n и документация.
  - Версия схемы БД выросла 5 → 7 (series + последующие правки); существующие базы пересоздаются.
  - Прежние series-обозначения стали системой `other`; автодетект для них больше не работает — требуется явный `--system other --kind`.
  - REST-каталог лишился `series_families`; перечисление систем — только `gost/ost/pro/jedec/jis/other`.
  - Поле обозначения `power` удалено как дубль параметра `Pnom`.
  - Формат наполнения: секция `fields` получила необязательные грамматические поля `series`/`dev_number`/`letters` для записей системы `other`; записи в `data/` конвертированы.

### Добавлено

- CLI: команда `version` — печатает версию сборки (в релизах инъектируется через `-ldflags -X`).
- CLI: карточки справки — `help <command>` показывает строку usage с полным набором флагов и опции с описаниями; `help catalog <sub>` — карточку субкоманды, `help catalog` — usage-строки всех субкоманд; общий help дополнен примерами и заметкой о позиции опций.

### Изменено

- CLI: разбор аргументов переведён с самописного парсера на `urfave/cli` v3 (дерево команд и диспетчеризация — библиотека); строгий лексинг флагов, каталог сообщений, локализованные ошибки и коды выхода сохранены байт-в-байт. Изменение поведения на границах: флаг перед субкомандой — теперь явная ошибка вместо тихой потери; отсутствующая/неизвестная субкоманда — специализированные сообщения.
- CLI: текст справки генерируется из реестра команд (раскладка колонок и перенос слов — по локали) вместо монолитного сообщения каталога.

### Исправлено

По итогам аудита CODEREVIEW-03 (находки высокого и среднего приоритета):

- Импорт NDJSON: строка-обёртка `{"catalog":…, "<класс>":…}` больше не обходит гейт смешанного файла `catalog import` (раньше запись молча терялась уже после применения каталога); невалидный JSON-хвост после значения строки — жёсткая ошибка формата.
- Storage: адресная чистка сирот-производителей вместо O(N²) анти-джойна на каждую замену секции (добавлен индекс `device_manufacturers(manufacturer_id)`, схема 6 → 7); COUNT и страница поиска — из одного запроса, без рассинхрона total; батч-чтения по списку id чанкуются; устранена самоблокировка `:memory:`/`MaxOpen=1`.
- Валидация: значения исполнений проходят проверку принадлежности секции; деактивация параметра не ломает инвариант «повторный импорт того же файла — Skipped»; выбор ошибки валидации детерминирован (без зависимости от порядка map).
- Разбор обозначений: корректный машиночитаемый код при явном несовместимом классе и неоднозначном «Ф»; позиции ошибок канонизации при внутренних пробелах; контроль ошибок `Atoi` и ведущих нулей/длины ГОСТ-номеров; убран тихий fallback с сырой кириллической буквой в `gostSubclassCode`.
- Слои и ошибки: `domain` больше не импортирует `internal/i18n` (выделено locale-нейтральное ядро рендера); ошибки открытия БД/DDL/сидирования переведены с сырых литералов на каталог сообщений.
- REST: в контракт DeviceRecord (`api/openapi.yaml`) добавлено описание секции `fields`.
- CI/релизы: actions закреплены по SHA вместо мутируемых тегов; маскировка DSN в выводе дочерних процессов QA; `golang.org/x/sys` зафиксирована в списке зависимостей AGENTS.md и плане.

### Документация и прочее

- План (`docs/plan/*`), `docs/fill-format.md`, `docs/class-keys.md` и README обновлены вслед за удалением series; отчёт CODEREVIEW-03 актуализирован (сняты находки C17/C40).
- Skill `git-commits` переведён на английский.
- Обновлены отчёты прогонов QA (`qa/reports`).
