## [Unreleased]

### Добавлено

- Международные коды ТКЕ в enum параметра `TKE` (EIA RS-198, выверка —
  `docs/plan/07-r1-verification.md` §6, источник S9): класс 1 — `C0G`,
  `NP0` (синонимичные написания — отдельные значения), `U2J`; класс 2 —
  `X5R`, `X6S`, `X7R`, `X7S`, `X8R`, `Y5V`, `Z5U`. Советские группы и
  варианты написания — без изменений; синонимия групп (`МП0` ≈ `C0G`/`NP0`,
  `М750` ≈ `U2J`) в фильтрах не объединяется (вне первого релиза).
  Наполнение `data/` дополнено: группы ТКЕ К10-17Б (многозначный enum),
  `X7R` у Murata MLCC.
- Параметр `nominalRow` — ряд номинальных значений (enum `E3`…`E192` по
  ГОСТ 28884-90 / МЭК 60063), применимость {резистор, конденсатор}:
  многозначный в записи (серия может выпускаться в нескольких рядах),
  связь с допуском — регламент наполнения; наполнение `data/` и примеры
  дополнены (МЛТ).
- Справочник ключей по классам приборов `docs/class-keys.md`: общие ключи
  записи, атрибуты, параметры по секциям с условиями измерения,
  массогабаритные наборы, исполнения, семейства series и именованные
  правила — сводка стартового наполнения каталога; `docs/fill-format.md`
  ссылается на него.
- `.gitattributes`: нормализация концов строк исходников и текстовых
  данных, базы и изображения — бинарные. `.gitignore` расширен: сборка,
  тесты, профилирование, SQLite-базы, логи, env, следы редакторов.

## [0.1.0] — 2026-10-02

Первый релиз: полный контур «импорт → хранение → поиск → карточка → REST»
для четырёх классов приборов (транзисторы, диоды, резисторы, конденсаторы)
на двух равноправных СУБД.

### Добавлено

- Домен обозначений: строгие грамматики ГОСТ 10862-64/ГОСТ Р 71055-2023
  (полупроводники, резисторы ГОСТ 3453-68, конденсаторы по ГОСТ Р
  57440-2017), ОСТ 11.074.009-78, PRO ELECTRON, JEDEC, JIS; система series
  по реестру семейств-данных; канонизация и автодетект класса/системы.
- Каталог-данные и движок валидации: параметры/атрибуты/условия/enum/
  наборы условий — строки БД, расширяются файлами наполнения без правки
  кода; применимость к классам многие-ко-многим; именованные правила
  (year_range, cap_dimensions_form, temp_pair, cap_variant_matrix,
  resistor_variant_power); метасхема импорта каталога; кэш снимка
  с проверкой catalog_revision.
- Хранилище: переносимое DML на database/sql, диалекты SQLite (modernc,
  pure Go; WAL, busy_timeout, пул чтения + одно соединение записи) и
  PostgreSQL (pgx stdlib); схема целиком через EnsureCreated, защита
  версией схемы (schema_version_mismatch / database_not_initialized),
  миграций нет; устройства (upsert с семантикой секций, исходы
  Added/UpdatedExisting/Skipped), поиск (подстрока, фильтры
  полей/атрибутов/параметров с вариантной семантикой EXISTS, сортировка,
  пагинация), исполнения-варианты, направленные аналоги с встречными
  ссылками, производители с чисткой сирот; счётчики ревизий для ETag.
- Импорт/экспорт: форматы jsonc/yaml/ndjson (упорядоченное дерево,
  дубликаты ключей — ошибка разбора), Issues-модель прогона,
  многопроходное разрешение аналогов (взаимные ссылки), round-trip
  экспорт всех форматов, включая каталог.
- CLI `catalogctl`: init, parse, add, import (--dry-run), list, info,
  find (подсказка равнозначных по материалу), delete, count, export,
  catalog export|import|list; префиксы «Ошибка: »/«Непредвиденная
  ошибка: », коды выхода.
- REST `/api/v1`: kinds, catalog, components CRUD+search (варианты и
  аналоги в карточке), suggest (отключаемый конфигурацией), stats;
  модель ошибок {code, message, details}, ETag/304, пагинация;
  OpenAPI 3.1 спецификация api/openapi.yaml, совпадение закреплено
  тестом.
- Сиды каталога и выверенное наполнение `data/` (57 записей, источники —
  docs/plan/08-data-verification.md), sample-data по классам, включая NDJSON.
- QA этапа 7: сквозные сценарии CLI+REST на обеих СУБД (qa/scenarios.sh),
  нагрузочная прикидка против ориентиров (qa/load_test.go), отчёты
  qa/reports; регламент наполнения docs/fill-format.md; ревью архитектуры
  qa/architecture-review.md.

### Ограничения первого релиза

- Аутентификация/авторизация, автоподбор аналогов по характеристикам,
  полнотекстовый поиск по атрибутам, история правок, миграции схемы —
  вне релиза (план 04 §6).
- Фильтрованный поиск (EXISTS по EAV) на SQLite при 10⁵ записей превышает
  ориентир 100 мс (0.2–1.2 с): материал плана Б риска R2 —
  qa/reports/2026-10-02-stage7.md.
