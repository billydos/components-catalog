# AGENTS.md — правила разработки

Проект **components-catalog** — справочник электронных компонентов (советская и мировая элементная база): Go-библиотека + встраиваемый REST API `/api/v1` + CLI `catalogctl`. Хранилища: SQLite и PostgreSQL, равноправные. Источник истины по архитектуре и контрактам — план `docs/plan/`: `README.md` (решения D1–D8), `01-architecture.md`, `02-database.md`, `03-data-model.md`, `04-module-functionality.md`, `06-examples.md`; порядок работ — `05-work-plan.md`. Код не расходится с планом; осознанное изменение решения — отдельный коммит с правкой всех связанных мест плана.

## Проверка

После каждого пакета и перед коммитом:

```
go build ./... && go vet ./... && gofmt -l . && go test ./...
```

`gofmt -l .` обязан быть пуст. CI (`.github/workflows/ci.yml`) выполняет то же самое.

## Слои и зависимости

- `internal/domain` — обозначения, единицы, классы, ошибки; не знает БД и форматов.
- `internal/storage` — переносимый DML на `database/sql` + диалекты sqlite/postgres; без бизнес-правил.
- `internal/catalog` — чтение каталожных таблиц, движок валидации по правилам из БД.
- `internal/service` — публичный сервисный слой: единственная точка входа для CLI, REST и встраивания.
- `internal/importer` — реестр форматов наполнения (jsonc/yaml/ndjson), семантика секций, тексты ошибок формата.
- `internal/httpapi`, `internal/cli` — тонкие транспорты над `service`: разбор запросов/аргументов и вывод, без бизнес-логики.

Направление зависимостей: `domain` ← `catalog`/`storage` ← `service` ← `importer`/`httpapi`/`cli`. Не пропускать слои: SQL не поднимается выше `storage`, разбор форматов не выходит из `importer`, бизнес-правила не живут в транспортах.

## Ошибки

- Ошибки — значения: `*domain.Error{Code, Message}` из `internal/domain`; без паник и магических строк в слоях выше.
- Код ошибки — машиночитаемая латиница snake_case; реестр — константы `domain.Code…`; дублирование строк кодов по месту использования запрещено.
- Русские тексты сообщений — дословный контракт, закреплены тестами дословно (`internal/domain/errors_test.go`); переформулировка текста — несовместимое изменение.
- CLI: ожидаемые ошибки (`*domain.Error`) выводятся с префиксом `Ошибка: `, прочие — `Непредвиденная ошибка: `; код выхода 1 (константы и вывод — `internal/cli`).
- REST: модель `{"code", "message", "details"}`, статусы 400/404/409/422/500 — по `04-module-functionality.md` §2.

## Семантика секций (upsert и импорт)

Для секций записи наполнения (`attributes`, секции групп параметров, `manufacturers`, `variants`, `analogs`):

- отсутствует или `null` — не менять;
- задана — заменить целиком;
- `[]`/`{}` — очистить;
- ошибка в любом значении секции — запись не применяется вовсе; частичное применение запрещено.

`variants` заменяет набор исполнений целиком вместе с их значениями; `manufacturers` — замена списка связей + чистка сирот-производителей; `analogs` — замена только исходящих ссылок (встречные ссылки других записей не затрагиваются, решение D8). Повторный импорт того же файла — исход `Skipped` по всем записям: без записи в БД и без инкремента ревизий.

## Именование кодов и ключей

- Коды ошибок — латиница snake_case (`invalid_designation`).
- Коды параметров/атрибутов/условий/единиц/групп/систем обозначений — стабильные ключи каталога и формата наполнения (совпадают с ключами JSON); переименование кода каталога — несовместимое изменение формата, экспорт всегда пишет актуальные коды.
- Таблицы и колонки БД — snake_case, имена — по `02-database.md`.
- Идентификаторы Go — MixedCaps; имена файлов — snake_case.

## Единицы

- Канонический справочник единиц — данные (таблица `units`). Фиксированные канонические единицы: сопротивление — Ом, ёмкость — пФ, частота — МГц, мощность — Вт (резисторы, предельные данные конденсаторов) и мВт (транзисторы/диоды), ТКС — 10⁻⁶/°C, ТКН — %/°C; безразмерные величины — unit NULL.
- Даташитные единицы (кОм, МОм, мкФ, нФ, кГц, ГГц) переводятся в канонические до записи; производные единицы отображения (мкФ, МОм, кГц) форматирует только слой вывода — в хранилище их нет.

## Переносимость DML

- Только `database/sql` + `sql.Named` (`@имя`). Переносимые конструкции: `LIMIT/OFFSET`, производные таблицы, `INSERT … SELECT`, `EXISTS`.
- Булевы значения — INTEGER 0/1; NULL — «не задано»; без JSON-функций СУБД и диалектных типов.
- Всё диалектозависимое (DDL и PK, получение id после вставки, открытие и пулы соединений) — только в `Dialect` (sqlite/postgres) внутри `internal/storage`.
- Весь DML — только в явных транзакциях записи (SQLite: одно выделенное соединение записи, WAL, busy_timeout); вне транзакций — только SELECT из пула чтения.
- Один и тот же набор интеграционных тестов обязан проходить на SQLite и PostgreSQL.

## Схема: без миграций

- Схема создаётся целиком `EnsureCreated` (`CREATE … IF NOT EXISTS`); миграций нет (решение D5).
- Защита от рассинхронизации — `schema_meta.schema_version`: несовпадение с константой модуля — `*domain.Error` `schema_version_mismatch` с отказом в работе; отсутствие `schema_meta` — `database_not_initialized`. Тексты обоих сообщений — дословный контракт.
- Любое изменение DDL — с инкрементом константы версии схемы. Эволюция каталога (новые параметры, условия, семейства) — данными, без правки кода и без смены версии схемы.

## Зависимости

- База — stdlib. Внешние: `modernc.org/sqlite`, `jackc/pgx/v5`, `tailscale/hujson`, `goccy/go-yaml`.
- Новая зависимость допустима, если: pure Go без cgo, минимум транзитивных, живое сопровождение, заменяет самописный разбор или существенно сокращает код. Граница библиотеки — лексика/синтаксис формата; семантика секций, порядок ключей и русские тексты ошибок — только в `internal/importer`.
