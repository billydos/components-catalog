# AGENTS.md — правила разработки

Проект **components-catalog** — справочник электронных компонентов (советская и мировая элементная база): Go-библиотека + встраиваемый REST API `/api/v1` + CLI `catalogctl`. Хранилища: SQLite и PostgreSQL, равноправные. Источник истины по архитектуре и контрактам — план `docs/plan/`: `README.md` (решения D1–D10), `01-architecture.md`, `02-database.md`, `03-data-model.md`, `04-module-functionality.md`, `06-examples.md`, отчёты выверки `07-r1-verification.md` и `08-data-verification.md`; порядок работ — `05-work-plan.md`, карта документов — таблица в конце `README.md`. Пользовательские справочники: `docs/fill-format.md` (регламент наполнения), `docs/class-keys.md` (ключи по классам), контракт REST — `api/openapi.yaml`; выверенное наполнение — `data/`. Код не расходится с планом; осознанное изменение решения — отдельный коммит с правкой всех связанных мест плана.

## Проверка

После каждого пакета и перед коммитом:

```
go build ./... && go vet ./... && gofmt -l . && go test ./...
```

`gofmt -l .` обязан быть пуст. CI (`.github/workflows/ci.yml`) прогоняет кроссплатформенный QA-прогонщик `go run ./qa/runner` тремя джобами: linux на SQLite, linux со службой PostgreSQL и windows на SQLite — каждая с нагрузочной прикидкой `CATALOG_QA_SCALE=10000`; отчёт прогона — структурный лог `qa/reports/*.log` (формат `qa-log/1`). Локальный прогон интеграционных тестов на PostgreSQL — задать `CATALOG_TEST_POSTGRES_DSN` (без переменной нога пропускается; `go test ./...` — с `-p 1`: одноразовая база одна на все пакеты, параллельные пакеты конфликтуют на DROP/CREATE таблиц; прогонщик `qa/runner` добавляет флаг сам).

## Слои и зависимости

- `internal/domain` — обозначения, единицы (коды), классы, ошибки; не знает БД и форматов.
- `internal/storage` — переносимый DML на `database/sql` + диалекты sqlite/postgres; без бизнес-правил.
- `internal/catalog` — чтение каталожных таблиц, движок валидации по правилам из БД.
- `internal/service` — публичный сервисный слой: единственная точка входа для CLI, REST и встраивания.
- `internal/importer` — реестр форматов наполнения (jsonc/yaml/ndjson), семантика секций; тексты ошибок формата — каталог сообщений.
- `internal/i18n` — бандлы отображаемых строк (en — канонический и обязательный, ru), переговоры локали; потребители — только транспорты (`httpapi`, `cli`) и тесты полноты.
- `internal/httpapi`, `internal/cli` — тонкие транспорты над `service`: разбор запросов/аргументов и вывод, без бизнес-логики.
- `internal/testutil` — общий код интеграционных тестов: доступ к локальному PostgreSQL (`CATALOG_TEST_POSTGRES_DSN`) и очистка одноразовой базы; только из `_test.go`.

Корневые пакеты: `seed` — стартовый каталог (единицы, условия, группы, параметры, атрибуты, правила, реестры `domain`); применяется `service` на пустую базу при открытии, состав закреплён пин-тестами `seed/seed_test.go` против реестров `internal/domain` и `internal/catalog`. `qa` — кроссплатформенный прогонщик QA `qa/runner` (Go, без sh/bat: сборка, статика, сценарии CLI/REST на SQLite/PostgreSQL, структурный отчёт `qa-log/1`), нагрузочная прикидка (`load_test.go`), отчёты прогонов — `qa/reports/`.

Направление зависимостей: `domain` ← `catalog`/`storage` ← `service` ← `importer`/`httpapi`/`cli`; `seed` — над `domain`/`catalog`, потребитель — `service`; `i18n` — отдельно от внутренних слоёв (зависит только от кодов-строк), локали не проникают в `domain`/`catalog`/`storage`/`service`. Не пропускать слои: SQL не поднимается выше `storage`, разбор форматов не выходит из `importer`, бизнес-правила не живут в транспортах.

## Ошибки

- Ошибки — значения: `*domain.Error{Code, MsgID, Args}` из `internal/domain`; без паник и магических строк в слоях выше.
- Код ошибки — машиночитаемая латиница snake_case; реестр — константы `domain.Code…`; дублирование строк кодов по месту использования запрещено.
- Сообщения — каталог (D9, этап 8.3): стабильный MsgID (латиница snake_case, реестр констант `domain.Msg…` в `internal/domain/messages.go`) + аргументы; форматы en (канонический) и ru — бандлы `internal/i18n`. `Message`/`Problem.Message` — канонический en-рендер; локализованный рендер — только транспорты (`Accept-Language`/`--lang`). Новое сообщение — константа + реестр + форматы en/ru одним изменением (полнота закреплена тестом `internal/i18n/messages_test.go`); изменение формата — несовместимое изменение. Аргументы-сообщения — `domain.MsgArg`, не конкатенация строк.
- CLI: ожидаемые ошибки (`*domain.Error`) выводятся с префиксом `Ошибка: `, прочие — `Непредвиденная ошибка: `; код выхода 1 (константы и вывод — `internal/cli`).
- REST: модель `{"code", "message", "details"}`, статусы 400/404/409/422/500 — по `04-module-functionality.md` §2.

## Семантика секций (upsert и импорт)

Для секций записи наполнения (`fields`, `attributes`, секции групп параметров, `manufacturers`, `variants`, `analogs`):

- отсутствует или `null` — не менять;
- задана — заменить целиком;
- `[]`/`{}` — очистить;
- ошибка в любом значении секции — запись не применяется вовсе; частичное применение запрещено.

`variants` заменяет набор исполнений целиком вместе с их значениями; `manufacturers` — замена списка связей + чистка сирот-производителей; `analogs` — замена только исходящих ссылок (встречные ссылки других записей не затрагиваются, решение D8). Повторный импорт того же файла — исход `Skipped` по всем записям: без записи в БД и без инкремента ревизий.

## Именование кодов и ключей

- Коды ошибок — латиница snake_case (`invalid_designation`).
- Коды параметров/атрибутов/условий/единиц/групп/систем обозначений — стабильные ключи каталога и формата наполнения (совпадают с ключами JSON; коды единиц — латиница, см. «Единицы»); значения словарей классификации (материалы `si`, `ge`, `ga`, `in`, `sic`, `other`, `gaas`; подклассы `bjt`, `fet`, `zener`, `rectifier`…; подстройка `fixed`, `variable`, `preset`; категории — коды каталожного словаря `categories`) — коды в полях разбора/секции `fields` и фильтрах; переименование кода каталога — несовместимое изменение формата, экспорт всегда пишет актуальные коды. Отображаемые названия сущностей — бандлы `internal/i18n` (ключ — код; en — канонический и полный, ru — полный; расширения каталога данными без записи в бандле отображаются кодом).
- Секция `fields` формата наполнения — словарная классификация поверх систем (D10): задаёт только поле, которое парсер системы записи не устанавливает сам, и только применимое к классу; значения — коды словарей; семантика секции — общая (замена целиком).
- Таблицы и колонки БД — snake_case, имена — по `02-database.md`; в каталожных таблицах текстовых колонок нет (D9).
- Идентификаторы Go — MixedCaps; имена файлов — snake_case.

## Единицы

- Канонический справочник единиц — данные (таблица `units`); коды единиц — латиница, locale-neutral (`V`, `mV`, `mA`, `uA`, `A`, `MHz`, `dB`, `pct`, `W`, `mW`, `ohm`, `pF`, `ps`, `ns`, `us`, `degC`, `degC_per_W`, `ppm_per_degC`, `pct_per_degC`, `g`, `mm`, `nm`, `mcd`); названия и символы единиц по локалям — бандлы `internal/i18n` (в БД текстов нет — D9). Фиксированные канонические единицы: сопротивление — ohm, ёмкость — pF, частота — MHz, мощность — W (резисторы, предельные данные конденсаторов) и mW (транзисторы/диоды), ТКС — ppm_per_degC, ТКН — pct_per_degC; безразмерные величины — unit NULL.
- Даташитные единицы (кОм, МОм, мкФ, нФ, кГц, ГГц) переводятся в канонические до записи; производные единицы отображения (мкФ, МОм, кГц) форматирует только слой вывода — в хранилище их нет.

## Переносимость DML

- Только `database/sql` с позиционными аргументами: текст DML — `@имя`-плейсхолдеры, перезапись в `$n` — единая точка `internal/storage/db.go` (`positional` + хелперы `query`/`queryRow`/`exec` и методы диалекта; pgx stdlib имена `@имя` не поддерживает). Переносимые конструкции: `LIMIT/OFFSET`, производные таблицы, `INSERT … SELECT`, `EXISTS`, `INSERT … ON CONFLICT DO NOTHING` (атомарное подавление конфликта уникальности при параллельных писателях postgres; возврат id — метод диалекта `InsertIfAbsentReturningID`, таблицы без суррогатного id — переносимый `Tx.InsertIfAbsent`).
- Булевы значения — INTEGER 0/1; NULL — «не задано»; без JSON-функций СУБД и диалектных типов.
- Всё диалектозависимое (DDL и PK, получение id после вставки, открытие и пулы соединений) — только в `Dialect` (sqlite/postgres) внутри `internal/storage`.
- Весь DML — только в явных транзакциях записи (SQLite: одно выделенное соединение записи, WAL, busy_timeout); вне транзакций — только SELECT из пула чтения.
- Один и тот же набор интеграционных тестов обязан проходить на SQLite и PostgreSQL.

## Схема: без миграций

- Схема создаётся целиком `EnsureCreated` (`CREATE … IF NOT EXISTS`); миграций нет (решение D5).
- Защита от рассинхронизации — `schema_meta.schema_version`: несовпадение с константой модуля — `*domain.Error` `schema_version_mismatch` с отказом в работе; отсутствие `schema_meta` — `database_not_initialized`. Тексты обоих сообщений — дословный контракт.
- Любое изменение DDL — с инкрементом константы версии схемы. Эволюция каталога (новые параметры, условия, семейства) — данными, без правки кода и без смены версии схемы.

## Зависимости

- База — stdlib. Внешние: `modernc.org/sqlite`, `jackc/pgx/v5`, `tailscale/hujson`, `goccy/go-yaml`.
- Новая зависимость допустима, если: pure Go без cgo, минимум транзитивных, живое сопровождение, заменяет самописный разбор или существенно сокращает код. Граница библиотеки — лексика/синтаксис формата; семантика секций, порядок ключей и русские тексты ошибок — только в `internal/importer`.
