## 1. Исполнение ревизии точное — ничего не потеряно

Все коды исходного предложения перебраны поимённо против обновлённого
файла и сида: 16 переименований, 20 исключений, 11 переопределений —

**Восстанавливать исключённые коды не нужно** — все 20 исключений
подтверждены (данные отображаются на расширенные определения).

## 2. Правки, внесённые при финальной проверке

1. `IbPulseMax` — `pulse_duration` переведён из optional в **required**
   (§4/§6.9г: импульсное предельное значение несёт обязательное условие
   `pulse_duration`; все сидовые `*PulseMax` так делают).
2. `PinPulseMax` — удалён второй набор с optional `pulse_duration`;
   остался один набор `pulse_duration` required + `freq`/`temp` optional.
3. **Консолидация `h12b`/`h12e` → `h12`** — один код
   (`at_most`, `tertiary`) с двумя наборами условий:
   `Ie+Vcb`+опц. `freq` (ОБ) и `Ic+Vce`+опц. `freq` (ОЭ).
   Обоснование: одна величина, конфигурация схемы — это схема измерения,
   а не другая величина; прецеденты — сидовый `h11` (один код, обе схемы
   наборами условий) и `Gp` (добавлен `Vcb`-набор вместо отдельного
   `GpCb`). Строки данных `h12b`/`h12e` перевести на `h12` с
   соответствующими условиями; в i18n — один ключ `param.h12` вместо
   двух.
4. Комментарии почищены (они — исходник для i18n-имён): `RthCase`,
   `PdPulseMax`, `tonKey`, `tr`, `PinMax`, `PinPulseMax`, `PinAvgMax`.

Итог: 104 определения — 93 новых кода + 11 переопределённых.

## 3. Кандидаты на слияние/восстановление — разбор

- **`h22e` → `h22`: не объединять.** Философия та же (конфигурация —
  набор условий), но база `h22` план-ограничена схемой ОБ
  (03-data-model.md §6.1: «выходная полная проводимость в схеме ОБ,
  h22б»), наборы — только `Vcb`-схемы. Слияние — осознанное изменение
  планового решения: правка плана + смена имён бандлов en/ru (контракт
  отображения) + переопределение сида — без выгоды для величины такого
  веса. `h22e` остаётся отдельным кодом по образцу `hfe`/`hfb`;
  расщепления сида (§6.9ж) новыми кодами не тиражируются, но и не
  переделываются задним числом.
- **`PinMax` vs `PinAvgMax` — вопрос.** «Непрерывная» и «средняя»
  входная СВЧ-мощность могут быть одной и той же нормировкой (CW =
  средняя). Проверьте по источникам (2Т3132, 3П325): если понятия не
  различаются — слить в один код и перевести строки данных.
- **`IleakPair` vs `IccLeak` — вопрос.** «Ток утечки между транзисторами
  сборки» и «ток утечки между коллекторами» — если физически это одна
  величина (коллектор-коллектор), оставить один код с условием `Vc1c2`
  (масштаб единиц уточнить по данным: uA против nA).
- **Пары `…Mismatch`/`…Ratio` (`gfs`, `Idss`) — заметка.** Два кода на
  одну величину структурно вынуждены разными единицами (проценты против
  безразмерного отношения), но проверьте, что источник реально
  нормирует каждую величину в обеих формах; если встречается только
  одна — второй код не вводить.
- Прочие близкие пары проверены — различия существенные, слияние не
  требуется: `Vn`/`VnDensity` (интегральное и спектральная плотность,
  разные единицы), `Rth`/`RthCase`/`RthAmbient` (точка отсчёта — не
  условие), `IdOff`/`Idss` (закрытое состояние против нулевого затвора),
  `IdTh`/`VgsTh` (ток против напряжения), `VbrCeo`/`VceoMax` (пробой
  против предельного значения), `tonKey`/`Ton` (разные контексты),
  `VgsDiff`/`VgsOffMismatch` (абсолют против относительного).

## 4. Коды, возвращаемые на доработку данных

- **`IbPulseMax`, `PinPulseMax`** — определения ужесточены до
  обязательного `pulse_duration`: строки без длительности перестали
  проходить валидацию. Для каждой такой строки возьмите
  `pulse_duration` из первоисточника; где источник молчит — верните
  перечень строк на ревью, не заполняйте приблизительными значениями.
  Прежний прогон «0 Issues» для этих строк недействителен.
- **`h12b`/`h12e`** — перевести строки данных на консолидированный
  `h12` (условия схемы сохраняются).

## 5. Верификация на нашей стороне

Репозиторий, временная база SQLite: `go build ./...` — без ошибок;
`catalog import --dry-run` — без замечаний; реальный импорт —
«catalog extended»; `catalog list` подтверждает типы, группы,
приоритеты, консолидацию `h12` и сидовые `h11`/`h22` без изменений.
Ваши 284 файла данных здесь не воспроизводились — итоговый сводный
импорт потребуется повторить после доставки файлов.
