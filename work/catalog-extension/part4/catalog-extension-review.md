# Ревью расширения каталога (work/catalog-extension/part4/catalog-extension.jsonc)

Дата: 2026-11-22. Предмет: предложение расширения стартового сида по итогам
анализа справочника «Полупроводниковые приборы. Транзисторы малой мощности»
(1989). Ревью — против правил именования (docs/plan/03-data-model.md §6.9,
docs/class-keys.md §15), стартового сида `seed/seed.go` и семантики секции
`catalog` (docs/fill-format.md §8). Статус: **к принятию не готов** —
требуются правки разделов 2–3 и ответы на вопросы раздела 4.

## Ключевая механика

Секция `catalog` применяется **upsert'ом по коду** (fill-format.md §8):
существующий параметр можно переопределить — наборы условий, применимость
и enum-значения замещаются целиком, поэтому в переопределении повторяйте
действующие наборы полностью и добавляйте новые. Тип `limits` существует
именно для «не менее / не более / диапазон» в пределах одного кода;
расширение `range`/`at_least` → `limits` обратно совместимо с уже
записанными значениями. Поэтому большинство кодов-близнецов `…Max`/`…Min`
не нужны.

## 1. Принимается без изменений

- **Единицы:** все пять — `uV`, `uV_per_degC`, `nA_per_degC`,
  `nV_per_sqrtHz`, `fC`.
- **Условие:** `Vc1c2`.
- **Биполярные, малосигнальные:** `Cce`, `Llead`, `Rb`, `Rcb`, `h22e`
  (сидовый `h22` — это h22б, отдельный код оправдан), `IeOpt`, `tr`, `tf`,
  `td`, `RinPulse` (прецедент — `fPulse`).
- **Ключи:** `Ron`, `RonMismatch`, `tonKey`, `toffKey`, `VonKey`, `IoffKey`.
- **Предельные (биполярные):** `VcerPulseMax`, `VgdMax`, `VgsMin`,
  `RthCase`, `RthAmbient`, `TempCaseMax` (следование семейству
  `TempJunctionMax`), `IcSatMax`, `IcAvgMax`, `IbPulseMax`, `IePulseMax`,
  `VeeoMax`.
- **Полевые:** `VgsDiff`, `gfs2`, `Yin`, `Yout`, `Rin`, `VggMax` (по образцу
  `Rbb`), `VsbMax`, `IgfMax`, `Vgs` как параметр (прецедент двойного
  использования — `Vnom`), `PdPulseMax`, `VdsPulseMax`, `VgsPulseMax`.
- **Однопереходные:** `EtaUjt` (дизамбигуация от `Eta`-КПД необходима),
  `Veb1Sat`, `Rbb`, `VbbMax`, `tonUjt`, `PeMax`, `Ipeak` и `Ivalley` — но в
  единственном коде каждый, тип `limits` (см. раздел 3).
- **Пары/сборки:** `VbeDiff`, `VcbDiff`, `hfeRatio`, `IdssRatio`, `gfsRatio`,
  `gfsMismatch`, `IdssMismatch`, `VgsOffMismatch`, `IleakPair`, `IccLeak`
  (условие замените на `Vc1c2`, см. раздел 2).
- **Лавинные:** `VbrAvalanche`, `IcAvalancheMax`.
- **СВЧ-мощность:** `fOpMax` (прецедент `opTemp`; `fMax` занят
  конденсаторами, коды глобально уникальны), `PebCwMax`, `PebPulseMax`.
- **Шум:** `Qn`.

Семейство сравнения пар (`…Diff`, `…Mismatch`, `…Ratio`) внутренне
согласовано — квалификаторы с прописной, как режимы. Импульсные предельные
последовательно несут обязательное условие `pulse_duration`, порядок
`Pulse` перед `Max` выдержан.

## 2. Переименовать

| Предложено | Решение | Обоснование |
|------------|---------|-------------|
| `VceoBreakdown` | `VbrCeo` | по правилу слитности V(BR)CEO → `VbrCeo`; унификация с `VbrAvalanche` — в файле два разных токена пробоя |
| `VeboBreakdown` | `VbrEbo` | то же |
| `TCRVgsDiff` | `TCVgsDiff` | TCR = temperature coefficient of **resistance**; здесь уход напряжения (мкВ/°C). TCV — устоявшийся термин (стабилитроны) |
| `TCRVbeDiff` | `TCVbeDiff` | то же |
| `TCRVcbDiff` | `TCVcbDiff` | то же |
| `TCRIbDiff` | `TCIbDiff` | то же, ток (нА/°C) |
| `tSetup` | `tSettle` | «время установления» = settling; `Setup` читается как цифровой setup time (t_su) |
| `VebF` | `VebForward` | одиночная прописная `F` — не форма токена (выводы и JEDEC-буквы строчные; прямое направление в сиде — строчное `f` у `Vf`/`If`) |
| `RinsCh` | `RinsChannel` | `Ch`-аббревиатура; прецедент сида — полное слово (`RinsCase`) |
| `VdsSubMax` | `VdSubMax` (или иное) | текущий код парсится как «drain-**source** + Sub», а величина — сток-**подложка** |
| `VccMax` | `Vc1c2Max` | V_CC в международной номенклатуре — питание; та же величина, что условие `Vc1c2`, — именуем одинаково |
| условие `Vcc` | исключить | использовать `Vc1c2` (в т.ч. в `IccLeak`); двух кодов на одну семантику не нужно |

## 3. Исключить — использовать существующий код (с расширением определений)

| Исключаем | Использовать | Что сделать |
|-----------|--------------|-------------|
| `h21e` | `hfe` | дубликат: у `hfe` уже `limits` и те же шесть наборов с опц. `freq`/`temp`; советское `h21э` в код не пишется (§6.9а) |
| `h11b` | `h11` | набор `Ie+Vcb` уже есть в `h11`; конфигурация схемы выражается наборами условий |
| `VbeOn`, `VbeOnMin` | `VbeTh` | сидовый `VbeTh` явно покрывает «напряжение отпирания»; если в источнике строки с условиями Iк/Iэ — добавьте эти наборы в `VbeTh` |
| `TauOs` | `Tauc` (после проверки — см. раздел 4) | τос = rб·Cк — вероятно та же величина, что `Tauc`; квалификатор `Os` — русская аббревиатура, в коде недопустима |
| `fTMax` | `fT` | переопределить `fT` типом `limits` (наборы — четыре действующих плюс ваш пятый «все опциональные») |
| `VgsOffMax`/`VgsOffMin` | `VgsOff` | переопределить типом `limits` (`allow_negative` уже есть) |
| `VgsThMax`/`VgsThMin` | `VgsTh` | то же |
| `IdssMax`/`IdssMin` | `Idss` | то же |
| `VceCutoffMax` | `VceCutoff` | переопределить типом `limits` |
| `IpeakMax`, `IvalleyMin` | `Ipeak`, `Ivalley` | оба кода новые в этом же файле — определяйте сразу `limits`, без трио range+Max+Min |
| `IdOffMax` | `IdOff` | объединить в один код `limits` |
| `Ciss0`, `Crss0` | `Ciss`, `Crss` | у сида прецедент обратный: `Cobo` несёт `Vcb=0` фиксированным набором условий без кода `Cobo0`; добавьте набор `fixed Vds=0` в `Ciss`/`Crss` |
| `GpCb` | `Gp` | «Gp при нормировании по Uкб» — другая схема измерения, а не другая величина: добавьте `Vcb`-набор в `Gp`; кроме того `Cb` с прописной нарушает правило строчных пар выводов |
| `IeboUjt` | `Iebo` | измерение отличается **условием** (межбазовое напряжение вместо Veb), а не величиной: добавьте условие `Vbb` (V) и набор `Vbb`+опц. `temp` у существующего `Iebo` |

## 4. Вопросы — нужны пояснения или выверка по первоисточнику

1. **`TauOs` vs `Tauc`** — подтвердите по справочнику 1989 г., что τос ≠ τк
   (если это одно и то же rб·Cк — код исключается целиком).
2. **`fT` «не более»** — физически странно; проверьте, не ошибка ли чтения
   «не менее» (если подтверждается — переопределение `fT` в `limits`
   решает).
3. **`IgTh`** — что это: «ток затвора при пороговом напряжении» как
   нормируемая величина выглядит подозрительно. Ссылка на страницу
   справочника.
4. **`Imod`** — «ток модуляции» однопереходного транзистора: подтвердите
   существование величины и её определение.
5. **`fGen`** — «предельная частота генерации»: подтвердите термин;
   возможно более точное имя.
6. **`GpControl`** — «глубина регулирования усиления» — это, по сути,
   AGC-диапазон: рассмотрите `GpAgc`.
7. **`Vcontrol`, `VcbControlMax`** — семантика мутная («управляющие
   переходы»?): что за величины и у каких приборов.
8. **`VgsQuad`** — понятен ли квалификатор читателю карточки? Рассмотрите
   альтернативы.
9. **`Klin`** — у величины нет международного символа; по правилу §6.9д она
   претендует на словесный код camelCase (напр. `linearity`). Либо
   обоснуйте `K` как символ.
10. **`Vn` и `En`** — одно семейство (шумовое напряжение) двумя символами:
    V (мкВ, интегральное) и E/ЭДС (нВ/√Гц, плотность). Выберите одну
    конвенцию.
11. **`PinMax`/`PinPulseMax`/`PinAvgMax`** — если это «наибольшая допустимая
    входная мощность», это предельное данное → группа `limiting` (рядом
    `PebCwMax`/`PebPulseMax` — limiting). Либо уточните, что это рабочая
    величина.
12. **`PinOverloadMin`** — порог сжатия усиления: подтвердите термин
    источника.
13. **`VcerMax`** — имя оставляем, но «условие Rбэ — в notes» неправильно:
    `Rbe` — существующее условие (им пользуется `Icer`), и ваш же
    `VcerPulseMax` его несёт. Сделайте набор `Vce+Rbe`.
14. **`TCRbb`** — имя корректно, но добавьте `allow_negative` (у `TCR` он
    есть; знаки ТКС Rbb встречаются разные), если источник даёт
    отрицательные значения.

## Общие требования к следующей итерации

- На каждый оставшийся новый код (параметры, единицы, условия) — записи
  `param.<код>` / `unit.<код>` / `condition.<код>` в бандлах
  `internal/i18n` en+ru одним изменением (en канонический и полный, ru
  полный — пин-тест полноты).
- При переопределении действующих параметров наборы условий и применимость
  повторяются целиком (замещение upsert'ом), действующие значения должны
  оставаться валидными.
- `priority`/`sort_order` возражений не вызывают.
