# qa — сквозные прогоны и нагрузочная прикидка (этап 7.1)

Артефакты этапа 7.1 `docs/plan/05-work-plan.md`: сценарные прогоны CLI и REST
на SQLite и PostgreSQL, нагрузочная прикидка против ориентиров
производительности. Ревью архитектуры — `qa/architecture-review.md`.

## Состав

| Файл | Назначение |
|------|-----------|
| `scenarios.sh` | Сквозные сценарии CLI (`catalogctl`) и REST (`qa/restsrv`): импорт выверенной выборки `data/`, идемпотентность, round-trip экспорта, поиск/карточка/find/подсказка, dry-run, каскадное удаление, негативные случаи (префикс «Ошибка: », коды выхода), REST-контракт (статусы, коды ошибок, ETag/304, CRUD). SQLite — всегда; PostgreSQL — при `CATALOG_TEST_POSTGRES_DSN` |
| `restsrv/` | Минимальный хост REST `/api/v1` для прогонов (модуль серверов не запускает — план 04 §5) |
| `load_test.go` | Нагрузочная прикидка: генерация NDJSON-датасета синтетических транзисторов JEDEC, импорт боевым путём, измерения поиска/карточки/suggest против ориентиров |
| `reports/` | Отчёты прогонов (формат — ниже) |

## Запуск

```
./qa/scenarios.sh                        # SQLite (+ PostgreSQL при DSN)
CATALOG_QA_SCALE=10000 go test ./qa -run TestLoad -v -timeout 30m
CATALOG_QA_SCALE=100000 go test ./qa -run TestLoad -v -timeout 30m
CATALOG_QA_DIALECT=postgres CATALOG_TEST_POSTGRES_DSN=postgres://… \
  CATALOG_QA_SCALE=10000 go test ./qa -run TestLoad -v -timeout 30m
```

Переменные нагрузочной прикладки: `CATALOG_QA_SCALE` — число записей
(без неё тест пропускается), `CATALOG_QA_DIALECT` (sqlite по умолчанию),
`CATALOG_QA_DB` — путь файла sqlite (по умолчанию временный),
`CATALOG_QA_STRICT=1` — строгий режим (превышение цели на порядок — отказ).

CI (`.github/workflows/ci.yml`) прогоняет сценарии на обеих СУБД и
нагрузочную прикладку на SQLite 10⁴; масштаб 10⁵ — ручной прогон по мере
надобности (в отчёт).

## Ориентиры производительности (docs/plan/04 §5)

- поиск с фильтрами по 10⁴–10⁵ устройств ≤ 100 мс;
- карточка ≤ 20 мс.

Прикидка — измерение, а не порог: медианы печатаются с меткой `ok` /
`ПРЕВЫШЕНИЕ` и фиксируются отчётом. Превышение ориентира — материал для
плана Б по риску R2 (денормализация/материализация вынесенных фильтров
без смены публичного API), а не автоматический отказ прогона; отказ —
только строгий режим (`CATALOG_QA_STRICT=1`, превышение на порядок) либо
ошибки корректности (отказы импорта).

## Формат отчёта прогона

Отчёт — `qa/reports/<ГГГГ-ММ-ДД>-<повод>.md`:

1. **Окружение** — машина/runner, ОС, Go, СУБД и версии, коммит.
2. **Сценарии** — `итог: ok=N fail=M` из `scenarios.sh` по каждой ноге
   (sqlite/postgres), список отказов при наличии.
3. **Нагрузочная прикладка** — таблицы измерений (диалект × масштаб ×
   операция: p50, цель, вердикт), скорость импорта; для превышений —
   краткий разбор (план запроса) и вывод.
4. **Выводы** — соответствие критериям v0.1, задачи на следующий релиз.

Формат отчёта ревью архитектуры — `qa/architecture-review.md`.
