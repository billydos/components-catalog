# AGENTS.md — Go-реализация (soviet-transistors-go)

Справочник советских транзисторов: консольная утилита Go + SQLite (UTF-8). Разбирает обозначения по ГОСТ 10862-64, хранит электрические параметры с условиями измерения, предельные данные и описательные атрибуты. Схема спроектирована переносимой на PostgreSQL/MariaDB.

## Команды

```shell
# сборка (без предупреждений: go vet и gofmt чисты)
go build ./...
go vet ./...
gofmt -l .        # пустой вывод — ок

# запуск
go run ./cmd/soviettransistors <команда> [аргументы] [--db <путь>] [--dry-run]

# восстановление рабочей базы из данных репозитория
go run ./cmd/soviettransistors import sample-data.jsonc

# проверка файла импорта (jsonc/yaml) без записи в базу
go run ./cmd/soviettransistors import <файл> --dry-run

# unit-тесты Domain и importer (table-driven)
go test ./...
```

Команды CLI: `init`, `import`, `add`, `parse`, `list`, `info`, `find`, `delete`, `count` (полный справочник — `help` и README.md). Unit-тесты (`*_test.go` рядом с кодом, пакеты `internal/domain` и `internal/importer`) покрывают парсер обозначений, валидаторы (все варианты условий каждого параметра) и каталог параметров — прогонять при правках `internal/domain/`. Сценарные прогоны остаются QA для CLI и БД (импорт + негативные случаи, `info`, раздельность записей КТ/2Т и подсказка `find`, каскадное удаление, exit-коды).

## Структура

```
cmd/soviettransistors/   точка входа (main)
internal/domain/         обозначения, каталог параметров, ratings, атрибуты, валидация — без зависимостей от БД
internal/storage/        RelationalStore (переносимое ядро DML, database/sql) + NewSqliteStore (DDL, диалект)
internal/importer/       реестр форматов импорта (jsonc/json — hujson, yaml/yml — goccy/go-yaml) + упорядоченное дерево значений + валидация секций
internal/cli/            разбор аргументов, команды, вывод, справка
```

## Ключевые правила

1. **Валидация электрических параметров декларативна**: правила (границы, потолок значения, варианты условий) заданы в каталоге `internal/domain/parameters.go` (`ParameterCatalog`) и `internal/domain/conditions.go` (именованные спецификации `Spec*`). Из каталога генерируются: валидатор (`internal/domain/parametervalidator.go`), раздел параметров `help` (`internal/cli/help.go`), список полей секции jsonc (`internal/importer/reader.go`) и CHECK-ограничения `electrical_parameters` (`storage/ddl.go`, компонуемый в `storage/sqlite.go`). Новый код параметра — правка каталога плюс SKILL.md. Валидация ratings и атрибутов по-прежнему дублируется в двух местах: `internal/domain/*validator.go` (сообщения по-русски) и CHECK в `internal/storage/sqlite.go` — обновляй оба места. Исключения: `chk_letters` сознательно слабее домена (переносимого предиката «1–2 заглавные кириллические» в CHECK у SQLite/PostgreSQL/MariaDB нет — обоснование в комментарии DDL, не «усиливать»); список полей атрибутов имеет единый источник — `domain.AttributeFieldNames()` (`internal/domain/attributes.go`, reflect по структуре записи), из него генерируются `chk_any_attribute` (`storage/ddl.go`) и `attributeColumns` (спецификация чтения в `storage/relational.go`), новое свойство записи подхватывается автоматически (пин-тест Domain ловит рассинхронизацию).
2. **Именование полей** единое в jsonc, полях структур и колонках БД (CamelCase): символ физической величины — первая заглавная, остальные строчные (`Uke`, `Ik`, `Freq`, `Rg`); слова-модификаторы — с заглавной (`Max`, `Nas`, `Gran`, `Pulse`); описательные поля — строчными (`parameter`, `min`, `max`, `colorMarking`); индексы ГОСТ — строчными (`Ikbo`, `Ikeo`, `Tauk`); h-параметры — всегда строчные (`h21e`, `h11`). Исключения: условия `freq`/`temp` — полные слова.
3. **Единицы канонические** (фиксированы типом параметра): В, мА (токи и токовые условия), мкА (обратные токи), МГц, дБ, Вт, %, Ом, пс, нс, пФ, °C, мВт, мкс, г, °C/Вт. Переводить значения даташита до записи; 1 кГц = 0.001 МГц.
4. **Семантика секций jsonc** (`attributes`/`parameters`/`ratings`): отсутствует или `null` — не менять (null у целой секции равносилен отсутствию; у полей внутри секций null — «не задано», у `manufacturers` — «не менять список»); задана — заменить целиком; ошибка хотя бы в одном значении — секция отвергается и запись не применяется вовсе, ни обозначение, ни остальные секции (защита от частичного стирания); `[]`/`{}` — очистить. Импорт идемпотентен.
5. **Миграции БД не поддерживаются намеренно** (проект в разработке): при изменении схемы рабочая база пересоздаётся импортом. Не добавляй код миграций.
6. **Обозначение — точный ключ записи; материалы равнозначны только физически**: Г/1, К/2, А/3, И/4 — один материал, но `КТ312` и `2Т312` — отдельные записи с собственными данными. `add`/`info`/`delete`/импорт работают по точному совпадению; фильтр `list --material` группирует оба символа; `find` при отсутствии точной записи подсказывает равнозначную по материалу (`FindMaterialEquivalents`).
7. **Данные sample-data.jsonc** (`sample-data.jsonc`) — правдоподобные, но непроверенные значения — только в рабочую базу, не в репозиторий.
8. **Кодирование значений в БД единообразно**: булевы — INTEGER 0/1 (`Assembly` — NOT NULL, опциональные булевы атрибуты — 0/1/NULL); отсутствие необязательного значения — NULL. Сравнение колонок, допускающих NULL, — переносимый предикат `col = @p OR (col IS NULL AND @p IS NULL)`, без сенти́нелов (`COALESCE(col, -1)` и т.п.).
9. **Ошибки — значения, не паника**: ожидаемые ошибки диалога (некорректный аргумент, данные, отсутствие записи) — `*domain.UserError`, CLI печатает их с префиксом «Ошибка: »; прочие ошибки — «Непредвиденная ошибка: »; код выхода 1. Не использовать `panic` в пути данных.
10. **Семантика nil**: nil-указатель в полях моделей (`*float64`, `*int`, `*bool`, `*string`) — «не задано»; в `storage.TransistorDetails` nil-секция — «не менять», пустая непустая-nil секция (например, `[]domain.ElectricalParameter{}`) — «очистить». Не терять это различие при правках (nil-срез ≠ пустой срез).
11. **Зависимости**: база — stdlib + `modernc.org/sqlite` (pure Go, без cgo). Внешние зависимости — инструмент оптимизации кодовой базы: добавляются, когда уменьшают число строк или ветвлений методов либо заменяют самописный разбор (стрипперы, лексеры) выверенной библиотекой. Критерии выбора: pure Go без cgo, минимум транзитивных зависимостей, живое сопровождение (ориентиры: jsonc — `tailscale/hujson`, yaml — `github.com/goccy/go-yaml`; xml хватает stdlib `encoding/xml`). Граница ответственности: библиотека — только лексика/синтаксис формата; семантика секций, порядок ключей и дословные тексты русских сообщений об ошибках остаются в `internal/importer`.

## Не трогать

- `transistors.db` — генерируется импортом; не коммитить.
- `.kilo/skills/soviet-transistors-go/SKILL.md` (проектный скилл Kilo) — регламент наполнения; синхронно обновлять при изменении формата jsonc (полный справочник полей и типичных ошибок там, дублировать в AGENTS.md не нужно).
- DML в `internal/storage/relational.go` — только переносимые конструкции (`@`-параметры через `sql.Named`, `LIMIT`, производные таблицы, `INSERT ... SELECT`); запись — в транзакции (`Begin` + `defer Rollback` + `Commit`). Диалектозависимые вещи — только в структуре `Dialect` (`Open`, `CreateTableSql`, `LastInsertIdSql`) и `NewSqliteStore`.
- Соединение БД — одно на `RelationalStore`: открывается лениво при первом обращении, закрывается в `Close` (CLI — `defer db.Close()`); у SQLite это `SetMaxOpenConns(1)` в `NewSqliteStore` — не увеличивать (PRAGMA `foreign_keys` действует на единственное соединение). `EnsureCreated` выполняют только команды записи (`init`/`add`/`import`, один раз за запуск); команды чтения и `delete` обходятся без DDL.
- AUTOINCREMENT у id-колонок в DDL (`transistors`, `manufacturers`) — осознанный запрет переиспользования id после удаления: id — стабильная внешняя ссылка на запись (FK-связи, вывод, экспорт), и IDENTITY/AUTO_INCREMENT целевых СУБД ведут себя так же. Не «оптимизировать» до `INTEGER PRIMARY KEY`.
- Тексты русских сообщений валидации и вывода — часть контракта.
