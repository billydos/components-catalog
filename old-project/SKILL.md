# Справочник советских транзисторов (soviet-transistors-go)

Проект: `soviet-transistors-go/` (Go, SQLite; зависимости — `modernc.org/sqlite`, `tailscale/hujson` (jsonc), `goccy/go-yaml` (yaml), все pure Go). База по умолчанию — `transistors.db` рядом с текущим каталогом (UTF-8). Обозначения хранятся в таблице `transistors`, данные — в `transistor_attributes` (описательные атрибуты, 1:1), `manufacturers` + `transistor_manufacturers` (производители, M:N), `electrical_parameters`, `maximum_ratings` (все связаны по `id`, удаляются каскадно).

## Запуск программы

```
go run ./cmd/soviettransistors <команда> [аргументы] [--db <путь>] [--dry-run]
```
```
soviettransistors <команда> [аргументы] [--db <путь>] [--dry-run]
```

Опции можно указывать в любом месте команды. `--db` (или `--db=<путь>`) переопределяет путь к базе; иначе берётся переменная окружения `TRANSISTOR_DB`, иначе `./transistors.db`. Команды `list`/`info`/`find`/`count`/`delete` не создают базу: если файла нет — ошибка с кодом 1.

| Команда | Назначение |
|---|---|
| `init` | создать таблицы (выполняется автоматически при любой записи) |
| `import <файл.jsonc\|.yaml>` | импорт транзисторов со всеми данными из структурированного файла (jsonc или yaml той же структуры; формат — по расширению) |
| `add <обозначение>...` | добавить транзисторы только по обозначению (через парсер) |
| `parse <обозначение>...` | разобрать обозначение и показать поля, база не трогается |
| `list [фильтры]` | список обозначений из базы |
| `info <обозначение>` | полная карточка: структура, параметры, предельные и дополнительные данные |
| `find <обозначение>` | проверить наличие по точному обозначению (при отсутствии — подсказка равнозначной по материалу записи) |
| `delete <обозначение>...` | удалить записи (каскадно с параметрами и данными) |
| `count` | количество записей |

Фильтры `list`: `--material=Г|1|К|2|А|3|И|4`, `--subclass=Т|П`, `--assembly=true|false`, `--feature=1..9`, `--number=1..999`, `--letters=А|АМ` (точное совпадение), `--modification=1..9`, `--chip=1..6`, `--limit=N`. Форма записи: `--опция=значение` или `--опция значение`.

Материалы попарно равнозначны физически: Г=1 (германий), К=2 (кремний), А=3 (арсенид галлия), И=4 (индий). Равнозначность — характеристика материала для фильтров и отображения, но не ключ записи: `КТ312` и `2Т312` — отдельные записи с собственными данными. `add`/`info`/`delete`/импорт работают по точному обозначению; `find` при отсутствии точной записи подсказывает равнозначную по материалу. Выходной код 1 — были ошибки (проверить вывод).

Порядок работы при наполнении: отредактировать jsonc/yaml → `import --dry-run` (проверка без записи) → `import` → контрольная проверка `info <обозначение>` и `list`.

## Формат файла наполнения (jsonc/yaml)

JSONC (JSON с `//`-комментариями и висячими запятыми; понимаются и `/* */`). Корень — объект с единственным ключом `transistors` (массив). Те же данные можно писать в yaml (расширения `.yaml`/`.yml`): структура и семантика секций идентичны, числа задаются без кавычек; повторяющиеся ключи объекта отвергаются при разборе в обоих форматах (с номером строки). В yaml повторяющиеся блоки можно задавать якорем и переиспользовать алиасом (`&имя` на блоке, `*имя` на месте копии — например, общая секция `attributes` для серии записей): алиас разворачивается в значение ранее определённого якоря; алиас без предшествующего якоря и циклическая ссылка — ошибка разбора файла. Каждая запись — одна из трёх форм:

```jsonc
{ "transistors": [
    "КТ315А",                                    // 1) строка — только обозначение
    { "name": "КТ315Б", /* секции */ },          // 2) объект с "name" + секции
    { "material": "Г", "subclass": "Т",          // 3) явные поля обозначения + секции
      "feature": 1, "number": 15, "letters": "А", /* необязательные: assembly, modification, chip */ }
] }
```

Секции `attributes`, `parameters`, `ratings` — необязательные, семантика у всех одна:
- секция отсутствует или задана как `null` — существующие данные транзистора не меняются (`null` у целой секции равносилен отсутствию; в yaml пустое значение ключа — то же `null`); у *полей* внутри секций семантика другая: `null` = «не задано» (при замене секции очищает поле), и только у `manufacturers` `null` = «не менять список»;
- секция задана — данные заменяются целиком (импорт можно повторять, он идемпотентен);
- при ошибке хотя бы в одном значении секция полностью игнорируется и запись не применяется вовсе — ни обозначение, ни другие секции (база не портится частичными данными), ошибка выводится в список проблем;
- `"parameters": []` очищает список параметров транзистора, `"manufacturers": []` — список производителей;
- запись транзистора (вставка + секции) применяется в одной транзакции: либо целиком, либо никак.

Канонические единицы: В (напряжения), мА (токи и токовые условия), мкА (обратные токи), МГц (частота), Ом (сопротивления), пФ (ёмкости), пс (Tauk), нс (Ton/Toff), дБ (KShum, KUr), Вт (PVyh), % (kpd), °C (температуры), мВт (мощности), мкс (длительность импульса), °C/Вт (тепловое сопротивление).

## Обозначение (name / явные поля)

Формат: `<материал><подкласс>[С]<признак><номер><буквы>[<модификация>][-<бескорп.>]`.

| Часть | Значения | Поле явной формы |
|---|---|---|
| материал | Г/1, К/2, А/3, И/4 | `material` (символ, как в источнике) |
| подкласс | Т (биполярный), П (полевой) | `subclass` |
| сборка | С, необязательна | `assembly` (true = С) |
| признак | цифра 1–9 | `feature` |
| номер разработки | 01–999 (2–3 цифры, «015» с ведущим нулём недопустимо) | `number` (1–999) |
| классификация | 1–2 заглавные русские буквы | `letters` |
| модификация | цифра 1–9, необязательна | `modification` |
| бескорпусное исполнение | дефис и цифра 1–6, необязательно | `chip` |

При форме `"name"` парсер допускает только это; префикс «М» (старая система, МП16) не поддерживается. Примеры: `КТ315Б`, `ГТ402Ж` (= Г/Т/4/02/Ж), `2Т819А`, `КТ3102А`, `КТ818АМ`, `КТ825А1` (модификация), `2Т914А-1` (бескорпусное), `1ТС801А` (сборка).

## Секция "attributes"

Объект — описательные атрибуты транзистора (1:1, таблица `transistor_attributes`). Все поля необязательны; в БД строка создаётся только если задано хотя бы одно поле.

| Поле | Тип | Смысл |
|---|---|---|
| `structure` | строка | структура проводимости: `npn`, `pnp`, `n-fet`, `p-fet`, `n-канал`... |
| `technology` | строка | технология: сплавная, сплавно-диффузионная, планарная, эпитаксиальная... |
| `package` | строка | корпус: «КТ-13», «TO-92»... |
| `packageMaterial` | строка | материал корпуса: металл, металлокерамика, пластик... |
| `colorMarking` | строка | цветовая маркировка (если обозначения на корпусе нет): «красный», «жёлтая точка»... |
| `pinout` | строка | цоколёвка: «КБЭ», «1-Э 2-К 3-Б»... |
| `esdSensitive` | bool | повышенная чувствительность к статическому напряжению |
| `militaryGrade` | bool | военное исполнение |
| `radiationHardened` | bool | радиационная стойкость |
| `tu` | строка | обозначение ТУ/ОТУ: «ТУ 11.365.001-71»... |
| `notes` | строка | примечание свободным текстом |
| `yearFrom` | int | год начала выпуска (1949–2100) |
| `yearTo` | int | год окончания выпуска (1949–2100, строго больше yearFrom); отсутствует/`null` — выпускался на момент описания |
| `massMax` | число | масса «не более», г |
| `datasheetUrl` | строка | ссылка на документацию |
| `manufacturers` | массив строк | производители; отсутствует/`null` — список не меняется, `[]` — очищается, дубликаты в списке допустимы (сводятся к одному). Хранится через таблицы `manufacturers` (уникальные имена) + `transistor_manufacturers` (M:N), дубликатов имён не создаёт; имена, оставшиеся без связей (после замены списка или удаления записи), из базы удаляются автоматически |

Строковые поля не могут быть пустыми строками (`null`/отсутствие = «не задано»); у булевых `null` = «не задано», `false` = «нет». Пустой объект `"attributes": {}` (или только с `null`-полями) очищает атрибуты транзистора; если при этом задан `manufacturers` (в том числе пустой массив `[]`) — атрибуты не трогаются, применяется только секция производителей (замена или очистка списка). Электрические параметры полевых транзисторов (напряжение отсечки, крутизна, начальный ток стока) пока не поддерживаются — их коды обсуждаются отдельно; полевые транзисторы вносятся с атрибутами, ratings.

## Секция "parameters"

Массив объектов. Одна строка массива = один параметр при одном наборе условий. Один и тот же параметр может встречаться несколько раз (например, обратный ток при +25 и +70 °C).

```jsonc
{ "parameter": "h21e", "min": 50, "max": 350, "Uke": 10, "Ik": 1 },
{ "parameter": "KShum", "max": 10, "Uke": 5, "Ik": 0.2, "freq": 0.001, "Rg": 200 }
```

| Поле | Тип | Смысл |
|---|---|---|
| `parameter` | строка, обязательна | код параметра (см. таблицу) |
| `min` | число | нижняя граница («не менее», или начало диапазона) |
| `max` | число | верхняя граница («не более», или конец диапазона) |
| `Uke`, `Ukb`, `Ueb` | число | условия: Uкэ / Uкб / Uэб, вольты |
| `Ik`, `Ie`, `Ib` | число | условия: Iк / Iэ / Iб, миллиамперы |
| `freq` | число | условие: частота, МГц (только частотные параметры; 1 кГц = 0.001, 1 ГГц = 1000) |
| `Rg` | число | условие: сопротивление генератора, Ом (только `KShum`) |
| `Rbe` | число | условие: сопротивление в цепи б-э, Ом (только `Ikep`) |
| `temp` | число | условие: температура среды, °C (может быть отрицательной; допускается у любого параметра) |

Канонические единицы значений заданы типом параметра (см. таблицу); переводить данные даташита в них до записи.

| Код | Параметр | Единица | Границы | Условия (ровно) |
|---|---|---|---|---|
| `h21e` | статический коэффициент передачи тока (ОЭ) | — (раз) | min обязателен, max опционален (диапазон) | пара `Uke`+`Ik` (ОЭ) либо пара `Ukb`+`Ie` (ОБ) |
| `h21b` | коэффициент передачи тока (ОБ) | — (раз) | min обязателен, max опционален | `Ukb`+`Ie` |
| `FGran` | граничная частота коэффициента передачи тока | МГц | только `min` («не менее») | пара `Uke`+`Ik` либо `Ukb`+`Ie` |
| `UGran` | граничное напряжение | В | только `min` | только `Ik` или только `Ie` |
| `UkeNas` | напряжение насыщения коллектор-эмиттер | В | только `max` («не более») | только `Ik` или только `Ie` |
| `UbeNas` | напряжение насыщения база-эмиттер | В | только `max` | только `Ik` или только `Ie` |
| `Ikbo` | обратный ток коллектора | мкА | только `max` | только `Ukb` |
| `Iebo` | обратный ток эмиттера | мкА | только `max` | только `Ueb` |
| `Ikeo` | обратный ток коллектор-эмиттер | мкА | только `max` | только `Uke` |
| `Ikep` | обратный ток к-э при заданном Rбэ | мкА | только `max` | `Uke`+`Rbe` |
| `h11` | входное сопротивление | Ом | только `min` | `Uke`+`Ik` |
| `Ck` | ёмкость коллекторного перехода | пФ | только `max` | только `Ukb` |
| `Ce` | ёмкость эмиттерного перехода | пФ | только `max` | только `Ueb` |
| `Tauk` | постоянная времени цепи обратной связи | пс | только `max` | `Ukb`+`Ie` |
| `Ton` | время включения | нс | только `max` | `Ik`+`Ib` |
| `Toff` | время выключения (рассасывания) | нс | только `max` | `Ik`+`Ib` |
| `KShum` | коэффициент шума | дБ | только `max` | пара (`Uke`+`Ik` либо `Ukb`+`Ie`) + обязательная `freq`; `Rg` опциональна |
| `PVyh` | выходная мощность | Вт | только `min` | обязательная `freq`; пара `Uke`+`Ik` опциональна (оба или ни один) |
| `KUr` | коэффициент усиления по мощности | дБ | только `min` | как `PVyh` |
| `Kpd` | КПД коллектора | % | только `min`, не выше 100 | как `PVyh` |

Дополнительные ограничения: все `min`/`max` и условия `Uke`/`Ukb`/`Ueb`/`Ik`/`Ie`/`Ib`/`freq`/`Rg`/`Rbe` строго положительны; при `min` и `max` одновременно `min ≤ max`; `freq` — только у `KShum`/`PVyh`/`KUr`/`Kpd`, `Rg` — только у `KShum`, `Rbe` — только у `Ikep`, `Ib` — только у `Ton`/`Toff`; запрещённые комбинации условий — ошибка.

## Секция "ratings"

Объект, предельные эксплуатационные данные:

| Поле | Смысл | Единица |
|---|---|---|
| `UkeMax` | постоянное напряжение коллектор-эмиттер | В |
| `UkbMax` | постоянное напряжение коллектор-база (к-б = б-к) | В |
| `UbeMax` | постоянное напряжение база-эмиттер (б-э = э-б) | В |
| `UkeoMax` | постоянное напряжение к-э при разомкнутой базе | В |
| `IkMax` | постоянный ток коллектора | мА |
| `IbMax` | постоянный ток базы | мА |
| `PkMax` | постоянная рассеиваемая мощность коллектора | мВт |
| `IkPulseMax` | импульсный ток коллектора | мА |
| `PkPulseMax` | импульсная рассеиваемая мощность | мВт |
| `pulseDuration` | длительность импульса (обязательна при любом из импульсных) | мкс |
| `tempMin` | минимальная температура среды (может быть отрицательной) | °C |
| `tempMax` | максимальная температура среды | °C |
| `tempJunctionMax` | максимальная температура перехода | °C |
| `Rth` | тепловое сопротивление переход-корпус | °C/Вт |

Все поля необязательны, но при задании — положительные числа, кроме `tempMin`/`tempMax` (любые, но `tempMin < tempMax` при обоих заданных); `pulseDuration` обязательна, если задан `IkPulseMax` или `PkPulseMax`, и не задаётся без них.

## Контроль и типичные ошибки

После каждого изменения данных проверять: `import --dry-run` (список проблемных записей с указанием номера записи и поля), затем `info <обозначение>`.

Характерные сообщения валидации:
- «позиция N: ...» — ошибка разбора обозначения (посмотреть символ в этой позиции);
- «условия — ...; задано: ...» — неверная комбинация условий: одно сообщение перечисляет
  допустимые варианты (через «либо») и фактически заданные условия, например у `h21e` —
  «условия — Uкэ (Uke) + Iк (Ik) либо Uкб (Ukb) + Iэ (Ie); задано: Uкэ (Uke), Iк (Ik), Iб (Ib)»;
  перечень вариантов по каждому коду — в справке (`help`) и таблице параметров выше;
- «верхняя граница (max) не допускается» — у параметра вида «не менее» указан `max`;
- «КПД коллектора не может превышать 100 %» — `Kpd` > 100;
- «длительность импульса (pulseDuration, мкс) обязательна, если задан импульсный ток или мощность» — в ratings;
- «Tмин ... должна быть меньше Tмакс» — диапазон температур в ratings;
- «год начала выпуска должен быть от 1949 до 2100» / «должен быть меньше года окончания» — атрибуты;
- «"manufacturers" №N: ожидалось непустое название производителя» — массив производителей;
- «значение должно быть положительным» — нулевое/отрицательное значение; про условия —
  «условие Uкэ должно быть положительным», «частота должна быть положительной» и т. п.;
- «неизвестный код «...»» — опечатка в `parameter` (список допустимых кодов — в сообщении);
- «повторяющийся ключ «...» (строка N)» — ключ объекта задан дважды (частая опечатка при
  копировании блоков); файл отвергается целиком до применения записей, в jsonc и yaml одинаково;
- «неизвестный ключ корневого объекта «...»», «отсутствует обязательный ключ "transistors"»,
  «"transistors" должен быть массивом», «корневой элемент должен быть объектом вида ...» —
  проблемы структуры корня файла: выводятся списком проблем (без префикса «Ошибка:») все
  сразу за один прогон; записи не применяются;
- «неизвестный алиас «*...» — якорь «&...» не определён до использования» — yaml: алиас стоит
  раньше якоря или якоря нет; «циклическая ссылка: алиас «*...» участвует в значении якоря
  «&...»» — якорь ссылается на себя; в обоих случаях файл отвергается целиком.

Не редактировать `transistors.db` напрямую в обход программы: ограничения продублированы в БД (CHECK/FK), но сообщения об ошибках и форматирование номеров («01–999») обеспечивает программа.
