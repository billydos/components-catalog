# STYLEGUIDE.md — стиль кода на Go

Гайд закрепляет правила стиля для этого репозитория. Архитектурные правила
(слои, зависимости, семантика секций, единицы) — в `AGENTS.md`; здесь только
стиль кода. Споры, не покрытые гайдом, решаются практикой Go
([Effective Go](https://go.dev/doc/effective_go),
[Google Go Style Guide](https://google.github.io/styleguide/go/)) и здравым
смыслом.

## 1. Базовые принципы

- `gofmt` обязателен: форматирование не обсуждается и не попадает в код-ревью.
- `go vet` обязан быть чистым.
- Изменения стиля не смешиваются с логикой в одном коммите.
- Пиши идиоматичный Go, а не «Go как C/Python»: нулевые значения, ошибки как
  значения, композиция вместо иерархий.

## 2. Форматирование

- Отступ — таб (ставит `gofmt`).
- Имена файлов — `snake_case.go` (`parameter_ranges.go`, `db_test.go`).
- Импорты группами, пустой строкой между группами, порядок: stdlib → внешние →
  внутренние (`internal/…`, `seed`); сортировка внутри группы — `gofmt`.

```go
import (
	"context"

	"github.com/billydos/components-catalog/internal/domain"
)
```

- Dot-import запрещён (в тестах — только при веской причине).
- Псевдонимы импортов — только при конфликте имён.

## 3. Именование

Общее правило — MixedCaps (camelCase): имена из нескольких слов пишутся
слитно, слова различаются регистром первой буквы. `snake_case` и
`SCREAMING_SNAKE_CASE` в идентификаторах Go не используются.

- **Переменные** — `camelCase` (`lowerCamelCase`): `byCode`, `def`, `snap`.
  В узкой области (пара строк, тело цикла) — коротко (`r`, `v`, `ok`, `i`);
  чем шире область и дальше от объявления до использования — тем полнее имя.
- **Экспортируемые идентификаторы** — `UpperCamelCase`; экспорт — контракт,
  имя должно быть понятным без пакета и комментариев.
- **Аббревиатуры** — одним словом, все буквы одного регистра: `userID`,
  `serveHTTP`, `maxURL`, но не `userId`, `serveHttp`.
- **Константы** — MixedCaps, без `ALL_CAPS`: `defaultPageSize`,
  `schemaVersion`. Перечисления — отдельный строковый/целый тип и общий префикс
  констант: `CodeValidationFailed`, `MsgKindUnknown`.
- **Пакеты** — коротко, строчными, без `_` и `mixedCaps`: `domain`, `storage`.
  Имя пакета — часть идентификатора: без тавтологии `catalog.CatalogError` →
  `catalog.Error`, `service.ServiceReload` → `service.Reload`.
- **Файлы** — по содержимому, без `utils`/`helpers`/`common`.
- **Интерфейсы** — объявляются на стороне потребителя, описывают только то,
  что потребителю нужно. Однометодные — суффикс `-er`: `Reader`, `Validator`.
- **Getter** — без префикса `Get`: `svc.Name()`; setter — `SetX(v)`.
- **Булевы переменные** — утвердительно и однозначно: `found`, `ready`,
  `isSorted`, `hasChildren`; отрицательные имена (`isNotReady`) запрещены.

### Receiver методов

Короткая устойчивая аббревиатура имени типа, **2–3 буквы**, одинаковая во всех
методах типа; не `this`/`self` и не однобуквенная.

```go
func (svc *DeviceService) Reload(ctx context.Context) error { … }
func (db *DB) Exec(ctx context.Context, q string) error { … }
func (tx *Tx) InsertIfAbsent(…) error { … }
```

Существующий код с однобуквенными receiver'ами (`s *DeviceService`)
переводится на это правило постепенно, при касании файла.

## 4. Комментарии и документация

- Комментарии — на русском (как весь код репозитория), идентификаторы —
  латиницей.
- Формат — `// ` (два слэша и пробел) сразу над сущностью; doc-комментарий
  начинается с имени сущности.
- Экспортируемая сущность обязана иметь doc-комментарий: контракт, единицы,
  ограничения, нулевые значения, что означает `error`.
- Объясняй «почему», а не пересказывай «что»: код отвечает на «что».
- Комментарий-заглушка, повторяющий имя, хуже отсутствия комментария.
- Инлайновые комментарии — для неочевидных решений:
  `continue // FK гарантирует наличие; защита от рассинхрона снимка`.
- `TODO`/`NOTE` с сутью и контекстом: `// TODO: снимать кэш по событию, а не по таймеру`.

## 5. Функции

- `context.Context` — первый параметр; `error` — последнее возвращаемое
  значение.
- Ранние возвраты вместо вложенных `if/else`; `else` после `return`/`panic`
  не пишется.
- Функция делает одну вещь; явные короткие локальные переменные полезнее
  комментария.
- Логические параметры-флаги в конец не добавляются — меняется семантика,
  а не нажимается переключатель (при необходимости — структура параметров).
- `defer` сразу после захвата ресурса.

## 6. Ошибки

- Ошибки — значения; правила проекта (`*domain.Error{Code, MsgID, Args}`,
  каталог сообщений, без паник и магических строк) — в `AGENTS.md`.
- Ошибка проверяется сразу; ошибок не глотать: `_` для `error` — только
  осознанно и с комментарием.
- Обёртка — `%w`, строковые `fmt.Errorf` — со строчной буквы, без пунктуации
  в конце: `fmt.Errorf("open snapshot: %w", err)`.
- «Из ничего» ошибки не конструируются повторным описанием — передаётся
  стабильный `MsgID` с аргументами.

## 7. Типы и структуры

- Порядок полей: сначала суть типа, затем метаданные; связанные поля рядом.
- Структуры всегда создаются с именованными полями:
  `ParameterRange{Parameter: code, Unit: unit}`, позиционные литералы —
  только тривиальные точечные (`Pair{k, v}`).
- Нулевое значение полезно: тип проектируется так, чтобы `var t T` был
  готов к минимальному использованию без конструктора.
- Конструктор `NewX` возвращает `(*X, error)`; множество опций — функциональные
  опции, а не растущий хвост параметров.
- Указатель вместо значения — когда нужен nil («не задано») или большие копии;
  скаляры и слайсы-только-для-чтения передаются значением.
- Методы не обязаны жить в одном файле со структурой, но обязаны в пакете
  типа; чужие типы не расширяются.

## 8. Слайсы и map

- Ёмкость известна — `make([]T, 0, n)` и `make(map[K]V, n)`.
- Проверка наличия — `v, ok := m[k]`; отсутствие ключа не ошибка.
- Возврат из функции — пустой слайс `make([]T, 0)`, если «пусто» это нормальный
  ответ; `nil` — «нет данных/не задано».
- Не сохранять срез массива, передаваемого дальше как неизменяемый, без копии.
- `range` по слайсу с индексом, когда нужен он сам; `for i := range n` вместо
  `for i := 0; i < n; i++`.

## 9. Управляющие конструкции

- `if` с инициализатором: `if def, ok := snap.Parameter(code); ok { … }`.
- `switch` без выражения вместо цепочек `if`.
- Возврат из глубины — `switch`/`for` с меткой вместо флага-побега.

## 10. Параллелизм

- Горутина имеет владельца, который её останавливает; «запустить и забыть»
  запрещено.
- Общее состояние — `sync`, мьютекс сразу над защищаемыми полями (поле-
  комментарий `// mu guards fields below`).
- Ожидание групп горутин — `sync.WaitGroup`; отмена/таймаут — только через
  `context`.
- Каналы — для передачи владения данными, не как эрзац-мьютекса.

## 11. Тесты

- Файлы `*_test.go`; общий код интеграционных тестов — только `internal/testutil`.
- Table-driven: срез кейсов, `t.Run` на каждый кейс, имя кейса — сценарий.
- `t.Helper()` в вспомогательных проверках; `t.Parallel()` где уместно.
- Тест проверяет поведение через публичный контракт, не через внутренности.

## 12. Запрещено

- Паники через границы слоёв/API (паника — только инвариант текущего пакета).
- `init` с логикой и зависимостями от порядка пакетов.
- Глобальное изменяемое состояние; константы и `sync.Once` — можно.
- `reflect` и интерфейс `any` там, где известен конкретный тип.
- Оставленный отладочный код, закомментированный код, пустые ветки.
